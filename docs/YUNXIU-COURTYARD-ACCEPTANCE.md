# 云岫别院场景验收 · courtyard-1.2

用户指出早期 terrain-lab 与原型画面差距过大，并提供了云岫别院参考图。本轮改为以该图的建筑、竹林、药田、石桥、溪流和山崖构图制作可交互场景。早期技术样机不作为本轮视觉交付。

入口：`dist/yunxiu-courtyard/index.html`。发布：`https://cybershp.github.io/Simulation-web-game/yunxiu-courtyard/?v=courtyard-1.2`。正式 EA 根目录与三个世界档位没有替换；此场景使用独立的 `xianfu-yunxiu-courtyard-v1` 存档。

## 已实现

- 1672 × 941 预渲染底图，沿参考图生成去除人物与 UI 的场景素材；构图接近参考，生成后的局部细节并非逐像素一致。
- 六名固定身份角色，六列四姿态透明精灵图；头像、地图服饰与存档身份一致。不是实时 3D 建模，也未实现无限随机角色服饰。
- 掌门点击通路行走；建筑选择、详情与前往；石路、两处过水通路、台阶、田埂采用登记到绘景坐标的道路网络，连续扫掠防止高速移动越过边界。
- 桥前栏杆、树冠与厨房附近前景轮廓可遮挡角色。遮挡是局部绘景轮廓裁剪，尚未逐物拆分整幅图的全部前景。
- 八个金色 SVG 图标系统入口、资源栏、纸面任务卡、场景详情卡、暂停与三档速度。
- 门人同行、定点照料与巡院；资源定时生产、木石修缮升级、札记奖励、传承研习消耗、干粮准备和纪事。
- 自动保存、重要操作与离开页面保存；恢复位置、人物同行、资源、等级、札记、研习、速度和暂停。没有跨设备云同步或离线结算。
- 横屏完整构图；竖屏跟随掌门、拖动查看、可滚动系统抽屉。

## 实际验收证据

`node qa/yunxiu-acceptance.mjs` 通过：1,296 组节点路线、12,292 段连续扫掠、2,592 次长距离边界扫掠；七处地标到达、三名同行者、暂停不推进、存档恢复、升级扣款与不足拒绝；道路非法位置为 0。这是逻辑测试，不代表每一个场景像素都完成视觉检查。

`node --test tests/*.test.mjs`：182 / 182 通过。原 EA 核心模块未修改。

云浏览器使用正常可见控件验证了：

- 素材完整加载；建筑和场景图标、人物尺寸与参考风格接近。
- 进入百工坊、过桥返回主屋，掌门到达主屋坐标 840,217，行走记录越界为 0。
- 陆知微、宋砚勾选同行；角色面板使用相同服饰图集。
- 札记奖励灵玉 +15、研习扣除 20：286 → 281。
- 暂停后药田升级，木材 98 → 80、石料 59 → 47，产出 +3 → +6，等级 1 → 2。
- 页面刷新后资源 281/80/47/57/86、主角位置 840,217、两名同行者、二级药田和暂停状态一致。
- 390 × 844 iframe 检查布局、抽屉和拖动；拖动后门人按钮仍可点击。不是 iOS/Android 真机生命周期验收。

## 范围与后续

当前交付是一个独立可交互山院场景。系统面板展示该场景的有限交互，未接入完整 EA 的功法、人物意愿、战斗和山外九区。门外其他场景未开放。固定地形上的建筑暂不支持搬迁；需拆分建筑素材、补齐遮挡和导航数据后才能可靠搬迁。

不要将此版称为完整新游戏、全部系统重做完成、所有遮挡绝无穿帮、无限 3D 同伴建模或真机验收完成。继续开发时先保留视觉风格，再逐场景登记路面和前景，不得用旧低保真样机替换本轮画面。
