# 宗门大山域试游

更新：2026-10-09。依据 [U-107 / R-33 / T-13](design/DECISIONS.md)，把现有小院置于可拉远观察、可沿开放路径游历的宗门山域中，并按用户最新要求拉开建筑间距、展开院落与山门至主殿的纵深。本批延续 Godot 2D、固定斜俯视、统一绘画素材与两名角色，沿用独立 `/painted-courtyard/` 入口。山域地形、镜头、院落布局和连续游历已获制作授权；实际效果与完成程度按下方 DOMAIN-01–06 的证据登记。

## 1. 山域尺度与空间目标

全山域以 **约 6×6 公里**作为规划建议尺度，登记为可调参数 T-13；后续依据近景比例、跨峰距离、实际行程与网页体验调整。它描述规划总览中的山域包络；本批精细游历层覆盖宽庭院到石桥与观瀑台，实际开放端点另行登记。正式 JS 的96米山院和旧档坐标继续作为既有运行基线；美术试游的像素、地形规划坐标与正式逻辑米分别记录，实施前明确它们的映射，不能用画幅大小反推实际路程。

沿用 [成长章程](SECT-GROWTH-PLAN.md)的地域身份：

| 地域 | 本批地形构图 | 后续生活与建设用途 |
| --- | --- | --- |
| Z-01 主峰 | 保留开山院、古松、山门、灵泉与两名角色；院落按下方最新建筑间距和方位关系布局 | 中枢、传承、接待、园林和核心修行，逐步成长为仙宫 |
| Z-02 东侧公共住居 | 主峰东侧有容纳生活设施的连续地域 | 公共住居、膳食、休养与日常研习 |
| Z-03 西侧生产谷 | 与主峰隔谷，谷地与山路关系可辨 | 灵田、药田、大宗生产与储运 |
| Z-04/05 近侧两峰 | 近左、近右分峰，各有可形成生活圈的台地 | 各自完整的日常生活圈 |
| Z-06/07 远侧两峰 | 远左、远右分峰，与近峰围合主峰 | 后续生活圈、传承与修行空间 |

U-107最新布局要求为**拉开每栋建筑之间的距离**：主殿前庭开阔，门人居与膳房各有独立院落，山门到主殿的纵深拉长，以道路、台阶和绿地衔接。新图保持主殿居中靠后、门人居在左、膳房在右、山门在前、灵泉在侧的方位关系，古松继续作为可辨认地标。人物与建筑保持相称比例；具体建筑位置、院落轮廓和通路按该构图重新布局并登记。

U-106原图固定像素锚点及其检查记录保留为先前构图的历史基线；本批新图使用与新位置一致的素材锚点、可走地面、碰撞、遮挡和点选区域，并在同一受验构建重新核对。约6×6公里的总规划参数保持可调，各区具体面积与建造点仍待配置。

峰内以完整生活圈组织日常起居、膳食、休养和修行，院落与道路保证服务相互可达。峰间由山岭、深谷、林海与瀑布形成距离和层次。全景应能辨认“主峰与四座分峰”的整体关系，东住居、西生产谷与自然地形相融。未建地域以自然状态呈现，阶段原型中的成熟建筑继续作为建设目标。

## 2. 本批制作范围

| 对象 | 本批可交付行为 | 记录要求 |
| --- | --- | --- |
| 大山域地形 | 同一构图呈现七区、山岭、深谷、林海和瀑布；小院在其中有稳定位置 | 素材来源、版本、全景与近景的映射；可达边界与纯景观地形分别定义 |
| 分级缩放 | 小院近景与完整庭院、观瀑步道之间连续缩放；继续缩小进入山域总览。总览在1–2.2倍内缩放、拖动，继续放大进入开山院近景；“全景／近观／跟随”可直接定位 | 各层保持共同位置映射和地域关系；镜头变换、边界和定位不修改人物身份、位置或临时计时 |
| 连续游历 | 掌门从主庭经台阶、石桥走到观瀑台，并可连续折返；南侧山门前后通行纳入完整巡游，保留两人的原有动作和辨识 | 在受验版本中登记实际路线端点、开放长度、行走比例和用时；沿途画面、脚点和可达性一致 |
| 小院布局与衔接 | 建筑之间拉开距离，主殿前庭、门人居院落、膳房院落及山门纵深清楚，以道路、台阶和绿地连接；两人可继续点选、行走、劳动及观察遮挡 | 主殿居中靠后、门人居左、膳房右、山门前、灵泉侧；新锚点与通路对应当前画面，U-106 / ART-2D 原证据按历史版本保留，受影响操作在新构建复验 |

沿用大世界、宗门总览和可操作近景的显示原则，本批山域内部采用两级查看：**精细游历层**支持小院近景到完整庭院与观瀑步道的合理范围连续缩放；**规划总览层**展示约6×6公里山域，以完整总览为1倍，允许1–2.2倍缩放与拖动。跨级时使用相应尺度的清晰绘画层，保持地域位置、地标关系和风格；继续放大总览可进入开山院近景。切层和“全景／近观／跟随”按钮只改变镜头，同一人物的身份、实际位置、当前活动与临时计时保持连续。各层具体缩放界限和切换阈值由受验构建记录。

扩大画面不要求同时加载或逐帧更新全山细节；实际渲染策略由实现记录说明。规划总览承担景观与方向辨认，精细游历层的可达地面和路径支持人物连续移动；界面反馈应让玩家分清两层及可行走边界。

本批先验证一条小院到外围的连续路线及全山域观察体验。全域精细步行、完整跨峰交通、施工迁居、生产物流和150人负载各自保留后续实施与验收，不能由全景可见推定完成。

## 3. 后续御物与遁法约定

U-107 确认：筑基可有限御物飞行；金丹具备更持久、更自由的御物能力；化雾等移动方式按具体遁法的学习与能力条件决定。境界方向已确定，速度、持续时间、消耗、起落条件和可达范围待玩法配置。

本批实施地形与步行游历原型，飞行玩法后续接入。届时人物保持同一身份与实际位置，地面、空中、起落及中断恢复共用唯一世界时钟，并核对通路、成本与到达；不能将镜头平移或地点定位当作人物飞行。高境界能力说明不改变前期炼气至筑基的完整内容范围。

## 4. 运行与保存边界

源场景继续使用 `godot/painted_courtyard/courtyard.tscn`，素材位于 `godot/painted_courtyard/assets/`，构建由 `tools/build-painted-web.py` 产生 `dist/painted-courtyard/index.html`。具体新增文件、素材版本、可达范围与受验构建在 [STATUS](design/STATUS.md)及本批证据中登记。

本试游仅使用观察、动作和游历所需的临时状态；刷新、重开后的实际恢复或复位方式须明示并验证。暂停时人物位置、动作及劳动展示冻结。正式 JS 规则、三个正式档位及已发布首页继续保持既有行为；样板不结算生产、库存或修为。后续玩法集成依 [05 运行时契约](design/05-RUNTIME-CONTRACTS.md)接入持久人物、空间和模拟时钟。

既有未提交源码、美术和历史版本保留。本批网页发布仅对应独立试游，源码、构建、本地网页、公开网页、目标真机和用户审阅分别记录状态。

## 5. 直接验收 DOMAIN-01–06

以下是本批判定依据，本文不预填通过。每项绑定相同受验构建及实际证据；失败项写明原因、修复与复验结果。

| ID | 必须操作并看到的结果 |
| --- | --- |
| DOMAIN-01 | 网页实际加载大山域；七区关系、主峰与四分峰、峰间山岭/深谷/林海/瀑布可辨。近景逐项查看建筑间距、开阔的主殿前庭、门人居和膳房各自院落、山门至主殿纵深及道路/台阶/绿地连接；主殿居中靠后、门人居左、膳房右、山门前、灵泉侧，古松与两人可辨，人物和建筑比例相称。新画面与其锚点一致，素材完整，无阻止操作的错误。规划6×6公里与实际开放路线分别说明。 |
| DOMAIN-02 | 从小院近景连续缩到完整庭院与观瀑步道，再缩小进入清晰山域总览；总览在1–2.2倍范围缩放和拖动，继续放大可进入开山院近景。分别操作“全景／近观／跟随”，检查各层地标对应与镜头边界。切层前后选中身份、人物实际位置、当前活动与临时计时保持连续，镜头操作不触发行走。鼠标与触摸手势分别检查。 |
| DOMAIN-03 | 通过公开地面操作，让掌门从主庭经台阶与石桥走到观瀑台，再连续折返；完整巡游另覆盖南侧山门前后通行。记录两条路径的实际端点、距离口径和用时。精细游历层内跨画面衔接不中断身份与位置，行走、转向、停止动画连续，脚点始终落在真实可走地面。 |
| DOMAIN-04 | 点击深谷、水域、陡壁、封闭边界等不可达区域得到明确拒绝或合法目标反馈，人物不穿越障碍。缩放/拖动后人物、建筑点选仍准确，山门前后与沿途遮挡和实际可见身体一致；失败操作不把人物移入景观层。 |
| DOMAIN-05 | 游历途中暂停、恢复、刷新和重开，逐项核对其临时状态语义；暂停不推进位置和动作，恢复后可继续操作。检查样板未读取、改写正式三个档位，未结算经营资源；加载或素材失败不得破坏原入口和档案。 |
| DOMAIN-06 | 桌面窗口、iPad横竖浏览器视口分别操作两级缩放、拖动、全景／近观／跟随、人物点选及观瀑步道；记录浏览器、CSS尺寸、DPR、两人实际活动、测量时长、帧间隔与明显卡顿。网页视口、目标设备实测、用户对规模与美术的认可分别登记。 |

先验证加载、移动、缩放、点选、遮挡及暂停，再核对相关的小院回归与性能。静态全景不能证明行走连续，两人样本不能外推150人经营负载，浏览器触摸模拟不能代替真机。
