代码主要位于 `godot/estate_2d/estate.gd`、`flat_actor.gd`、`flat_people.gdshader`、`standing_person.gd`、`shadow_layer.gd`、`valley_scene.gd`；导出脚本为 `tools/build-estate-painted-web.py`。图集的范围、脚点及两处帧边缘隔离由 JSON／运行 shader 控制，图像文件保留生成工具的原始输出。旧素材仍在源码，导出阶段过滤已替换的院景建筑图。

素材生成使用内置 imagegen，根提示词见 [RUNTIME-PROMPTS](RUNTIME-PROMPTS.md)，人物提示词见 [flat-people-prompts](../../../godot/estate_2d/assets/flat-people-prompts.md)，山谷见 [FLAT-VALLEY-PROMPTS](../../../godot/estate_2d/assets/FLAT-VALLEY-PROMPTS.md)。素材位于 `godot/estate_2d/assets/flat-*.png` 及关联 JSON。

## 实际验证

- Godot 4.6.3 Compatibility 导入、脚本解析与 Web 导出通过。人物既有播放约束 45/45、平涂人物专项 37/37、山谷 26/26、独立建筑／透明命中／遮挡／田地排序 168/168。各组分别覆盖其局部契约。
- 本机 Chromium 1440×960，独立 `acceptance=qa-u126-flat-20261013`：普通新档落脚处可见；从 U-124 原连续实玩末档导入世界步 8894，主殿、成熟药田、丹房和既有人物读取真实状态。点击主殿、药田和陆知微均打开对应窗口。
- 继续行走并中途改道，世界步 8894→8964、掌门位置 (28,12.6)→(34.453177,33.516091)；实际行走片段步态帧发生变化、行走中站立转身计数为 0；暂停后世界步保持。通过界面保存，再刷新，411874 字符完整导出解析后完全相等。
- 实机检查发现默认镜头裁到主殿屋脊、药田遮住人物腿部，已调整镜头和药田地面图层并重建复验。独立复核发现作物损坏／升级状态缺少回退，已补齐并复验。

前一轮受验构建 `output/u126-flat-preview/`（该输出目录后来重建，复验时须核对场景包哈希）；场景包 `scene-1497128c2023.pck`，27,284,472 字节，SHA-256 `1497128c2023e57f30d6c3015407b7f5f0ba351485a74b46dc680438cba833b4`。两片、106 个清单文件及 build.json 共107文件逐项校验通过。

证据保存在仓库外 `/Volumes/Media/immortal-qa/u126-flat/` 与 `/Volumes/Media/immortal-qa/u126-flat-independent/`；关键实际截图为 `courtyard-final.png`、`farm-selected.png`、`lu-selected.png` 和 `walk-final.png`。复核日志 `check-ground-order.log`，构建日志 `build-final.log`，导出清单复核 `final-build-preflight.json`。QA 保存、截图和过程日志不提交源码。
