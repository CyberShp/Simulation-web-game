# 桌面双画风自动实机样板

用户要求 D 国风 3D 与高清像素两种自动演示样板，用实际运行的光影、建筑、环境、人物动作与技能效果比较制作方向；Windows 为主力平台，当前先在 macOS 验证。样板与正式玩法迁移分别记录。

## 制作范围

- 共用山院布局、角色、镜头流程与示范施法事件，每段 72 秒。
- 依次展示山院全景、建筑、人物行走、单体招式、30 人同场、暮色灯火。
- 12 个主动快捷位用于界面容量评看，冷却与对应示范施法共用事件；数量与数值为样例配置。
- 正式游戏经营、人物身份与存档继续由既有实现负责。样板是独立演示，不读取或写入正式三个档位。

## Three.js 样板

用户在观看制作中的 Godot 版本后指出与 D 原型差距很大，并要求尝试 three.js。当前制作转入 `prototypes/three_style_showcase/`；Electron 提供桌面窗口，three.js 负责三维场景。此项用于实际画面比较，尚不代表全游戏已确定新引擎或迁移完毕。

场景树木与山石采用 Poly Haven CC0 模型及纹理，来源、减面数量和哈希分别记录于该样板 `assets/nature/manifest.json`、`SOURCE.md` 与 `assets/surfaces/SOURCES.json`。主殿和骨骼人物基础资产来自本仓库 Blender 源文件。原型图作为视觉方向，实际样板的精细度须按运行画面评看。

本次关联 SR-XF-003 / 004 / 007 / 013 / 029 / 030 的空间、角色、交互与平台表现；仅提供本样板的局部证据，不关闭完整 SR/AC。

## 先前 Godot 样板

`prototypes/desktop_style_showcase/` 保留停止时的源码和素材。用户已指出当前画面不符合预期；最新环境修订仍有解析错误，其早先局部原生截图与动作检查不覆盖停止时全部文件。该版本未发布。

## 验证与交付

实现位于 `prototypes/three_style_showcase/`；Three.js 0.180.0、Electron 39.2.7 均由 lockfile 固定。自包含 macOS 应用已经生成，运行时无需 Node 或网络下载；本地开发签名用于当前机器评看，Windows 包尚未制作和验证。

- D 模式：真实模型、骨骼动作、纹理、阴影、环境光与技能发光。
- 像素模式：场景在 640 像素宽下绘制；人物由 96×128 格子的共享图集作为精灵呈现，18Hz 更新动作，HUD 保持窗口分辨率。当前为技术效果比较，手绘像素资产仍待制作。
- 两种模式使用同一 72 秒镜头流程与事件；正常启动按 D→像素→D 循环，Escape 退出。
- 30 人是演示规模；技能栏共有 12 位，四种示范技能实际播放，其余为界面容量示意。演示无战斗胜负与正式伤害结算。

根代理检查了全景、建筑近景、人物行走、单体技能、30 人与暮色的真实运行截图。独立复核发现的像素图集绘制统计遗漏、双人阶段人数文案错误均已修复；冷却读自掌门自己的示范施法事件，敌方施法不写掌门冷却。素材修复包括松针纹理色彩转换、远处悬浮岩片与河岸连接。

实际美术差距：主殿瓦作和木构仍显简化，人物面部与衣物细节不足，后山轮廓及河谷转折生硬，远景人物较小；像素模式尚缺专门设计的像素材质与逐帧角色美术。当前运行结果不能视为 D 原型精细度已实现，也不足以据此决定最终画风或整个游戏引擎。

本批本地未提交、未推送、未更新 Pages；正式经营、人物关系、存档与战斗规则未迁移。Windows、其他硬件、完整大世界、存档兼容与用户美术验收仍待完成。

### 本地交付与证据

根目录：`/Volumes/Media/immortal-qa/three-style-showcase/`。

- `delivery/云岫山院-双画风样板.app`：macOS arm64 自包含应用。
- `delivery/D-国风3D-自动演示.mp4` 与 `delivery/高清像素-自动演示.mp4`：实际运行 canvas 与 HUD 的实时录制。
- `release-d/`、`release-pixel/`：自包含应用运行的七张阶段 PNG、原始 WebM 与指标 JSON；对应 `.log` 在根目录。
- `verification-manifest.json`：源文件哈希、系统版本与受验基点。

指标中的帧率是本机录制期间的短样本，受截图和录制开销影响；`drawCalls/triangles` 包含各次绘制通道，是结束时单帧值，不能当作全过程峰值或纯模型面数。


### 自包含应用实跑结果

2026-10-13，macOS 27.2 / Apple M4，1600×900 桌面内容区；两种模式分别从自包含 `.app` 启动，自动到终点并保存视频。

| 模式 | 演示秒数 | 平均 FPS | P95 帧间隔 | 完整示范事件 | 控制台 |
| --- | ---: | ---: | ---: | --- | --- |
| D 国风 3D | 72.01 | 48.0 | 25.7 ms | 7 个单体事件 + 11 轮群体事件 | 未记录错误 |
| 高清像素效果 | 72.01 | 108.7 | 14.9 ms | 7 个单体事件 + 11 轮群体事件 | 未记录错误 |

这是单次录制负载样本，D 与像素绘制分辨率不同，不能用该差值推算正式游戏性能或宣称稳定 60 FPS。像素录制期间另有 CPU 视频转码运行；Windows 与其他设备未覆盖。源码和包内 29 个运行文件及资产已比对相同，定向语法检查、SR refresh/validate 与差异空白检查通过，完整 SR/AC 状态未推进。

原生窗口额外核对：通过 macOS 应用启动入口打开自包含包，实际看到 D 模式人物段自动播放，随后未操作即切到高清像素全景段；桌面窗口已留给用户评看。此项验证 D→像素，后续循环回 D 的代码接缝已独立检查，未以该次观察宣称长期循环稳定性。

两段最终 MP4 已导出，均为 1600×900 H.264；完整解码检查通过，并从 D 视频抽取画面核对与实机 HUD 一致。原始 WebM 保留。
