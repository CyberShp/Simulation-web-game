# 门人志 · 游戏界面评看稿（2026-10-10）

本稿对应 [U-108 游戏式界面](../design/DECISIONS.md)与 [U-111 门人收录原则](../design/DECISIONS.md)。评看入口为 [门人志游戏界面稿](disciples-ui-20261010/index.html)。在仓库根目录运行 `python3 -m http.server 8788`，打开 `http://127.0.0.1:8788/docs/art/disciples-ui-20261010/` 即可切换查看。

## 画面与操作

- 旧别院场景始终在屏幕上；左侧雕纹功能牌打开门人，右侧卷册显示当前人物。点击场景中的人物或卷册上方肖像印记，切换同一人物的门籍、近况、修习与经历；“山院定位”收起卷册，回看人物所在位置。
- 山门求见从场景下方提示或卷册书签打开。先呈现来访者当前可知的年岁、灵根与自述，再拟定外门、内门或亲传；亲传必须指定本人师父。核对收录打开游戏内确认卷册。
- 收徒令书签展示总余量、三级身份余量、主持者、择徒方向与培养承载。右下角演示阶段切换开山旧院和分峰后的山域概念画面；分峰时可查看主峰及丹霞峰门籍。
- 桌面采用场景右侧卷册；iPad 竖屏把卷册移至画面下半部，让场景、求见提示与底部功能牌保持可见。卷册内部可滚动阅读。

## 规则在界面中的位置

| U-111 规则 | 玩家看到的位置 |
| --- | --- |
| 正式收录即定外门、内门或亲传 | 求见卷册中的拟授身份与确认层 |
| 各峰拥有各自门籍 | 分峰演示下人物的归峰与师承 |
| 收徒权受职务和峰别限制 | 收徒令中的主持者与本峰受权 |
| 收徒令限定人数、身份及培养资源 | 收徒令卷册的余量和择徒条款 |
| 仅凭已知信息作择徒判断 | 求见卷册的自述、初看信息与待核实提醒 |
| 正式收录走同一道结算 | 核对收录确认层；实际结算留待规则接入 |

## 演示边界与接入点

人物、资源、名额和阶段画面均为示例。当前文件只有界面状态和点击反馈；确认、婉谢、定位、阶段切换不调用正式模拟，也不写入存档。桌面与 iPad 视口截图属于浏览器评看证据，画面中分峰背景是成长阶段概念图。下一步接入时，卷册读取同一人物 ID、世界位置、事件记录与门籍结算结果，求见从实际山门人物触发；门籍身份、归峰、师承和名额由正式命令一次落档。规则实现和完整游戏验收仍以需求台账单独记录。

本轮预计改动为本界面稿的 `index.html`、`style.css`、`app.js`，以及 U-111 决策和 STATUS/HANDOFF 交接。实际评看重点：开山人物切换、求见三级身份与亲传师父、确认层、分峰名册、收徒令，以及桌面/iPad 横竖浏览器视口。正式旧别院预览、首页、三个档位及功法规则在本轮不接入这份示例数据。
