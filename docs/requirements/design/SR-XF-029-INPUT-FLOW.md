## D01-1 输入与命中

| 输入 | 只读反馈 | 可提交动作与防误触 |
| --- | --- | --- |
| 鼠标左键或单指轻点画布 | 指针下的可见人物/物件优先给出身份或对象；空地显示当前模式目标 | 按下与抬起的曼哈顿距离不超过 6 CSS px 才激活一次；一次物理操作至多派发一次命令。双击不重复扣费。右键不作世界确认。|
| 单指拖动画布 | 平移镜头，保留选中对象、营造候选和世界状态 | 移动距离超过 6 CSS px 后归为拖动；抬起不再选择、行走或确认。指针取消、失焦、页面隐藏和失去捕获均结束本次手势，不补发点击。|
| 双指手势 / 鼠标滚轮 | 双指中心或滚轮指针下的世界点作为缩放锚；镜头限制在真实场景边界 | 第二触点到来即取消单指激活；缩放结束不落地建造或移动。镜头变化只属于视图，不改人物位置、RNG、世界步或材料。|
| 管理页、侧卡、弹窗内的点击/滚动/输入 | 控件自行响应；可滚动区域在自己的容器内滚动 | 只有画布接收平移和缩放；表单获得焦点时 WASD、方向键、空格、Esc 不派发场景动作。弹窗打开时画布动作停用，关闭弹窗只恢复视图。|
| 键盘与显式按钮 | 焦点可见，当前模式、候选及拒绝原因可读 | 在无文本焦点且无弹窗时，方向键/WASD 才移动掌门；Esc 退出营造候选或选择，暂停需显式控制。Enter/空格只激活当前聚焦按钮，不用页面级快捷键暗中确认高风险动作。|

命中顺序采用同一投影和实际 CSS 容器坐标：露天可见人物（含掌门）及其身体/脚点 → 其他可交互实体 → 地面。人物与物件重叠时提供具名候选，不按数组首项永久抢先；候选含同身份肖像、姓名、当前可公开活动，选其中任何一个都只选中该人。人物被树或低层前景挡住时可由描边/局部透明和人物定位入口选择；封闭建筑屋顶下不穿屋顶点人，建筑卡列真实占用，人物/建筑管理提供具名选择。远景聚合先进入可辨视图或打开候选；露天人物触控目标保持至少 44×44 CSS px，独立于画中身体尺寸、镜头缩放及 DPR。系统按钮、选择器、弹窗关闭与确认也保持至少 44×44 CSS px；不可用设备像素替代。

选中人物只显示身份、活动、公开理由和定位；不会顺便移动掌门。行走模式轻点合法地面才下达掌门移动；观察模式轻点地面只清选择。营造/迁建模式轻点地面仅设置吸附到 2 米营造格的候选，半米精度继续用于人物导航；候选显示实际预制件占地、入口、材料与阻断。人物/物件命中仍可选择和查看，不用营造模式吞掉其身份。鼠标悬停可更新预览，触控点地更新同一预览；离开画布、缩放或拖动不擅自更换已选候选。独立的“确认营造/迁建”按钮才调用命令，提交时重验地形、通路、人物、材料与权限；失败保留候选、原建筑和资源并显示具体改选方法，成功给出工作单和可回看的阶段。退出或关闭只清预览；施工取消按已发生投入返还，不能把“退出预览”当作“撤销施工”。这些命令的空间与事务细则沿 [SR003–006](SR-XF-003-006.md) 与 [03 空间设计](../../design/03-SPATIAL-ART.md)。

## D01-2 所有操作共用的页面状态

每个页面只突出一项当前主目标，并可从同一入口回看已知前情、当前条件和帮助。主目标由玩家已知的事实生成，带来源/观察时刻；未知人物位置、隐私和作者真相不得成为提示。打开、展开、折叠、定位、缩放、帮助、阅读及表单草稿均是只读；除已有世界正常运行外，它们自身不新增世界步、消耗、奖励或 NPC 决定。

操作依次显示“可选/条件不足 → 草稿与风险预览 → 明确确认 → 已接受并等待实际世界活动 → 完成或中断”。草稿取消不建立事务；已提交的取消只走对应任务的权威取消命令并展示已耗与可退部分。等待必须写当前阶段、实际地点/工位、阻塞原因、已发生消耗和继续方式，不把接受订单说成产出完成。有历时任务的页面重开与读档用持久任务 ID 恢复这张状态卡，一次性结果按已有事实 ID 回看，不从 DOM 草稿补发命令。提交时根据最新状态重新校验，拒绝只返回公开原因、保留可继续的输入；同一次确认的重复事件不得重复扣费或结算。发生不可逆投入、人员死亡、远行、产权改变或旧案清算前，确认框列对象、成本、时间与已知风险；取消保持原事实。暂停、切页、后台和关闭沿唯一世界时钟与存档规则处理；只读会话不提交。

每个拒绝卡至少包含“哪项条件不满足、去哪里处理、保留了什么、怎样重试/返回”，并在缺料、路断、工位被占、人物不愿、地点未到、期限已过等情况下指向真实可用入口。可观察的消息标“事实/人物说法/推测”，不把解释当作幕后真相。若提交成功而保存失败，明确标“本次进度仍在此窗口，尚未写入”，暂停高风险继续，提供重试保存、导出当前完整进度、读取原档/备份及只在明确选择后内存继续；不得显示“保存成功”或用重载试探覆盖原档。原档与备份保持可读，导入前校验且覆盖须再次确认。[05 运行契约](../../design/05-RUNTIME-CONTRACTS.md) 仍是存档与结算来源。

### 开局结缘的三个独立决定

[06 §2](../../design/06-OPENING-ACCEPTANCE.md) 的结缘段和 [14 §7](../../design/14-EARLY-GAME-DETAILED-DESIGN.md) 的关系边界在同一 `person:lu-zhiwei` 身份上执行。当前主目标可以依次推荐赠药、邀请暂居、商议正式入宗；目标切换仅改变提示。每一步都有单独的玩家确认、陆知微本人的回应和持久结果。赠药只改变药材归属与已知善缘；暂居只建立可撤回的住居关系；正式入宗才建立组织成员资格。同行另行邀请，并按本人当时意愿判断。打开对话、翻页、已读或关闭帮助均不提交这四种决定。

| 独立步骤 | 可见条件与确认 | 取消、等候、拒绝和恢复 | 持久事实与下一目标 |
| --- | --- | --- | --- |
| 赠药或暂缓 | 掌门与陆知微实际同场近旁；显示她已说出的求药缘由、山院有权交付且未预留的灵草10份、交付位置及赠药后的物权变化。点击“赠出10份灵草”前单独确认受赠人和数量。 | 关闭/选择“暂缓”只保留求药线索及可回访入口，不扣药。距离不足先走近；现货不足说明采集、取回或合法补给，已预留药不能支付；她不在现场则显示最后已知位置与消息时刻，待实际再会。命令拒绝/失败时重开仍能检查条件和选择。 | 成功时山院实际灵草减10、陆知微药袋加10，写唯一赠药事实和本人记忆；重复点击/读档不再转移。界面只说药已交给她，不把院外家属治疗当成已完成。下一目标可以建议住居商议，仍保留其他开局经营路线。|
| 邀请暂居或暂缓 | 在她实际可交谈时，展示目前是否有安全可用住处、暂居的生活安排及其本人可公开的意愿；“邀请暂居”是第二次明确提交。未赠药也可查看她对住居的公开条件，赠药不能替她同意。 | 关闭/暂缓保持访客关系及已发生赠药。住处不足指向建居舍或腾出真实床位；距离/行程阻断显示会面入口。她拒绝时保留善缘及原因，允许条件改变后重新商议；若答复需等实际到场，显示阶段与位置，暂停不推进。 | 接受后登记独立暂居约定、本人实际住处/床位与可撤回状态；本批不设自动到期或自动转正。她仍不是正式门人，私物不变，工作和同行各需另问。退出暂居保留赠药及记忆，并按真实位置安全离开。下一目标可建议继续经营或商议入宗。|
| 正式邀请入宗或暂缓 | 对当前真实可会面且有意了解山院的陆知微，列明组织身份、可用居所、可公开的院规/安排及本人是否愿意；“正式邀请入宗”须第三次明确提交。暂居不作为自动批准，未暂居也不能凭一次赠药跳过本人会面和同意。 | 关闭/暂缓保留当前访客或暂居关系。容量、院规或双方条件不足时给具体改善入口；她拒绝时继续保留既有赠药/暂居事实及可公开理由，后续条件改变可再谈，不把拒绝写成强制退出。若她离开，先按已知消息寻人并实际会面；等候本人到场或答复时显示实际阶段，暂停不推进。 | 本人接受后才写唯一成员资格事实并将同一 `personId` 加入成员引用；肖像、药袋物权、记忆、关系和既有活动不重建。后续工作、任职、同行仍各自询问；下一目标转向药田、生产和研习。|

每步帮助从该人的对话和当前主目标都能重新打开：赠药说明现场药材与合法补药入口，暂居说明床位与会面路径，正式入宗说明身份、院规和本人意愿。帮助关闭后保留当前选择界面和已知前情，不代替任何确认。

这三步的确认回执分别有稳定事实/约定 ID 与结果状态，界面从权威状态恢复，不根据弹窗是否看过推断。持久状态至少分别可查赠药事实、暂居约定及当前状态/床位、正式成员事实及当前状态、新三步中陆知微本人明确拒绝的记录；各记录都引用同一 `personId`。只有正式入宗接受后才进入 `homeMemberIds` 等成员引用。草稿取消不建事实；已交付药材不能通过取消邀请退回，已接受的暂居与成员身份只能走各自已定义的解除/离院流程。旧 schema6 `opening.gifted` 与 `fact:opening:gift` 对应赠药事实；旧 `opening.invitation=joined` 是既有正式入院结果，兼容时保留其成员身份，不倒填从未发生的暂居；旧 `opening.invitation=declined` 表示掌门选择让陆知微先回家照应家人，兼容时保留该玩家选择、赠药善缘和原人物，不生成陆知微拒绝邀请的事实或正式成员。迁移先校验原档、在副本中确定映射，失败保留原档。当前 `advanceStory` 的“赠药→邀请入院/离开”只覆盖赠药及旧入院结算，新的暂居与正式入宗需 I01 分立实现；本设计不将旧两段 UI 作为三步体验已通过。

## D01-4 画布与信息布局

依据 U-95，以实际 CSS 容器宽高、`devicePixelRatio` 和安全区域计算：画布位图宽高应分别对应容器 CSS 宽高乘当前 DPR（允许单像素取整），绘制与命中都以 CSS 坐标及同一逆投影换算。调整窗口、iPad 横竖切换、底部面板折叠、字体放大和 DPR 变化后重新测量，原选中 ID、候选地块与手势锚点仍指同一世界对象；空白区域和被面板盖住的画布不接受世界激活。输入目标按 CSS px 测量，不能以位图缩放掩饰较小的命中区。

| 可用区域 | 排布与阅读规则 |
| --- | --- |
| iPad 横屏与较宽桌面窗口 | 画布保有可操作区域；当前主目标和选中侧卡分别可折叠。八页导航与状态、确认/取消保持可见或在同一页稳定滚动到达，侧卡和底部管理页各自滚动，不改变镜头。|

尺寸断点只选择排布，不充当设备证明；iPadOS 横竖、Windows/macOS 不以系统名推算视口。现存 360/390 视口兼容可以继续，U-95 后不作为本 SR 必需设备关闭条件。任何浏览器模拟记录须写视口 CSS 宽高、DPR、缩放、浏览器、存档来源及实际触发方式；目标设备记录另列机型/系统/浏览器/触摸或鼠标。浏览器合成触控、Node Canvas 耗时及模拟世界时长分别不能称为真机触控、网页 FPS 或真人体验。
