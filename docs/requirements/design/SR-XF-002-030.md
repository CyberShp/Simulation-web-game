# SR-XF-002 / SR-XF-030 · 共同契约与确定迁移

版本1，2026-10-06。源为DB-2026-10-05 v1.2、05/14，继承U-63/U-93/R-25/R-26。以下是作者实施默认，不冒充用户逐字段确认。

本模块负责共同身份、引用、单位、内容激活与事务/迁移隔离；不运行第二个世界循环，不结算领域伤害、天气或生产。真正的领域动作、UI和浏览器集成须由各领域及入口验收，单独通过本模块不能关闭SR。

## 共同实体契约

所有主表为非数组对象。键稳定且带前缀；身份字段必须与键相同。空引用使用null；已完成/取消等历史记录和事实可保留已释放的预约/活动/工作单引用作为来源，活跃记录仍须存在有效引用；其他未知引用拒绝并报告完整表/ID/字段路径。新字段必须可JSON序列化，禁止NaN/Infinity/函数/循环/危险对象键。

| 主表 | 身份字段/前缀 | 共同必填/范围 | 引用及领域写入侧 |
| --- | --- | --- | --- |
| personsById | personId / person: | name、稳定appearance（保留旧spriteIndex/accent）；lifeStatus alive/dead | activityId、combatSessionId；人物/危机模块共同原子写身体。死者必须有唯一deathRecordsByPersonId |
| buildingsById | instanceId / building: | 旧id/type/level/condition维持兼容；新transform由空间模块管理 | 工位/建筑实体不凭镜头重建；旧condition0–100暂保，物品新condition0–1 |
| scenesById | id / scene: | 名称、坐标单位metre；默认云岫身份不生成建筑 | localSceneId指向本表；米制由initSpatial一次转换 |
| itemsById | id或instanceId / item: | definitionId、condition0–1、ownerId、location | ownerId合法person/organization；location.kind为person/stockpile/scene/building/travel/destroyed且有效id；slot可选四槽，所属和装备位置仅这里权威 |

| crisesById / hazardsById | id / crisis:或hazard: | 持续危险与已部署危险，领域细化原因/截止/自救 | 人物与地点共享；新急救命令不等于治疗完成 |
| deathRecordsByPersonId | personId / person: | 键唯一、人物确实dead；不可复活式重写 | personId与personsById互相一致，遗物由itemsById独立位置迁移 |

### 当前 schema 6 人物跨场景写入侧（M1 核对）

此表把上面的目标契约落到 EA 1.6.0-dev 的实际字段；它是 SR002-D01 的已核对子范围，不表示所有领域已完成目标契约。来源为 U-94、R-25、[01](../../design/01-CHARACTERS.md) §1、[05](../../design/05-RUNTIME-CONTRACTS.md) §§1–3、7–8，以及 `ea-opening-sim.mjs`、`ea-sr-world.mjs`、`ea-sr-persons.mjs`、`ea-sr-spatial.mjs` 的现有读写路径。

| 阶段 | 持久身份与权威字段（`location` 为运行适配） | 前置、失败及保存恢复 |
| --- | --- | --- |
| 山院 | `personsById['person:master'] === master`；持久的 `master.position={kind:'scene',sceneId:'scene:yunxiu-courtyard',x,y}` 与 `master.scenic` 保存山院行走脚点及路径；非序列化 `master.location={kind:'local',sceneId,x,y}` 是读写适配，写入会转写 `position` | 施工、研习等只用 `master.activityId` 指向一个活动；失败命令不能另造身体或扣除预约；一般读档校验已保存路径并恢复运行适配，旧布局迁移才重新计算相关路径。 |
| 出发与途中 | `travelsById[activeTravelId].participantIds` 包含同一 `person:master`；实际启程后持久的 `position={kind:'worldTravel',travelId}`，运行适配 `location={kind:'travel',travelId}` | 出发校验路线、支付行程成本、按需预约公共运具票，并从公库转移行囊物资；步行无需运具票。途中 `scenic` 仍可留作历史院内脚点，但不能被当成第二个活跃身体。等待登船时取消不退已付票款，其余按旅途记录的实际位置与规则恢复。 |
| 抵达与斗法 | 抵达把同一人物的持久 `position` 置于目标 `sceneId`，`location` 随之投影；SR 战斗的 `combat.player.personId='person:master'` 与 `combat.sessionId` 指向 `combatSessionsById` 的唯一活跃会话。具名同伴/敌人同样引用各自 `personId`；每位参战者的 `combatSessionId` 与单一 `activityId` 指向该会话。画面 `hp` 从人物 `wound` 投影，受击和治疗立即回写同一伤势；装备仍由 `itemsById` 唯一实例的归属、位置和槽位判定 | 挑战须目标、知情、地点和身体前置通过；起手/收势沿用同一战斗活动，胜败撤释放会话与身体，不在结算时重复加伤。同世界步后续系统造成的致命伤会在保存前结束战斗。旧活跃战斗在校验副本内确定迁移，坏会话引用拒绝且不改原档。此为 SR 战斗代码与组件层已验证契约；正常山院→旅行→斗法→返院整链仍须单独验收，不能仅凭此关闭 AC-01。 |
| 返院 | 同一 `person:master` 回到云岫本地位置；人物外观配方、物品实例 ID 与所有权、伤势、世界步沿路保留；已结算命令由持久结果账本拒绝重复执行 | 从途中的正式存档加载不补离线时间；坏引用/未知版本拒绝并保留原文。浏览器保存失败应暂停并提供导出/恢复，不能把内存提交写成磁盘成功。 |

AC-01 的正常验收必须取新档或有来源的正常公开命令存档，在同一链上分别保存并读取出发前、在途、抵达、斗法中和返院状态；逐点核对 `personId`、单一可行动身体、装备实例/归属、伤势与 `worldTick` 单调一致、无院中第二身体，并核对战场生命值对人物伤势的结算。共同契约表样本、战斗组件 fixture、旧完成档运输检查与现有新档旅行子链只能作为局部证据。战斗组件目前覆盖会话全程、受击治疗、同 tick 外伤、胜败撤、旧活跃档迁移及坏引用原子拒绝；它不替代上述正常整链。

2026-10-07 的公开操作审计使用同一 `seed 618033` 有来源的第11境山院存档，继续至第12境并完成调查、三场战斗及返院。`qa/ea-sr-integration-acceptance.mjs` 在出发前、在途、抵达、战斗起手、人物实际受伤时、返程途中和返院分别执行精确存读并保留阶段档；在途人物无山院活动，斗法只占一项 `sr-combat` 身体活动。独立复核的世界步依次为 698140、698140、698340、698952、699701、699980、700505；受伤时 `wound=23.5602` 对应战场 `HP=146/191`，铁剑和法袍实例、归属和槽位沿路不变。此证据满足 AC-01 的运行时公开命令口径，完整 D/I/V/R 仍按各自门槛推进。

当前版浏览器持久层仍以 Web Lock 保证单档单写者，保存调用同步返回读回结果。超过 256 KB 的有效本地 JSON 封装可压缩存放；旧未压缩档仍直接读取，下载导出保持普通 JSON。压缩封装记录原始字节数，解码后继续按当前 schema 校验；普通保存与压缩封装均以 8 MB 未压缩输入上限检查。有效旧主档进入滚动备份时可转为等价压缩封装；迁移或异常源档的原始资料保留区仍保存其原文。容量或写入失败时不报告成功，原主档保持可恢复并提供导出。

数值时间：worldTick/revision为非负安全整数；每tick100ms，ticksPerDay1200。字段名后缀Tick必须是非负安全整数，atTick不能超当前世界步。现实关闭、后台和暂停不结算。各模块可使用beginContractTick(s,module)去重同tick；它仅登记游标，不增加worldTick。

## 命令、事务、错误与顺序

入口`executeContractCommand(s, command, {handlers, clone, validate})`返回新状态；只有status committed时调用者替换原状态。actorId默认掌门，直接控制其他人物拒绝。command.id为稳定command:前缀（数字序列或会话序号）；args必须数组；expectedRevision不匹配拒绝。数字旧编号没有账本时也不能再执行。相同ID/签名重送返回already-applied，改参数复用ID返回command-id-conflict。

在隔离clone执行所有handler修改，再更新revision/命令账本并整体validate；无效引用、异常或领域前置失败均保原状态。返回status/commandId/revision/reasonCodes/transactionId/changedIds/result/saveStatus/replayed。changedIds目前空列表，不能假称列全实体差异。committed是内存事务，saveStatus为not-yet-saved；磁盘成功另行更新保存反馈。错误码为unsupported-version、invalid-reference、stale-revision、invalid-identity、not-authorized、command-id-conflict、invalid-contract、pending-placement、save-failed。

transactions.receipts保留最近128条；transactions.outcomes永久记录已提交ID、签名、修订和结果，读档后仍能防重复，不能因短收据淘汰重新扣费。新档导出保持该账本。

共同效果层：protection → stabilization → contact-damage → ongoing-loss → recovery → death → observation。层仅提供确定规则枚举，领域实现负责从相同阶段快照聚合与裁定；定义存在不代表已实现全部同tick救援/死亡。

knowledgeView(s,{observerId})只输出public/knownClaimIds/knownByIds允许的消息，含来源、观察时刻、收到时刻和有限locationHint。不会输出作者truth或未公开消息；调用前后权威状态必须一致。

## 内容编译与版本矩阵

`validateContentDefinitions`隔离校验输入并返回clone；校验成功前不修改当前运行内容。输入version1/contentVersion sr-content-v1.2；persons/items/scenes/routes/claims/crises/activities/authorCards对象表必填。每定义id与键一致、全局唯一、references数组每项存在。activities还须durationTicks正整数及合法effectLayer；authorCards还须truth对象、clues/outcomes数组与user-confirmed/recommended/tunable来源。详细领域条件由领域内容验证补齐。

| 输入 | 支持与处理 |
| --- | --- |
| 旧version1–4 | 既有model/world/living/sect确定迁移链先验合法，再迁至结构6 |
| 旧version5 | 既有ea-sim验证，再隔离迁移，不改变原对象 |
| schema6 / opening-runtime-1/2/3 | 原有局部规则继续支持；契约主表可确定初始化，不追算过去 |
| schema6 / sr-runtime-v1.2、sr-content-v1.2 | 完整SR模块入口激活后用各模块validate；结构版本仍6 |
| 未知schema、ruleset或content版本 | 原档拒绝加载，保留原文及导出，不静默降级 |

## 确定映射与原档保护

| 旧事实 | 映射 | 守恒/失败规则 |
| --- | --- | --- |
| master、disciples、departed | master固定person:master；数值门人转person:yunxiu:N，departed亦登记历史身份（compatibilityMode historical-only，无可行动身体） | 姓名、性格、外观、主辅修、记忆、RNG结果保留，nextPersonId不占用 |
| time、sim.carry、seed | 原time×10加carry整tick；剩余carry保留；rngState=seed | 历史clockOrigin不变，不调用随机、不补日结 |
| 建筑与旧槽位 | 旧building身份/等级/材料/进度保留；initSpatial own确定旧像素→米和transform | 契约不另安置；无合法位置由空间模块登记pendingPlacements与恢复动作，不能丢资产 |
| knowledge单值 | migrationLedger.legacyKnowledge记录原legacyMastery/understanding=n/mastery=0及来源；成长模块读取映射 | 不把同一旧值复制成理解熟练都满，不重学随机重抽 |
| 旧装备缺失 | itemsById空表 | 无凭空全套补偿；已有实例由装备模块映射有效owner/location |
| 旧已完成篇章 | story.completed/ending/claimed保持；ending源legacy-completed且additionalTargetsAllowed=false | 不追加两管事使旧完成失效，不再次发奖 |
| 旧未完成篇章 | 已clues/preparations/claimed/revengeDone留存为storyFacts.progress；新版故事模块映射具体事实 | 兼容记录本身不成为数量许可，不扣历史收益 |
| 在途、治疗、制作、危险 | 保留原活动/工作单/行程及当前tick，migrationLedger.atTick登记启用边界 | 不补离线死亡、天气损失或隐秘抽取；领域resume校验合法行动 |
| 一次性迁移补偿 | appliedKeys含sr-contracts-v1；实际补偿如有须独立确定键 | 目前不发补偿，重复init不赠物资或知识 |

`migrateState`首先structuredClone原输入；`prepareMigration`保原始JSON文本和独立新state，先版本识别、既有验证、迁移、共同验证再返回。`commitMigration`先backup原文，再write新文；备份失败不写，写失败返回内存state/originalRaw/save-failed供导出与恢复。实际浏览器仍用现有persistence原档/备份/写锁流程，入口须完整集成测试。存储write函数本身须采用现有受保护写入协议。

## 本地验证与真实边界

`node qa/ea-sr-contracts-acceptance.mjs`：当前 19/19 Node 检查通过；脚本所引用的旧完整 v5 fixture 缺失，该可选场景明确跳过。其余检查覆盖 v1–v5 真实生成器链、原对象/资源/RNG/日内相位、知识一次映射、128 收据淘汰后的重送、过期和无效引用事务回滚、隐私查询、未知内容版本、缺定义引用、备份失败/写失败、同 tick 去重。合法完成 v5 参考档在 `qa/ea-sr-travel-continuity-acceptance.mjs` 中另行验证。共同人物旅行/战斗表引用只以契约级样本证明同实体，不冒充完整实际出行和斗法 UI 通过。

现代入口调用base.validateSave(legacyProjection(s),{canonical:true})仅校验副本，不回写人物、建筑或故事；legacyProjection保留spatial与SR版本。canonical分支保留资源、人物、知识、社会及篇章形状校验，米制位置/自由建筑由共同与领域校验负责，不调用旧像素修复、不要求旧grid地址。

旧version5离院历史只存姓名/时间/原因/公开记忆，旧实现已丢弃的身体、私有功法与外观无法凭空恢复；迁移以historical-only保护身份与已有来源，不生成可行动NPC。schema6离院已有完整主表实体则继续保留。

待集成：自由布局不可安置恢复UI、各领域旧在途/危机样本、成长/装备/责任链实玩法、浏览器保存失败反馈与触控。实际gateway山谷旅行/保存/重载/重送/抵达和真实persistence内存注入备份/主档配额失败现已通过Node验证，仍不是浏览器DOM/真机证据。没有新增真机、真人或FPS证据；AC是否关闭须以总集成验收决定。测试脚本进入源码，生成截图与过程文件不上传。
