# SR-XF-002 / SR-XF-030 · 共同契约与确定迁移

版本1，2026-10-06。源为DB-2026-10-05 v1.2、05/14，继承U-63/U-93/R-25/R-26。以下是作者实施默认，不冒充用户逐字段确认。

本模块负责共同身份、引用、单位、内容激活与事务/迁移隔离；不运行第二个世界循环，不结算领域伤害、天气或生产。真正的领域动作、UI和浏览器集成须由各领域及入口验收，单独通过本模块不能关闭SR。

## 共同实体契约

所有主表为非数组对象。键稳定且带前缀；身份字段必须与键相同。空引用使用null；已完成/取消等历史记录和事实可保留已释放的预约/活动/工作单引用作为来源，活跃记录仍须存在有效引用；其他未知引用拒绝并报告完整表/ID/字段路径。新字段必须可JSON序列化，禁止NaN/Infinity/函数/循环/危险对象键。

### SR002-D01 字段级校验表（目标契约）

下表是新写入记录及显式迁移完成后的验收目标，不表示当前 `validateContracts` 已逐字段执行。现行 `schema 6` 允许旧活动、旧场景和历史消息保留其已登记的局部形状；加载顺序必须先识别 `schemaVersion/rulesetVersion/contentVersion`，隔离迁移并记录来源，再按对应版本校验，不能把新增必填项直接用于拒载尚未转换的有效旧档。`R-25` 提供统一实体/事务原则；本表未获用户逐值确认的细项为 **R（作者实施默认）**，时长、场景尺寸及影响平衡的数值为 **T（可调）**。`0`、`false`、`[]` 均是有效值，不能用真值判断代替类型判断；“可空”只允许显式 `null`，不等于可缺省。

共同类型：`ID` 为带表前缀、不可因改名重用的非空字符串；`tick` 为 `0..Number.MAX_SAFE_INTEGER` 的整数且已发生时刻 `≤ worldTick`；`durationTicks` 为正安全整数；`metre` 为有限数，坐标须落在对应场景的合法空间/碰撞定义内；比例为有限 `0..1`，数量为有限非负数。字符串需非空且有内容定义所给的长度上限；列表须为数组、引用项不重复。所有显式引用在记录活跃时必须命中同一状态快照中的目标主表；历史终态可保留已释放的活动/预约/工作单 ID 作为来源，但不得重新当作活跃占位。错误返回包含稳定错误码和完整字段路径。

2026-10-07 的公开操作审计使用同一 `seed 618033` 有来源的第11境山院存档，继续至第12境并完成调查、三场战斗及返院。`qa/ea-sr-integration-acceptance.mjs` 在出发前、在途、抵达、战斗起手、人物实际受伤时、返程途中和返院分别执行精确存读并保留阶段档；在途人物无山院活动，斗法只占一项 `sr-combat` 身体活动。独立复核的世界步依次为 698140、698140、698340、698952、699701、699980、700505；受伤时 `wound=23.5602` 对应战场 `HP=146/191`，铁剑和法袍实例、归属和槽位沿路不变。此证据满足 AC-01 的运行时公开命令口径，完整 D/I/V/R 仍按各自门槛推进。

当前版浏览器持久层仍以 Web Lock 保证单档单写者，保存调用同步返回读回结果。超过 256 KB 的有效本地 JSON 封装可压缩存放；旧未压缩档仍直接读取，下载导出保持普通 JSON。压缩封装记录原始字节数，解码后继续按当前 schema 校验；普通保存与压缩封装均以 8 MB 未压缩输入上限检查。有效旧主档进入滚动备份时可转为等价压缩封装；迁移或异常源档的原始资料保留区仍保存其原文。容量或写入失败时不报告成功，原主档保持可恢复并提供导出。

数值时间：worldTick/revision为非负安全整数；每tick100ms，ticksPerDay1200。字段名后缀Tick必须是非负安全整数，atTick不能超当前世界步。现实关闭、后台和暂停不结算。各模块可使用beginContractTick(s,module)去重同tick；它仅登记游标，不增加worldTick。

## 命令、事务、错误与顺序

入口`executeContractCommand(s, command, {handlers, clone, validate})`返回新状态；只有status committed时调用者替换原状态。actorId默认掌门，直接控制其他人物拒绝。command.id为稳定command:前缀（数字序列或会话序号）；args必须数组；expectedRevision不匹配拒绝。数字旧编号没有账本时也不能再执行。相同ID/签名重送返回already-applied，改参数复用ID返回command-id-conflict。

在隔离clone执行所有handler修改，再更新revision/命令账本并整体validate；无效引用、异常或领域前置失败均保原状态。返回status/commandId/revision/reasonCodes/transactionId/changedIds/result/saveStatus/replayed。changedIds目前空列表，不能假称列全实体差异。committed是内存事务，saveStatus为not-yet-saved；磁盘成功另行更新保存反馈。错误码为unsupported-version、invalid-reference、stale-revision、invalid-identity、not-authorized、command-id-conflict、invalid-contract、pending-placement、save-failed。

### 命令的可执行前置与回执（SR002-REQ-02）

命令信封目标形状为 `{id,name,actorId,expectedRevision,args}`：`id` 满足 `command:` 加稳定序号/会话键，`name` 命中已登记 handler，`actorId` 省略时仅表示 `person:master`，`expectedRevision` 为提交时读取的非负修订号，`args` 为 JSON 可序列化数组。正式入口在解析后按下列顺序判定；同一 ID 已提交时先比较持久签名并返回旧结果，不因后来状态变化再执行。签名由命令名、实际 actor 与参数确定，`expectedRevision` 只用于首次提交的过期判断。领域 handler 继续校验目标/可知/所在场景/身体占用/资源与权限；统一入口不得用错误码掩盖这些领域原因。

| 边界 | 前置/提交条件 | 成功结果与拒绝语义 |
| --- | --- | --- |
| 解析/版本/身份 | 信封及参数形状合法；当前结构/规则/内容版本已识别；所有 ID 前缀、活跃引用和 actor 有效 | 无效信封或定义为 `invalid-contract`，未知版本为 `unsupported-version`，身份字段与键冲突为 `invalid-identity`，缺实体/外键为 `invalid-reference`；均 `rejected`、原状态及修订号不变。 |
| 重送与并发 | 持久 `outcomes[id]` 先于修订比较；旧数字序列 ID 未在账本时不得复用；首次请求 `expectedRevision===revision` | 相同签名返回 `already-applied`、旧 `result`、`replayed=true`；同 ID 改签名为 `command-id-conflict`；过期修订/序列为 `stale-revision`。既有结算和 RNG 均不重做。 |
| 权限与领域前置 | 当前只直接控制掌门；实体存在且掌门有合法知情与可达性；活动未占用身体；必要场地、工位、预约、库存、能力、阶段及截止仍有效 | 非掌门直接控制为 `not-authorized`；目标仍存在却因道路、材料、工位、身体等失效时返回领域稳定原因码及可恢复动作，不把等待伪装成已完成。无法安置的旧资产为 `pending-placement`，保留资产与恢复入口。 |
| 事务提交 | 在隔离副本计算预约/扣费/活动/事实/结果键；统一与领域验证全部通过才增加一次 `revision` 和命令序号 | `committed` 只说明内存事务成立，回执给 `transactionId/result/saveStatus=not-yet-saved`；`changedIds` 应由提交前后权威实体差异产生并稳定排序，**现行实现固定空数组，尚不能用于审计**。验证或 handler 异常拒绝时不能替换原状态、推进时钟/RNG、留下部分预约或结算。 |
| 保存与读回 | 提交后的持写锁保存、备份、回读另行确认；保存失败与事务失败分别呈现 | 持久写入成功才反馈 `saved`；失败用 `save-failed`、保留内存新态与原档/导出路径并暂停，不能再次扣费。128 条短收据可滚动；永久结果键及领取键在读回后仍拒绝重放。 |

现行 `executeContractCommand` 已实现信封、重送优先、修订/掌门检查、隔离 clone、整体验证和内存回执；它对 handler 抛出的无编码异常回落 `invalid-contract`，尚未统一领域原因码、`changedIds` 或同步磁盘提交。测试应分别断言“命令被接受并登记计划”“实际活动完成并产生结果”“磁盘保存成功”，不可混用；NPC 对邀请的接受/拒绝属于后续世界事实，不属于命令校验结果。

transactions.receipts保留最近128条；transactions.outcomes永久记录已提交ID、签名、修订和结果，读档后仍能防重复，不能因短收据淘汰重新扣费。新档导出保持该账本。

共同效果层：protection → stabilization → contact-damage → ongoing-loss → recovery → death → observation。层仅提供确定规则枚举，领域实现负责从相同阶段快照聚合与裁定；定义存在不代表已实现全部同tick救援/死亡。

世界步接入目标按 [05](../../design/05-RUNTIME-CONTRACTS.md) §§4–6 固定：①按序收本 tick 合法命令/NPC 已定意图；②到期天气、路线、设施条件重验；③推进真实移动/活动并确定**本 tick 已完成**的效果；④同一阶段快照汇集效果，按上列七层处理；⑤合并伤势/危机/资源/工作单，仅在合法稳定与恢复均计入后判不可逆死亡，并原子写遗物、释放与死亡记录；⑥发送/送达观察和消息、更新信念；⑦修订/只读投影/保存。相同 tick 同层以稳定效果 ID 排序仅用于重放，不能以遍历或画面回调顺序决定生死；新下达救治需先完成正整数时长，已在攻击前完成的合法稳定可生效，晚于不可逆死亡的治疗不可复活。加速/批处理在到达、动作完成、危机、死亡等边界拆分，与逐 tick 同输入对照。**现行 `EFFECT_ORDER` 只是枚举，`tickSR` 仍顺序调用各领域；全领域统一快照/聚合、对等相杀与批处理等价属 I01 待实现/验收**。`beginContractTick` 只防模块同 tick 重跑，不是第二时钟。

knowledgeView(s,{observerId})只输出public/knownClaimIds/knownByIds允许的消息，含来源、观察时刻、收到时刻和有限locationHint。不会输出作者truth或未公开消息；调用前后权威状态必须一致。

知识投影目标输入为**已校验且当前世界步固定的权威快照**与有效 `observerId`，输出是新对象列表；不得改变 `claimsById/factsById/beliefs/worldTick/revision/rngState`。逐条先判公开、已实际送达或观察者 `knownClaimIds/knownByIds`，再给 `id/text/可知来源人/observedAtTick/该观察者自己的 receivedAtTick/有限 locationHint/certainty`；证据事实、转述根源与核实程度分别按观察者已获知范围筛选。旧档缺逐人送达时刻时输出 `receivedAtTick=null` 与已知来源标识，不能猜作发话时刻。未送达消息、作者 `truth/truthType`、秘密参与人、准确远程坐标、当前危机剩余倒数不进入 UI、地图、日志、特效、API 包。陈述的“已核实”仅指该观察者有相应来源，不把后台真值直接公示；迟到消息保留其观察/收到两个时刻。**现行 `recordClaimSR` 已为初始收件人登记逐人时刻，实际传话完成才追加收件人、送达事实及其时刻；`knowledgeView` 只读该观察者的 `receivedTickByPersonId`，旧档缺证据时返回 `null`，不以 `issuedTick` 推断。** `qa/ea-sr002-receipt-time-acceptance.mjs` 的延迟送达、旧档缺值、再次传话与伪造收据 5/5 经独立复核。`knowledgeView` 仍直接转发已存 `locationHint` 和 `verification`，证据权限、位置精度、传播时序及领域 UI 的独立投影尚须逐字段审查；自含存档校验不能证明被整体同步篡改前的外部历史。隐藏真相/假消息的同档查询及产品画面仍属 I01/V01 集成验收。

## 内容编译与版本矩阵

`validateContentDefinitions`隔离校验输入并返回clone；校验成功前不修改当前运行内容。输入version1/contentVersion sr-content-v1.2；persons/items/scenes/routes/claims/crises/activities/authorCards对象表必填。每定义id与键一致、全局唯一、references数组每项存在。activities还须durationTicks正整数及合法effectLayer；authorCards还须truth对象、clues/outcomes数组与user-confirmed/recommended/tunable来源。详细领域条件由领域内容验证补齐。

### 作者卡到运行定义的编译门槛（目标）

作者输入和运行实例分开。作者卡源至少含 `id`、卡自身 `version`、`sourceStatus∈{user-confirmed,recommended,tunable}`、`scope`（地区/境界/一次或可重复）、`truth`（固定起因、参与者、机制、既发生事实）、`publicClaims`（发言者、收件范围、来源/时间）、`clues`（来源、独立性组、取得条件、时效）、`timeGraph`（可观察→定位→到场→干预和迟到边界）、`actions`（前置、正整数时长、距离/材料/效果层）、`outcomes`（接受、调查、拒绝、反制、失败/迟到后的持久事实与幂等键）、`persistence`（实例种子/既定真相/迁移）、`acceptanceIds`。重要链的根 ID、`rootKind`、`manipulationTag` 与理由按 [09](../../design/09-INTRIGUE-OPPORTUNITIES.md) 登记；稀世内容的隐藏联系和至少两条不共享误导根源的查验路径按 [12](../../design/12-CONTENT-AUTHORING.md) 固定。`truth` 和原始利害只用于编译/权威规则，不进入玩家投影或可选 AI 包。以上字段及分支最低集是 R-25/12 的作者实施目标，不声称现行 JSON 卡均具备。

编译器按确定顺序处理且**全程不写运行状态**：

1. 解析 JSON、版本和对象表，拒绝不可序列化值、危险键、空/重复 ID；诊断给 `cardId/table/fieldPath/code`，不只报“内容无效”。
2. 解析 `references` 和显式字段引用，构建“定义 ID → 人物/物品/场景/路线/事实/危机/活动/作者卡”有向图；检查目标存在、前缀与类型相配、场景/路线端点有效。允许有说明的故事因果回指，不允许实例生成循环或同一领取键由两条分支共同结算两次。
3. 归一单位与数值：米、比例、100ms 世界 tick，成本/库存非负，行动 `durationTicks≥1`，效果层属于七层；路线和危机时间图需可从合法知情时刻经实际路径到达，至少保留一条可靠主线/查证路径，不能以作者全知坐标证明可救。
4. 因果审阅检查真相在激活前固定、线索先于不可逆承诺/伤害、两个独立来源不共用同一转述根、NPC 自主/成本/伤亡和拒绝/迟到后果存在；约 40% 算计只按重要**独立根链首次对玩家可参与激活**计数，不按消息或带 `schemeId` 的普通内容计数。此步需要作者审阅加可执行样本，不能仅靠 JSON 类型校验宣布通过。
5. 输出带 `version/contentVersion/rulesetVersion` 的不可变定义包及来源映射、诊断和验收 ID；先在隔离态调用结构及领域验证，成功才激活。实例生成时保存参与身份、已定真相/机制、局部随机状态、结果键与 `contentVersion`；已激活链不得因热更重抽，必要修复走显式迁移并保留原因与旧值。失败不激活、不扣资源、不发占位奖励，现有世界与原始内容包仍可恢复。

**现行边界**：`validateContentDefinitions` 仅检查八张对象表、全局 ID、声明式 `references`、活动时长/层和作者卡 `truth/clues/outcomes/sourceStatus` 的浅层形状，返回克隆；它没有把 12 的完整作者卡编译为运行定义，也没有检查字段内所有引用、线索独立性、时间图、分支可达性、内容版本热更或真相泄漏。`dist/ea-sr-world-content.mjs` 的部分卡是代码内固定数据，不能把其存在等同于上述编译门槛已通过。此处为 D01 契约，落实及领域验收归 I01/V01。

`migrateState`首先structuredClone原输入；`prepareMigration`保留原始JSON文本或对象序列化原文，先拒绝未知结构，并要求调用者提供能返回已校验 schema 6 状态的完整 `validate`；旧 `version=1..5` 还必须提供 `validateLegacy` 和 `migrate`。候选档经完整校验后才在隔离副本执行 `initContracts`，再次校验通过才返回新 state；旧档须先落到 `opening-runtime-2` + `legacy-ea-1.4.2`，坏版本/引用不得靠初始化补成合法档。`commitMigration`先backup原文，再write新文；备份失败不写，写失败返回内存state/originalRaw/save-failed供导出与恢复。`qa/ea-sr-version-gate-acceptance.mjs` 已覆盖缺校验器、坏版本与旧档原文不变；实际浏览器仍用现有persistence原档/备份/写锁流程，完整浏览器故障路径待验。存储write函数本身须采用现有受保护写入协议。
