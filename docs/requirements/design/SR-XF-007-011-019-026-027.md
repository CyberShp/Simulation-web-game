## SR-XF-008：自主日程与承诺

候选过滤身体伤势>20、精力<22、饥饿、外出/行程、另一身体活动、设施失效/迁建、通路不达、工位不可用、原料不足。不能做以 available=false 返回具体原因；可以但不愿做按自律0.3、仁心0.1、信任0.4及草木志向药田加15评分，阈值42；不是掷骰。

相同设施、身体阈值、关系档位和物资条件的邀请保存签名；重复点击不重抽、加关系或改变意愿。接受后承诺240tick，正常微小评分变化不打断；伤势、危险、外出、失去设施合法中断，释放原工位后重验。当前回执给出120tick重试建议，但尚未执行阶梯退避；同一活动只有一个身体引用。日相位默认0—20%休整、20—55%生产偏好、55—80%研习偏好、80—100%休整；schedule钩子仅约束旧自主 owner，不另做execute。重要人物关系与私有动机仍用既有 mind 和记忆；产品投影只显示公开理由与本人说法，不投影 privateMotives。

### SR-XF-008-D01：候选、日程与职责目标契约

本节给出 `autonomy:yunxiu:v2` 的**设计目标**，供 D02 审阅和 I01 实施；当前运行时仍是 `autonomy:yunxiu:v1`，本节不会使下述目标自动生效。来源：U-63 授权作者补齐前期细节，R-25 确定前期范围，[01 人物](../../design/01-CHARACTERS.md#4-日程需要与可解释决策)规定自主意愿、活动和隐私，[05 运行时](../../design/05-RUNTIME-CONTRACTS.md)规定单时钟、命令与存读，T-03 给出 3–5 人小院和 24–32 人宗门的验收规模。下述分值和时间是作者可调起点，不是用户逐项确认；现有 `v1` 已通过的三条 AC 只证明各自情景，不代替本节的完整日程实现。

| 维度 | `v1` 已运行的事实 | `v2` 待实施的目标 |
| --- | --- | --- |

候选处理顺序固定为：从本人已知的目标、现有活动与实际机会列候选 → 检查身体和危险 → 检查身份/权限、目标、可取得资源、路径与空间占位 → 核对既有承诺 → 计算效用 → 按分数、候选稳定 ID 排序 → 本人决定并写唯一活动。仍由既有 `tickSociety` 自主决策入口在同一世界时钟调用，不建立第二个执行循环。`available=false` 表示当前**不能做**，记录首个阻塞原因和可恢复条件；`available=true, willing=false` 表示**可以但不愿做**，记录本人公开说法。岗位资格不够、材料不在现场、无可达工位、人在外地或已经被其他身体活动占用均不得用低分伪装成不愿意；不愿承担危险、信任不足或个人志向另有所向也不能伪装成建筑故障。

| 候选 | 硬条件及可用时段 | 效用输入与职责边界 |
| --- | --- | --- |
| 休养、饮食、疗伤 | 本人在合法位置可取得床、食物或治疗机会；伤势 >20、精力 <22、饱食 <20 时优先处理紧急需要；恢复到40后退出紧急补给判定 | 需要值高时优先，不因岗位承诺强迫带伤生产；缺物资时说明等待或改找合法来源 |
| 生产、采集、施工 | 本人知晓机会，有可达目标、合法材料与实际独占脚点；20–55%日相位偏好，不是硬限制 | 志向、现有技能、供给责任、关系及现场风险参与评分；多人共享一个工作单但各占不同工位，每人每步最多贡献一次 |
| 研习、修炼、授业 | 本人可接触对应知识，达到具体法门要求，能到书案/静修位；授业还需老师有真实理解、双方有空闲时段和位置；55–80%偏好 | 已同意课程可预约时段；师徒关系影响意愿，不自动授业或分享全部知识；独处私学只显示可公开活动 |
| 巡护与组织职责 | 已自愿任职、具备岗位能力，实际巡护位置可达；巡护可跨日相位，授课需双方同时有空闲 | 职位是长期约定，不等于每步自动产生巡护/授课收益；同一人同时只占一个身体活动，出行时院内贡献为零 |
| 出行、同行与救援 | 本人已知地点/消息，有实际路线、合法补给、准备时间与风险窗口；已有职责先完成、告假或交接 | 同行须本人同意；风险、亲近关系与已知危险影响意愿；离院释放院内执行位，所在地与消息时间不能冒充实时全知定位 |

普通非紧急候选的作者默认分数为 `clamp(0,100, round(需要×0.24＋志向×0.18＋能力×0.16＋关系×0.16＋责任×0.16＋时段匹配×0.10－风险×0.20－切换成本))`，六项正向输入、风险均在0–100，切换成本为0或15分；邀请接受起点为42分。能力的正向分只表示熟练程度，不能覆盖法门、任职或身体硬门槛；责任分只来自本人已同意的约定。时段匹配为偏好，已有有效承诺不因跨相位失效。危险、伤势或饥饿的紧急选择先于此分数；同分按稳定候选 ID 排序，不消费随机数。实际平衡数据和各类岗位表现由 I01/V01 用 3–5 人与 24–32 人有来源档校准，调整须升配置版本并记录迁移依据。

工作邀请首批的切换成本取值：本人已在同一目标工作，或从休憩、空闲起步时为0；离开正在进行的工作或其他有效身体活动去接新差事时为15。当前伐木、采石、药田、稻田和百工普通生产均无最低专技门槛，能力使用50为普通起点，超过50的本人实际技能仍计入评分；藏经阁、灵泉等对应能力继续读取本人实际技能，额外资格另按各自规则核对。工位可行性、身体占用和路径仍先按硬条件核对，不能用能力起点代替。

| --- | --- |
| 需要 | 休养/饮食取身体缺口，工作取本人已知的生活供给缺口，研习取已立阶段目标的学习缺口；无相关缺口为50，不能读取隐藏世界库存 |

`v2` 的新增持久记录仍附于同一 `personId`：`person.lifePlan={id,goalId,createdAtTick,currentStepId,dependencyIds,commitmentIds,reviewAtTick,status}`；`schedule.commitmentsById` 各保存稳定 ID、来源事实、活动/目标、开始与到期 tick、本人接受状态；`schedule.responsibilitySlots` 保存职位 ID、可用相位和当前代班/告假事实；`schedule.retriesByTarget` 保存条件签名、连续失败次数、下一次可重新判断的 tick；现有 `schedule.invitations` 留存回执与公开理由，`privateMotives` 只作权威事实引用。`activityId`、工位 `slotId` 和 `reservationId` 继续指向已有身体/空间权威，不在日程里复制第二套执行状态。新字段在 `v2` 启用时才要求校验，D02 须审阅字段名、事实来源与依赖接口。

达到成熟和照料条件后，先以冻结的产量规则及当时已记录的人员、天气、设施状态试算完整一批，并检查同一灵草来源尚有足额实际产量及田边仓容量；来源不足则保持 `ripe/waiting`，取得补种材料并实际补种后再验；仓满则腾仓后再验。采购本身不增加地块的有限来源余额。成功时只写一条 `fact:production:<building>:<batch>` 与关联的 `fact:crop:harvest:<building>:<batch>`，按实际产量扣有限来源并把药草放在田边，不再另发第二批草；`harvestedAtTick` 固定，`fallowUntilTick=harvestedAtTick+1`，下一世界步才能播下一批。切镜头、刷新、暂停及读档只重建显示，不改上述时刻或重复扣种/收获。此阶段化过程是 v2 目标；现行 v1 药田已在公开来源档验证的无逐批种苗生产照旧按已登记结果保留。

### 施工、生产与迁建接缝

新施工订单确认后，从公库扣下实物投入，另建主屋预留仓与工地仓；工单 `materialFlow` 记录 `sourceStockpileId/siteStockpileId/cargo/carrierId/trips/phase/cancelRequested`，每趟最多 **40** 份。掌门实际到主屋取料、走至工地交货，全部实物到场后方开始施工；每步安装从工地待用量移到 `usedCost`。逐键满足“预留仓 + 携带 + 工地 + 已安装 = 本单实物投入”。灵石费用仍按原工单预约和结算，旧无 `materialFlow` 的在建档保留原结算，不追溯添加运输。

取消新施工时先携当前货返主屋，再逐趟从工地收回未用料；全部到仓后按工单一次结清 `cost-usedCost`，已安装量不退。路断或受伤时材料与进度保持原位，恢复通路/身体后继续；迁建中的仓位锁暂停普通搬运和生产，先处理当前身体事务，几何与库存位置一同切换。生产输入只在设施仓位真实交付后可用，工序预留从该仓位扣下；无人到工位、源在途或容量不足均不能虚产。完成/取消/拆迁时，工作单、预约、场地仓位和事实键按同一事务结清，不留第二份材料。

藏经阁的道韵产量直接记入云岫公库的研习预算；开工可用性先按声明产量检查公库容量，结算再按实际产量复查，满库时保留原批次与来源等待腾出空间。旧档中已入藏经阁公仓的未预约道韵一次转入公库并记迁移事实；原私人、商人余额和已在途预约保持原所有权与结算路径。旧档原有超容量余额原值保留，新产出继续受容量约束。
