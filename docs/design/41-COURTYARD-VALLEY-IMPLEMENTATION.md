# 云岫炼丹与山谷实玩 · 实施记录

## 授权与交付顺序

U-123：用户确认按以下顺序以目标模式、多 agent 完成开发。沿用 U-120 游戏界面、U-117 新山院、U-119 掌门控制、05 共同运行契约。每批完成实际操作、相关失败和存读验证后同步源码及已有 Pages；真实设备和用户评看分别记录。

1. 山院采药／种收 → 实际搬运 → 丹房炼药 → 成丹入库 → 取药疗伤。
2. 云岫山院 → 山谷 → 场内行走、采集和会面 → 实际返程与带回所得。
3. 山谷首战 → 攻击、护持、躲避 → 伤势、撤退 → 回院治疗。

## 第一批：丹房与第一炉

- 复用既有回春散丹方：一炉消耗公库灵石 10、炉边灵草 10；200 世界步，成丹 2 份。费用、产量与其他丹方继续读取规则定义。
- 新丹房建位 `site:alchemy-court`，米制坐标（46，26），占地 6×6 米，南侧留门道。按既有建造成本、工程、实物运输及工位规则营造。
- 百艺页以丹方、丹炉、当前炉事和成丹去处组织；当前规则为掌门亲炼单炉。用料缺口、炉事中断和可用药物读取实际状态。
- 新档筹料使用现行山院亲采、随身搬运与来访商人交易；商人到院、距离、库存及价款以现有市场规则决定。宗务提供对应操作。
- 丹方产物先落在丹房货位，送回公库与取到随身均经过正式物流。服药读取真实伤势／精力／修为收益。
- 封闭丹房显示完整外观，工位与人物劳动在同一空间和时钟中运行。

预计文件：`dist/ea-godot-bridge.mjs` 的只读炼丹／取材／商人视图，必要规则常量导出；`system-crafting.*`、`system-sect.*`、共同 UI 接线；`estate-sites.json`、`estate.gd`、丹房透明素材及构建清单。

## 第二批：山谷往返

- 复用 `scene:valley`、`route:home-valley`、有限药丛、青萝与既有对象。场景画面和碰撞采用同一实际坐标。
- 山院与山谷各有可见出口。远处选择出口先行走，近处启程；旅行经过真实世界步，到达后切换地点。
- 青萝会面要求本人存活、同场且近处。采集扣除有限存量，物资进入队伍货位，返院后搬入公库。
- 山院、途中、山谷存档均可继续；掌门及携带物不复制。山外窗口负责公开地点、路线和当前行程。

预计文件：`ea-sr-world.mjs`、`ea-godot-host.mjs`、桥接世界投影、Godot 场景呈现与山外页。

## 第三批：第一场山谷战斗

- 在谷内设置稳定身份、可见的低阶遭遇，近处触发；沿现有同场战斗结算、动作起手／收势、装备、攻防技与伤势。
- 游戏场景提供目标选择、攻击、护持、躲避与撤退；征兆和动作反馈可见。炼气掌门可参与此遭遇。
- 撤退结束战斗并回到山谷安全位置，之后走出口返院；回院使用第一批药物治疗。
- 具体敌人数值为作者试算，按现有同境预算与实玩校准。首战结果和伤势写入正式存档。

本批作者试算：山魈身份 `person:valley-shanxiao`，常驻谷中（27，36），玩家走近后主动应战。山魈气血 160，基础伤害 10，起手 18 步、收势 20 步；沿现有天气修正。战斗空间为谷内 12×8 米，原点（21，32），撤离点（21.7，36）。角色实际脚点随战斗移动，战报确认后继续探索；战败保留原地重伤，仍可安排返程。胜利记录同一山魈死亡，不附加凭空掉落。

青岚、赤阳、寒泉、厚土、金锋均使用开局实际习得的攻击和护持。界面冷却、起手、命中、气血、灵力与伤势读取正式动作结果。闪避给出四向落点，场内点地可移步；敌方起手在地面显示范围征兆。

预计文件：现行战斗规则、战斗入口／结算、桥接、Godot 战斗呈现和必要 UI。身份、物品、时钟、保存继续共用当前模拟。
