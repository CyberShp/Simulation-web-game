## 写入、读取与校验路径

- 天气每 600 步生成 `weather`，水涝每 300 步生成 `ecology-damage`；当前天气的 `sourceFactId` 与生态最后 40 条 `traceFactIds` 是有效引用。
- 每日供给写 `daily-supply-relation`，信任/饱食的效果已计入人物。日结算及人物动机仍按 `personId + dayIndex` 隐式查询当前凭证，不能仅依显式引用判断。
- 商人到院生成 `merchant-arrival` 流水；往返生成 `merchant-travel`。在途/阻塞者的身体、货仓和经济游标仍引用旅程；完成后可成为历史候选。
- 原始生产流水参与立派的资源种类、设峰的两批供给统计、作物批次序号、幂等以及工单验证。普通已到达旅程参与同行物资预算资格；票据、跨界、供货及救援还有各自引用。这些全部保留。
- `validateV6Shape → validateContracts`，及 `validateSave → validateSR → validateContracts` 会完整遍历序列化主表；命令先克隆隔离草稿再完整验证，成本随纯历史增长。保持严格校验，通过压缩其输入减少成本，未引入会跳过原档验证的缓存。

## 保留与摘要契约

`HISTORY_POLICY` 为本批作者可调参数，不改变游戏费用、资源精度或天气规则。每 600 个真实 100ms 世界步执行一次；不是墙钟定时器，也不是 UI 或保存回调。

| 可候选类别 | 最近明细保留 | 额外保护 |
| --- | --- | --- |
| weather | 120 条 | 当前 `sourceFactId`，全部外部证据/知情引用 |
| ecology-damage | 120 条 | `traceFactIds`，任何剧情/调查/人物引用 |
| daily-supply-relation | 每人最近 2 条 | 当前游戏日、`society.lastDay`、`economy.lastSupplyDay` 的隐式凭证 |
| inventory-transaction / merchant-arrival | 20 条 | 经济界面最近 20 笔原始流水、全部外部引用 |
| merchant-travel / completed | 32 条 | 身体/货仓/游标、明细流水等任何引用 |

根扫描递归读取所有其他状态的字符串值与键，包括嵌套证据数组、人物知情、交易收据、物品位置、剧情结果、运输票据及未来扩展字段；再沿保留事实/旅程求传递闭包。未知类别、生产/交易/剧情结果、一般旅程，以及结构不完整或引用损坏的候选保留。事实自身的 knownByIds / knownByPersonIds / knownBy 知情标记、公示、亲见及行为者也使其长期保留，保护没有人物前向 ID 的既有知情。唯一行为者例外为已结算商旅到货审计的固定商人标签；该类仍保留全部证据、知情、公示引用及最近账目。只有白名单内、形状完整、无有效引用且超过窗口的记录才删除明细；以五个固定分类汇总计数及首末世界步，不创建另一张随时间增长的完整历史表。

这不是对所有事实的硬上限。仍在影响玩法的历史、有限世界内容和显式引用增加时，保留量可以增加。不能用丢失证据、幂等键或暂停人物活动换性能。两次清理之间可新写入少量候选，因此参考旧档中天气 120/121 条都符合策略。

schema 6 原档缺少 `historyRetention` 仍支持，加载不剪枝、不补跑，不改原文。开始实际世界步后才建立该可选字段。已有归档的版本、游标和五类摘要严格校验；未知版本或坏引用拒载。`validateSave`、保存和查询均不执行剪枝，确保相同档二次保存一致。

## 可重复运行

基准脚本执行每个真实世界小步，不跳过人物、生产或天气。`tickCallMs` 是一次 `tick(s,1)` 的 10 步总成本；独立比较脚本直接测 `tick(s,.1)`。存档大小使用 UTF-8 字节，命令测真实网关的 `setSpeed(1)`，并在隔离草稿上执行，保持长跑轨迹不被测量命令修改。

```bash
# 将基点的 dist 文本模块及 yunxiu-courtyard 依赖准备在仓库外 before/dist。
node qa/ea-history-benchmark.mjs --runtime /tmp/before/dist --label opening-before --commit 36b6dd3 --hours 6,12,24,48 --output /tmp/issue6
node qa/ea-history-benchmark.mjs --label opening-after --hours 6,12,24,48 --output /tmp/issue6
node qa/ea-history-compare.mjs --before-runtime /tmp/before/dist --scenario opening --directory /tmp/issue6
# 两边加相同 --fixture qa/ea-travel-world.json 或 qa/ea-reference-world.json
# 并对应使用 legacy-before/after、reference-before/after 标签。
node --test tests/ea-history-retention.test.mjs
```

比较前等待对应基准结束。比较脚本在每个时点交替测量 24 轮，丢弃前三轮，再推进两边各 1,200 个真实小步。除历史表/摘要外的所有可序列化状态须精确一致；保留明细须是原表的未改子集；天气、经济、宗务、世界知情投影须精确一致。资源、RNG、身份、伤势、信任、剧情、工单、在途位置和库存因此逐字段比较。

基准来源：正式 SR 新档；原 `qa/ea-travel-world.json` v5 两门人五建筑旧档；原 `qa/ea-reference-world.json` v5 三十门人四十建筑旧档。全程使用自然模拟，不注资、恢复饱食度、冻结人数或重新抽随机。门人可因正常供给状态自主离院；记录每时点人数，不能称为持续 30 人或原 Issue 的 16 人压力测试。单位测试中的大量人工流水与长跑来源分别标注。

### 玩法一致性与旅行增长边界

当前自然长跑的旅行在有限商运/路况下已稳定在 50 条（参考档 51 条），未复现旧 Issue 所述 1→181 的同样曲线。仍修复完成商旅的潜在无引用增长：160 条完成商旅的明确边界夹具可汇总为最近 32 条加外部引用闭包；在途/阻塞、一般同行、票据、货位及生产引用都保留。不能将边界夹具称为当前自然游玩的旅行曲线。
