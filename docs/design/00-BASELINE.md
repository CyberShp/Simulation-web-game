# 模拟仙府 · 统一设计基准

设计编号：DB-2026-10-05；版本：1.2；更新日期：2026-10-06（北京时间）。

本文是后续重构的目标规格，不是当前游戏功能清单。用户已确认的方向、设计者给出的实施建议、可调参数和后置范围，分别见 [决策登记](DECISIONS.md)。实际完成程度只以 [实现状态](STATUS.md) 和对应验收证据为准。

## 0. v1.2前期收束

本轮接续v1.0及v1.1，已确认的世界观足够开始前期详细设计，不再以远洲王朝、全势力名单或高阶规则未定为阻塞。前期范围、地方内容默认、固定复仇责任人、筑基条件与迁移安排统一见[14](14-EARLY-GAME-DETAILED-DESIGN.md)。作者依U-63补齐具体内容，按R/T标明来源；现阶段没有必须追加给用户的确认题。

保留单人浏览器游戏、仅控掌门、NPC自主、真实空间、单一时钟及危险永久死亡。运行代码与设计分开，目标schema 6不表示当前v5存档已经迁移。

## 1. 一句话定位

玩家作为遭灭门的修行世家遗孤，在有季节天气、私人利益、可信情谊与隐藏谋局的修仙世界中亲自行动，经营宗门、恢复传承、完成复仇，并承担门人自主远行、生死与共同事业的真实后果。

游戏的五个相互依赖的支柱：

| 支柱 | 玩家应当得到的体验 | 不能用什么冒充 |
| --- | --- | --- |
| 人物 | 认得出人、理解其选择、共同经历能改变关系 | 重复外观、无原因闲走、只有心情数值 |
| 空间 | 建筑真实改变土地、通行、容量和活动 | 完整背景上贴功能图标、永久预画地块框 |
| 修行 | 心法、术法、技艺和装备形成不同道路 | 所有功法只增加同一个攻击系数 |
| 江湖 | 选择改变人物、势力、线索和机缘 | 地区只是资源兑换按钮，NPC每次重新生成 |
| 经营 | 提供人们生活和成长所需的条件 | 强制派工、无限自动产钱、与人物脱离的计时器 |

## 2. 用户已确认的根本边界

以下是跨会话不应自行改变的产品约束；最新明确用户指令优先，改变时更新决策登记。

- 单人仙侠经营与角色养成；现阶段仍是浏览器游戏。
- 玩家只直接控制掌门。门人自主选择工作、学习、服丹、突破、任职和同行，玩家通过机会、制度、沟通与邀请影响。
- 掌门天资卓绝、来自修行世家，遭灭门，父母以生命掩护出逃，携带部分家传；第一大主线是复仇。
- 掌门不是绝对天赋上限。更优秀的弟子可以出现，权威来自能力、恩义、认同、制度与共同事业。
- 第一篇章《余烬立山》必须真正收束，不追加无限幕后黑手拖延兑现；结束后能够继续经营。
- 场景、营造、人物与交互需要共同重构。可见建筑和人物要融入同一个实际空间。
- 《天龙八部》经典单机版是侠义、套装、武学、事件和NPC关系的玩法参考。
- RimWorld、模拟人生、城市天际线及同类修仙经营游戏也作为系统关系的参考，不只借鉴画风。
- 保留苍劲有力的标题风格，正文以可读为准。精美素材不能牺牲交互可辨认性。
- 文档、真实玩法和验收要一致；数量、按钮、模板与自动测试通过不能冒充体验已经成立。
- 人物、场景和天气要共同持续变化，世界不能等掌门到场才开始存在。
- 正/魔/鬼/妖等道途不直接决定个人善恶；邪修违反共同禁忌，但邪修指控可能伪造，正统人物也可能暗中勾结。
- NPC在危险中可以真正永久死亡；斗法与死亡过程耗世界时间，玩家要获知线索、寻找并实际行动才能救援或谋害。
- 消息可不完整、失真或被操纵；稀世传承、装备、古洞天和重大机缘必须有暗线，真假因果不能按玩家后续选择临时翻转。

## 3. 本版推荐的整体方案

下列取舍是设计者建议，不宣称用户逐项批准。实施开始后默认依本版规格推进；若用户改变取舍，先同步文档和依赖，避免不同模型分别实施不同版本。

| 方面 | 本版推荐 | 选择原因 |
| --- | --- | --- |
| 视角 | 固定斜俯视、正交投影的2D/2.5D，可缩放和平移 | 统一人、门、建筑和地面尺度，控制素材成本与遮挡复杂度 |
| 空间 | 地形、道路、建筑、屋顶、物件、人物分别为实体 | 营造、移动、碰撞、选择和工作位置具有同一事实来源 |
| 控制 | 掌门直接行动；NPC自主；自愿队伍接受约定的战术号召 | 延续已定人物自主边界，保留玩家可理解的组织手段 |
| 战斗 | 延续即时移动、攻击、术法、守御、闪避；允许战术暂停 | 不在场景重构时额外改成回合制；多种传承产生不同打法 |
| 失败 | 掌门保持恢复/明确失败读档；NPC危险可永久死亡，并有发现、应对、濒死与后果过程 | 最新U-13覆盖v1.0 NPC死亡后置建议；主角硬核删档仍后置 |
| 成长 | 炼气至筑基为首轮完整范围；高境界预留接口 | 先证明不同道路可玩，避免内容体量代替深度 |
| 装备 | 有限四槽、来源可追溯、主题套装、可见关键外观 | 保留获取故事与搭配价值，控制无穷词条和视觉组合量 |
| 经营 | 少量完整供给链，有限产能和工位，真实物流 | 玩家能通过布局、人才和预算改善瓶颈 |
| 世界 | 具名关键人物与有限区域持续变化；主线节点可靠 | 有故事后果，也不依赖无限全世界模拟 |
| 时间 | 单一模拟时钟；暂停、后台和关闭不推进 | 延续存档习惯，避免移动端离开造成不可控剧情损失 |
| 规模 | 重点验收3–5人小院及24–32人中型宗门 | 人物可读、空间可用和系统稳定优先 |
| 谋略 | 重要事件/机缘链约40%有实质算计；稀世内容全部有作者暗线 | 普通交往和真实互助仍可信；不把每句话都掷骰判谎 |
| AI | 可选、默认关闭；规则世界完整可玩，AI增强授权表达 | 开关/掉线不改变命运，模型不生成新世界真相或结算死亡 |

## 4. 核心循环与相互反馈

1. 掌门发现一个具体问题、人物需要或复仇线索。
2. 在资源、时间、关系、风险之间选择解决办法。
3. 提供设施、材料、典籍和制度，或亲自外出调查。
4. 门人按照自身意愿和实际机会行动，产生可见结果。
5. 新人物、装备、知识、势力态度和事件后果回到宗门。
6. 宗门和外界出现新的生活方式、生产能力、传承道路、债务与未了关系，支持下一次行动。

NPC也有自己的生活计划、出行目的和风险判断；天气、供给、谋局与他人行动会改变其计划。掌门未介入的事件照样有发展和结局，近景与离屏采用同一时钟和规则约束。

例：药材短缺不是单独弹一条提示。它影响炼丹、伤者恢复和出行准备；玩家可以种植、采购、改变分工或求助；不同办法改变人物关系与地方支持。

## 5. 人物、空间与世界的控制关系

掌门是玩家的直接行动主体，不是无限权限的全知管理器。

- 营造规划、设施用途、材料预算、典籍开放和门规由掌门决定。
- 岗位或差事是一份可接受的机会，不能把“发布”当成“NPC必然执行”。
- 人物先判断意愿，再检查材料、道路、工位和身体状态；拒绝与阻塞必须区分。
- 日常生活由NPC自主执行。玩家可以沟通、调整条件、取消自己的邀请或更改公开政策。
- 自愿同行者在出发前认可队伍目标与约定。迎敌、集结、撤离属于约定范围的号召，仍受状态与立场约束；不提供逐个强制施法或改性格按钮。
- 正在履约的NPC有有限承诺期，不因每次微小评分变化立刻改意；危险、受伤、失去工位或目标变化允许打断。
- 隐私、隐藏动机和未发现违规通过证据逐步公开；UI不能泄露未获知的真实事实。
- 掌门对山外NPC的定位来自目击、消息、调查或卜算。已知最后位置不等于实时真位置，人物栏不能充当全世界GPS。
- 干预通过掌门的实际到场、布置、施术、救治和约定合作发生；无法把远方NPC强制拖出洞天或直接改成死亡。

## 6. 三种空间尺度

| 尺度 | 展示内容 | 数据来源与操作边界 |
| --- | --- | --- |
| 大世界 | 地点、势力、地形、已知路线、旅队、情报 | 地点引用持久localScene；在这里组织出行、查看局势 |
| 宗门/地区总览 | 实际地形与建筑缩略、峰域、活动分布 | 同一局部场景的缩放或聚合，不生成第二套设施 |
| 可操作近景 | 人物、门、工位、材料、内部生活和实际营造 | 同一实体身份与世界坐标；支持点选、互动、营造 |

建筑内部为同一局部空间内可显示的室内区域。初版以地面层和屋顶退隐为主；复杂楼层及上下重叠桥面后置。

## 7. 修行、装备与门派特色

人物成长分为修为境界、悟性理解、技能经验、法门掌握与个人志向，不能合并成一个天赋乘数。

- 拥有残卷、能够接触、理解内容、练会招式、能够传授分别记录。
- 主修心法形成稳定功体；术法/招式、身法和生产技艺在可用基础上分化。
- 装备的材料层次、制作品质、用途和故事价值分别表达。高品质不自动解除境界或知识门槛。
- 套装的获得关联人物和地区经历，效果改变使用方式；避免所有套路都只有攻击数字不同。
- 宗门特色由已有传承、人才、设施、资源和选择形成，初版不在开局硬选不可改变的职业。
- 普通资质的人也能成为药师、匠师、阵师或执事，有可见的成长与社会地位。
- 稀世内容有作者真相、公开说法、利益相关人、隐藏机制、线索与多条结果。传承确实强大也可能附有认主、抽取或职责条件；不能用“有坑”抹去此前全部价值。
- 高阶母子篇抽取为长期机制设计；首轮炼气/筑基先验证可缩尺的追踪、反制和危机过程，完整金丹/元婴内容仍后置。

## 8. 侠义与事件

侠义是行为后果体系。江湖名声画像、各势力立场和逐人关系分别记录。

- 救助、守约、背叛、夺宝和清算要记录对象、见证、证据、目的与手段。
- 正当复仇不自动等于恶行；波及无辜、违背承诺等行为有独立后果。
- 主线可提供选择，但可靠线索不能只靠随机刷新唯一NPC。
- 人物可以提供情报、传承、装备部件、避难和同行，也可以拒绝、讨债或报复。
- 事件有启动、参与、完成、失败和后续状态，不重复领取已经结算的奖励。
- 日常变化与随机遭遇需要节奏和恢复期；关键主线不因关闭网页或背景计时自行失败。
- 真话、陈旧消息、误解、诱导和蓄意谎言分别有来源与传播。查证获得有限新证据，不能开详情便知道所有真假。
- 人物可死亡、证人可失踪，主线用档案、第二证人或其他事实提供替代路径，不能复活关键NPC补剧情。
- 谋局者受时间、资源、地点、能力和暴露风险约束，玩家与NPC都可识破、反制或利用；不设置无所不知的导演敌人。

## 9. 开局基调与呈现

保留“雨夜余烬→落脚疗伤→赠药结缘→恢复生产→整理遗卷”的故事基础。细节目标见 [开局与验收](06-OPENING-ACCEPTANCE.md)。

- 首屏应清楚显示掌门、旧别院和当下需要，玩家先知道自己是谁、在哪里、为何行动。
- 初始经营范围小而完整，不把所有远期系统铺满屏幕。
- 首次营造必须形成与场景同尺度的实体，门人随后有可以看懂的真实活动。
- 首位同伴有姓名、身份、动机和可辨认外观，不以支付费用后突然出现一个匿名人口替代。
- 重要选择、扣费、接纳和剧情推进由明确操作发生。看剧情或确认已读不自动替玩家作选择。

## 10. 验收与实现边界

完整目标是所有系统共同成立，工程可以分依赖切片实现。拆分用于降低集成风险，不能把一个样机宣布成全部完成。

- 每个功能都要具备规则、数据、实际行为、场景反馈、UI说明、存档和失败路径。
- 至少覆盖一条贯穿人物、空间、生产、关系、装备/功法和主线的正常玩家事件链。
- 使用实际新档与旧档迁移验证；不覆盖用户正式三个档位。
- 自动测试、浏览器视口、真实设备、真人盲测、长时运行和平衡反馈分开记状态。
- 上线与设计通过不是同一件事。当前EA 1.4.2不能宣称已经满足本基准。
