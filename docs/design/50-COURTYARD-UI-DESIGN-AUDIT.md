# 山院管理界面审查与重整方案

2026-10-15，U-148 / R-48。审查基线为 main `d9751a9`、本日对话中的四页静态原型，以及既有系统界面和人物交谈设计。用户指出院务结构不对，认可“掌门自动设置＋单田操作代替了院务管理”的问题，并要求同查其他界面。

**结论：四页有功能接线，但信息架构、行动前后反馈和跨页路径尚不完整。该原型不能直接作为还原定稿。** 本文列出30项问题及修正提案；不是已经实施的新界面，也不改变唯一模拟、NPC自主、真实物资或时钟规则。既有47项组件检查仍只覆盖49记录的范围。

## 1. 范围与证据

- 已目视：对话中的院务／人物／修行／物资四页静态图。数值、肖像和工位数量是样例，不能据此推定运行数据错误或素材已获认可。
- 已核对源码：`courtyard-panels.mjs`、`courtyard-main.mjs`、`courtyard.html`、`courtyard.css`、`courtyard-inspection.mjs`、`sect-sim.mjs`及正式物资、研习命令。路径均在 `prototypes/pixel_scene_validation/`，正式模拟在 `dist/`。
- 已核对设计：[01人物](01-CHARACTERS.md)、[02功法装备](02-EQUIPMENT-ARTS.md)、[05共同契约](05-RUNTIME-CONTRACTS.md)、[07经济](07-ECONOMY-ORGANIZATION.md)、[20成长](20-ARTS-GROWTH-COMBAT.md)、[42交谈](42-CHARACTER-DIALOGUE.md)、[既有UI契约](../art/system-ui-20261012/UI-CONTRACT.md)、[49实际范围](49-P0-P2-COURTYARD-PROGRESS.md)。旧系统原型承担参考职责，不当作当前高清像素入口已经接入。
- 两项定向命令复现：大量收成搬运超限、取消搬运后的落地物资恢复；均从现有检查点走正常公开命令，没有改库存或补免费材料。浏览器点击和桌面真机本轮未运行。
- 标记“图”指静态原型问题；“码”指当前源码可确认的呈现／调用路径；“缺项”指详细设计或接入边界未定。源码静态风险与命令复现分开描述。优先级“高／中”仅用于本次UI整改，不等同06工程P0—P2，也不修改SR优先级。

## 7. 建议的页面职责与跨页关系（R-48）

这是待评看的信息架构，保留现有入口直到新方案完成接入和验证。四个名字是当前山院阶段的入口，不规定完整游戏只能有四页。

| 入口 | 第一层回答什么 | 深入对象与操作 | 跨页时携带的上下文 |
| --- | --- | --- | --- |
| 院务 | 院中现状如何、哪些事需处理、哪些事已在做 | 具体事务→生产／营造／供给详情；掌门自主安排是独立次级设置 | 事务ID、建筑ID、具体缺口、来源页 |
| 人物 | 找谁、是什么公开身份、目前怎样、已答应什么 | 掌门自身详情；NPC观察／交谈；已知身况、关系与所学 | 人物ID、名单范围、筛选排序、可靠消息时间 |
| 修行 | 掌门当前在怎样成长、选中法门有何用途、下一步缺什么 | 当前安排／已知法门及版本／学习条件／已有突破与转修条件 | 行为主体、法门ID、当前安排、来源人物 |
| 物资 | 有什么、在哪、归谁、哪些已占用、哪里缺 | 物资与货位详情、相关工单、搬运／回收详情 | 资源或物品ID、货位ID、需求事务、归属 |
| 建筑详情 | 这栋建筑能做什么、正在怎样使用、为什么停住 | 生产／施工／库存／席位，按已有类型和阶段组织 | 建筑ID、工单ID、选中席位及来源页 |
