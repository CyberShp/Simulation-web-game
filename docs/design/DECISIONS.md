# 设计决策登记

设计编号：DB-2026-10-05；版本：1.0。与 [统一基准](00-BASELINE.md) 一起读取。

## 状态与使用方法

- `user-confirmed`：用户明确表达、或本次重申的方向。后续模型不能自行改动。
- `recommended`：本版设计建议。它是可实施的默认方案，但不能汇报为用户逐项批准；用户可调整。
- `tunable`：数值、体量与节奏起点；必须用平衡/体验数据调整，不能暗中改变规则含义。
- `deferred`：明确后置，初版不依赖它完成核心循环。

模型不得把自己的偏好添加为user-confirmed。改变状态需要明确来源、理由与受影响的文档/数据/验收；新增用户指令优先于本表。

## 可调参数，不得当成永久世界规则

| ID | 状态 | 起点或目标 | 如何调整 |
| --- | --- | --- | --- |
| T-01 | tunable | 初次兼容基点120秒/游戏日；tick单位固定100ms作为本版数据契约 | 改日长要迁移日相位、日结算与事件到期；改变tick单位属于契约版本变更 |
| T-02 | tunable | 默认近景人物约44–64屏幕像素高 | 按素材与视口调；触控命中44px验收下限独立于人物显示大小 |
| T-03 | tunable | 小院3–5人；中型宗门24–32人 | 先验收拥挤、工作位、行为可读与浏览器稳定性 |
| T-04 | tunable | 开局15–30分钟学会核心循环 | 真人学习时间目标，不等于模拟运行时长或已实测 |
| T-05 | tunable | 剑/丹药/阵护三条首轮可行道路 | 可调内容数量，但每条必须有玩法差异和可靠获取途径 |
| T-06 | tunable | 首次套装、筑基、立派与分峰的节奏 | 依据正常新档的等待、选择密度与瓶颈调整 |
| T-07 | tunable | 成本、产出、契合增益、学习时长、AI权重、事件冷却 | 单独配置、记录变更和理由，不在不同模块各写一个常量 |
| T-08 | tunable | 常规压力场景30人/40设施，扩展压力40人/80设施；移动端30FPS、桌面60FPS、反馈100ms为初步目标 | 目标设备基线实测后修订；不得汇报为已达到或硬性支持上限 |
