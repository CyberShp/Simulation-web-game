# 12 · 世界内容作者、因果审阅与集成验收

设计基线：DB-2026-10-05 v1.1。目标规格，非已实现内容。最新用户指令优先；本文件把[活世界](08-LIVING-WORLD.md)、[谋略机缘](09-INTRIGUE-OPPORTUNITIES.md)、[危机救援](10-CRISES-RESCUE-DEATH.md)、[可选AI](11-AI-CONTENT-CONTRACT.md)变成后续模型、策划和开发可执行的内容规则。

## 1. 内容不能只有名称和奖励

每个重要NPC、稀世功法/装备、古洞天和重大机缘都要回答：谁想要什么，谁付了代价，公开说法是什么，隐藏事实是什么，怎样发现，能怎样应对，拒绝或失败以后世界留下什么。

有暗线不等于有恶人。有些传承受托保管，有些宝物与救灾誓约关联，有些洞天封着真正危险，也有些恩债只是当事人不愿讲。真相卡用于创作与规则运行，不直接发给玩家。不得临场因为玩家选择“相信”就把一个原本善意人物改成骗子。

新普通生活内容也要有日程、物资、关系或环境用途，但不要求每次做饭、收割和交谈藏谋杀。可信帮助、平常交流和共同劳作需要足够篇幅与实际价值，支持约40%重要链算计密度的体验。

## 2. 内容作者卡的必填项目

| 项目 | 必填内容 | 不合格表现 |
| --- | --- | --- |
| 身份与范围 | 稳定ID、版本、内容类别、境界/地区范围、一次性或可重复 | 以显示名判唯一；改名后可重复领奖 |
| 真相 | 起因、参与者、事实、利害与隐藏机制；哪些尚未发生 | 完成后才临时补出母篇敌人或幕后黑手 |
| 人物立场 | 道途、公开身份、真实动机、底线、资源、所知与误解 | 正道必善/魔道必恶；人物自动知道所有秘密 |
| 暗线 | 关联scheme/opportunity/fact/事件；义务、旧债、争夺或恶意标记 | 稀世内容只有说明、数值和掉落概率 |
| 公开说法 | 谁对谁说、声称什么、证据/利益关系、传播时间与渠道 | 一条传闻变成全世界同时确认的事实 |
| 线索 | 来源、位置、出现条件、独立性、可观察信号、过期与误导 | 所有所谓证据都来自同一骗徒，没有可获得的查验入口 |
| 能力与代价 | 真实效果、门槛、消耗、距离、设施、时间和暴露风险 | 恶人无成本任意定位/抽取；装备能隔空无敌 |
| 时间图 | 各阶段的开始/持续/触发、定位/出行/干预预算、暂停行为 | 求救收到的同一tick直接死亡；切镜头冻结远方 |
| 分支 | 相信、调查、拒绝、接受合作、反制、迟到或失败 | 只有作者预想的一条正确选项；拒绝则永远堵主线 |
| 结果 | 物资、伤势、知识、归属、记忆、名声、场景与后续机会 | 结算只写一段剧情，实际状态没有变化 |
| 身死与替代 | 可否致死、危机/死亡记录、遗物归属、关键证据替代 | 死者删注册、所有装备复制给宗门、证人复活补剧情 |
| 知情投影 | 世界真相、NPC相信、掌门知道、公开传播、开发诊断分别列明 | 人物详情、任务日志、AI请求暴露隐藏身份 |
| 持久化 | 实例/阶段/既定结果/随机流/领取键/迁移策略 | 刷新换幕后人、重载重新判定真假 |
| 验收 | 正常、拒绝、失败、迟到、无AI、重载及至少一条反制操作 | 只有控制台跳阶段和漂亮概念图 |

关键线索至少有两个独立来源或两种不共享同一误导源的验证办法。具体隐藏风险可以未知，但发现渠道必须符合掌门/其他人物的能力、位置和世界因果，不要求全知才能破局。

## 3. 最小逻辑示例

以下是作者输入的局部示例，不是完整存档。`causalSpecVersion`固定作者规则；`opportunityId/schemeId`最终引用权威主表。内容验证器应检查引用、单位、可达性与分支，不能把这个JSON当成运行中新增世界实体的后门。

```json
{
  "contentId": "content:rain-valley-legacy:v1",
  "causalSpecVersion": 1,
  "scope": {"realmIds": ["realm:qi", "realm:foundation"], "regionId": "region:yunxiu"},
  "opportunityId": "opportunity:rain-valley-legacy:001",
  "rootKind": "opportunity",
  "schemeIds": ["scheme:seal-handover:001"],
  "truthAuthoring": {
    "hiddenThreadIds": ["thread:inherited-seal-duty"],
    "manipulationTag": false,
    "causeFactIds": ["fact:old-seal-weakened:001"],
    "involvedPersonIds": ["person:artisan:001"]
  },
  "cluePaths": [
    {"id": "clue:old-repair-ledger", "sourceKind": "document", "independenceGroup": "old-ledger"},
    {"id": "clue:local-flood-mark", "sourceKind": "scene-observation", "independenceGroup": "terrain"}
  ],
  "possibleOutcomeIds": ["outcome:accept-duty", "outcome:negotiate-shared-duty", "outcome:decline-safe"],
  "criticalStoryFallbackFactIds": ["fact:other-evidence-route-known"],
  "acceptanceIds": ["CONTENT-01", "CONTENT-03", "CONTENT-05", "WORLDCHAIN-01"]
}
```

`opportunityId`引用05/09统一重要根链注册，`rootKind`也可为`event-chain`；子事件引用`rootChainId`。首次对掌门可参与/调查的激活时刻才进入体验密度统计，作者卡字段不形成第二份计数副本。`truthAuthoring`只进入作者工具与规则编译，不进入产品UI/在线AI请求。`scheme`可表达有意安排与传承交接；算计统计读取明确`manipulationTag`，不能看见有schemeId就算阴谋。

## 4. 内容层与运行层怎样分工

1. 作者写真相卡、机制、线索与允许结果，附范围和验收。
2. 结构验证检查ID/引用/枚举/单位；因果审阅检查动机、成本、知情与可达性。
3. 内容编译为版本化定义。生成事件实例时固定参与者、既定机制与随机状态，保存之后才对玩家显现。
4. 规则引擎按世界行动推进事实、消息、危机和结算；允许因真实行动出现非预设组合，但不能违反规则。
5. 玩家获知投影显示合法线索；确定模板或可选AI表达其授权内容。
6. 验收操作证明至少一条正常路线和必要失败/反制路线，记录存档与真实画面。

作者工具可以用AI提出内容草稿；未经过审阅的草稿不是正式世界。A2运行AI无写入事实权限；未来A3高层提案也必须受合法命令约束，不能直接生成作者真相卡并即时上线。

作者修改尚未激活的新内容可使用新定义版本；已激活链的真相、身份和既定结果不被更新偷偷改掉。漏洞修复需显式迁移，保留原值与调整原因，不把修复伪装成世界反转。

## 5. 贯通情景：暴雨、药商与失联药师

本节为新设计示例，不是参考小说/游戏的剧情复刻，不替代《余烬立山》可靠主线。具体人物、概率、时长和货量可调。

### 5.1 世界先有自己的事情

持续降雨使低洼药田积水、山路难行；掌门如果修了排水或留有库存，损失更小。陆知微为寻药与救治某山民提出自愿出行，说明计划与已知风险；她可以改期、换路或拒绝掌门另一个差事。另一个药商也受补给断路影响，价格和采购目标来自真实账本。

### 5.2 利益与信息分层

药商宣称旧洞天内有足够药材，这部分可能真实，但隐瞒开门要消耗封印、附近妖修守护药地的旧约，以及他打算抢先控制供应。正道执事公开保护坊市，私下可以接受药商利益；同门中也有人真实反对侵占。守地妖修可以愿意交换药材，只拒绝毁约，不因妖道标签自动敌对。

陈述保存来源与送达时刻。玩家可问商队是否亲见、查旧采药图、观察水位/阵纹、寻找守地人或请人卜算。每种方法提供有限线索并耗实际活动时间，NPC也会调查和据其相信的消息行动。

### 5.3 险境真实推进

陆知微若到场触动封印或遭人阻路，可尝试退避、求助、隐匿或谈判；她不会静候掌门按“救援”。口信有传播距离与迟延，通讯失效可以有真实环境原因。危机保存地点、已消耗资源、阶段与伤势；未获知时UI仅显示未按约回报或最后消息。

掌门接到线索后可卜算大致方向、查行迹、亲自赶路、邀请愿意同行的人，或与守地修士谈判。暴雨、路线与留守缺口都有成本；不能点击她的头像获得实时坐标。到场后通过实际斗法、破阵、急救、撤离或合作改变危机。

### 5.4 结果不是一种数值

救出她可能改善关系，但她未必认同掌门杀死守地妖修；若掌门揭露药商，坊市不同人物反应各异。若掌门暗中篡改机关谋害她，需要真实材料/布置/触发并承担暴露可能，不能远程修改生命值。她和第三方有识破、绕行或反制机会。

若错过生机窗口，她可以真正死亡。遗物仍在实际地点/持有人处，门人记忆、已借装备、救治未完成的山民和公库约定均有后果。主线证据有替代路径，但世界不重生一个同名药师消除损失。

若事情平安解决，世界也应继续：水退、商路恢复、药田重种、互相感谢或拒绝合作。不能总在下一段立即升级成更大的黑手；不含算计的对应版本同样必须有完整日常价值。

## 6. 母子篇内容的最低要求

用户给出的高阶抽取创意按09扩展。它可以作为长期暗线，但首轮内容必须避免以下捷径：

- “天下无敌”是某人宣传的claim或人物评价，不能写成无约束世界事实。
- 母篇持有者、来源关系、可抽取范围、跨境触发、距离/媒介和成本在激活时确定。
- 资质、修为、知识、人格与特质分开；不能把整个角色复制给施术者。“吸走特质”仅针对明确可抽取的修行特性，不删除姓名、志向、全部记忆或先天人格。
- 效果有过程：异常→可查证线索→抽取危机→反制/逃离或损失/死亡。强者可受封印、媒介、反噬或地理限制，不在任意时间吸尽所有子篇修士。
- 至少两种不同机制的生机：例如事前校勘转修/断媒介，事中封阵保护/求助守护者；只是两个同义按钮不算两条路线。
- 生机不是隐藏保底。可付出部分修为、稀有材料、债务或放弃宝物保命；若连续错过、冒险执迷或反制失败，NPC仍可能死亡。
- 被夺修为/资质/可抽特性、施术者实际吸收、逸散及反噬有唯一可追踪结算；不能每次刷页面再扣一次。
- 主角的默认恢复边界与NPC死亡分开。首轮炼气/筑基采用可玩缩尺链；金丹/元婴完整境界、高阶母篇来敌属于L-01长期内容，不能借本例擅自宣布全部开放。

## 7. 跨模型开发规则

- 开始任务先读AGENTS、基准/决策/状态/运行时，再读任务相关08–12；个人记忆不能覆盖文件版本。
- 任何新增“世界活起来”的功能必须形成至少一个持续事实和一个真实行动后果，不能只加风雨粒子、NPC闲话和剧情名称。
- 日程、天气、谋局、战斗、危机、生产、行程共用worldTick。画面与在线调用不能推进或冻结其中一个子系统。
- 不将40%落在谎言骰子或必死率；不强补目标把善意角色突然改恶人；稀世暗线检查与阴谋密度检查分开。
- 不用阵营标签生成善恶，不用形象/肖像揭露隐藏动机；行为、证据、传播和他人判断逐步形成公认评价。
- 只控制掌门。NPC可接受、拒绝、自救、求救、识破、误判与死亡；玩家通过实际世界机制介入。
- 无消息≠已确认死亡，收到求救≠仍在该坐标，卜算≠读全真相。所有信息带来源、时刻与可知范围。
- 新致死规则先有作者卡、时间图和复测，再进入正式危险；旧档默认保护/明确选择按10执行，不改既有过去结果。
- 保存不洗命；查看不改命；关闭/后台/暂停不推进；只有继续模拟或有效命令改变未来。
- API为可选表现层；没有网络或密钥仍能完整开局、经营、调查、救援、斗法和收束主线。
- 分模块agent共享实体/枚举/单位，主agent负责因果和集成审阅。不能各写一套Life/Death/Claim/RNG/时钟。

## 8. 内容与世界验收

| ID | 可观察验收 |
| --- | --- |
| CONTENT-01 | 每项稀世内容有真相卡和至少一条实际暗线，含非骗局样本；普通可靠获取仍可用 |
| CONTENT-02 | 人物有资源、所知和底线；同道途出现可信善意与逐利者，不自动全员背刺 |
| CONTENT-03 | 至少两条独立线索/查验入口；假信息来自可追踪陈述和利益，查看不能改变真假 |
| CONTENT-04 | 作者卡能给出定位→出行→斗法/救治预算与迟到结局，真实操作证明可达而非纸上窗口 |
| CONTENT-05 | 知情权限分别核对UI、日志、人物详情、地图、特效、声效和AI包；未知幕后不得泄露 |
| CONTENT-06 | 激活后固定身份/机制，内容更新、刷新、读档不重抽母篇/收益/死亡结果 |
| CONTENT-07 | 拒绝、信任、调查、NPC自救、玩家救援、玩家陷阱与迟到均走合法机制，失败后世界有持续结果 |
| WORLDCHAIN-01 | 第5节暴雨→供给/出行→真假线索→定位→实际干预→关系/库存/生态后果，全程无AI可完成 |
| WORLDCHAIN-02 | 同一情景分别救出/被NPC自救/迟到死亡/陷阱被识破；没有改NPC身体或全知坐标按钮 |
| WORLDCHAIN-03 | 在离屏与近景、1x/加速、暂停/后台、读档各路径中事实守恒；切镜头不改变生死结算 |
| WORLDCHAIN-04 | 母子篇缩尺机制至少验证一次提前破局、一次过程反制、一次真实损失与NPC死亡；高阶长期范围标明 |
| WORLDCHAIN-05 | 首次玩家能分别描述“已知事实、某人的说法、自己的猜测”，知道当前应查哪里和怎样找人 |
| WORLDCHAIN-06 | 完成危机后留有生产/交往/恢复期；真人未被全员疑似恶人和密集危机迫使持续暂停 |

本轮仅检查设计一致性与文档，不执行这些游戏目标验收。实际代码、设备、操作录像与真人反馈必须进入STATUS及相应交付记录，不能因作者卡写完就标verified。
