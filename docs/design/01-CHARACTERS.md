# 01 · 人物、生活与自主社会

设计基线：DB-2026-10-05 v1.1。状态：目标规格，不代表当前代码已完成。
本文件与 [00-BASELINE.md](00-BASELINE.md) 共同约束后续设计、代码、内容及验收。
首次数值、人口与时长都是可调设计起点；v1.1按最新U-13允许NPC永久死亡，过程与干预见[10](10-CRISES-RESCUE-DEATH.md)。掌门硬核删档/继承仍后置。

## 1. 人物定位与玩家权限

人物是具有持久身份、身体、经历、关系和个人目标的行动者；加入宗门只改变组织身份。
玩家仅直接控制掌门，NPC 不提供“接管身体”或强制派工入口。
玩家可以提供设施、资源、课程、报酬、制度、差事及任职邀请；NPC 自主接受或拒绝。
工作、学法、服丹、拜师、任职、归峰、同行均经过条件检查与本人意愿检查。
任职表示承担约定责任，不能把性格改写成忠诚或把全部个人时间改为工作。
危机时玩家可以号召救援、说明风险、开放避难与撤退路线，不能强制胆怯者迎敌。
NPC 自愿参加队伍后，可按事先同意的队伍约定响应集结、撤退和战术号召；仍由 NPC 执行。
拒绝不触发自动惩罚；制度后果必须有预告、实际行为、证据和处置过程。
不允许“点一次任命直接改 officeId”“点击推荐功法直接让 NPC 学会”等绕过意愿的捷径。

主角确认设定：修行世家遗孤、炼气六层、天资卓绝但不是世界天赋上限。
父母以生命掩护逃生，带走部分家传；开局伤势可恢复，不永久损伤资质。
天才弟子可以超过掌门；师恩、认同、共同经历与制度维持权威，不能用境界强锁忠诚。
第一篇章复仇必须真正收束；人物支持、反对或守山的选择参考 [04-WORLD-STORY.md](04-WORLD-STORY.md)。

## 2. 同一身份贯穿生活、场景和战斗

人物注册表是唯一身份源；宗门成员、访客、同行者、战斗实体均引用同一个 personId。
ID 不使用姓名、肖像索引或数组下标；姓名允许重名，ID 永不复用。
掌门固定 `person:master`；首名普通人物示例 `person:npc:001`，实际分配器持久保存计数。
人物离宗、远行、战败、失踪或死亡不删除注册记录；改变位置/存活状态并保留已有事实、物品归属、关系与死亡记录。
返回场景、重载存档和从访客变为门人，都不得重掷外观、经历或关系。
角色生成使用存档内专属随机流；重新打开详情页不消耗生成随机流。
剧情关键角色使用作者配置；随机人物使用同一模型，并记录出生背景与生成来源。

| 字段组 | 目标字段 | 实现约束 |
| --- | --- | --- |
| 身份 | `id, name, aliases, backgroundId, generationSeed` | 种子及来源随存档，别名不替换身份 |
| 外观 | `appearance.recipeId, body, face, hair, palette, outfit` | 肖像、场景、战斗从同一配方派生 |
| 身体 | `lifeStatus, health, injuries, needs, ageStage` | 存活alive/dead是真实事实；bodyState由健康/伤势推导，不另写第二份生命值 |
| 修行 | `cultivation.realmId, layer, progress, aptitudes, affinities` | 境界与层数分字段；规则见武学文档 |
| 理解 | `comprehension, knowledge, learning[artId].understanding, learning[artId].mastery` | 理解能力、已获得知识与实操熟练度分离 |
| 技艺 | `skills.{herbalism, crafting, medicine, arrays, ...}` | 已习经验与专长，不由资质直接代替 |
| 人格 | `traits, values, temperament` | 支持稳定倾向和情境变化，禁止单一善恶人格 |
| 目标 | `aspirations, goals, lifePlan, commitments, preferences` | 志向、可执行阶段计划、近期承诺和喜好分开；谋局引用schemeId |
| 社会 | `memberships, offices, relationships, memories` | 所属、任职、对人关系均有持久引用 |
| 位置 | `location.sceneId, position, facing` | 同一人物不能同时出现在宗门与山外 |
| 行动 | `activity, pendingIntent, suspendedActivities` | 活动有真实目标与生命周期 |
| 知情 | `knownFacts, observations, disclosedFacts, knownClaimIds, beliefs` | 已知陈述可为谎言；UI不把相信等同世界真相 |

人物体型与门窗、座椅、道路保持人类尺度，不能通过永久放大人物解决远景辨识。
视觉配方包含稳定主色、发型、身体轮廓、佩戴位置和肖像特征；至少三项组合有可见差异。
装备改变服饰与法器外观时保持人物身份特征；转换战斗视图不能生成陌生面孔。
缺少对应资产使用同风格明确回退，不随机换肖像；资产规范见 [03-SPATIAL-ART.md](03-SPATIAL-ART.md)。

## 3. 资质、悟性、技能、志向与性格

资质描述修行吸收与适应能力；灵根/适性描述对路线和材料环境的契合。
悟性描述理解、归纳、迁移知识的能力；学会一门法仍需要来源、时间和实际练习。
技艺描述已获得的实操经验；普通资质者能成长为可靠药师、执事、阵匠。
志向描述本人长期希望达到的生活与修行目标，可以有主目标和次目标。
经历提供机会、限制、知识、创伤或恩义；不能以“出身贫寒”永久锁死能力。
性格维度沿用仁心、野心、守信、自律、好奇；增加倾向前先证明其行为差异。
首版倾向以 0–100 表示，使用自然语言描述；不向玩家堆五条精确数值条。
勇怯、风险判断可由性格、伤势、情报和经历共同产生，不用“野心高必莽撞”代替。
高仁心者也会拒绝不合理牺牲；低仁心者不必按周期违法。
主角“天资卓绝”使用高位档，生成器保留稀有更高资质；不写为数值最大值。
旧 `talent` 迁移为资质基线；悟性及技能优先从既有学习、工作经历映射，缺失值用稳定迁移规则。
迁移不重新随机生成已有门人，不让旧档普通弟子被集体改成绝世天才。

## 4. 日程、需要与可解释决策

核心需要：饱食、精力、身体安全、休养、归属；修行愿望与职责进入动机层。
饮食、睡眠、疗伤、社交、工作、授业、研习、修炼各消耗时间和空间容量。
首版不模拟逐次如厕、复杂器官或逐口吃饭；有床位、食物、治疗机会就有可观察结果。
日程是偏好时间段与已同意的约定，不是玩家强制按小时控制 NPC 的表格。
长时课程与队伍出发可形成预约；预约前检查交通、准备时间和本人意愿。
候选行为先做硬条件过滤，再计算收益、需要、志向、关系、责任、风险与转换成本。
硬条件包括目标存在、资源可接触、已知来源、路径可达、工位可用和身体许可。
决策输入、结果及拒绝原因保留调试记录；对玩家只展示可公开的主要理由、本人解释或已证实行为。本人解释可能隐瞒动机，要标为解释，不能由UI直接揭露幕后理由。
随机扰动仅打破相近候选；同一邀请与同一条件下不能靠反复点击重掷接受结果。
状态改变才重新评估接受意愿，例如准备充分、关系改善、伤势恢复或新情报出现。

防止反复改意的起点（可调）：
- 一般活动承诺至少 180 ticks；工作周期、授课或用餐的完成优先级更高。
- 无紧急情况时，新候选效用至少高 15/100，才提前切换既定活动。
- 同目标失败采用 150、300、600 ticks 退避，条件变化可提前触发重评估。
- 需要低于 20/100 可进入紧急补给；恢复到 40/100 后退出，避免阈值附近抖动。
- 所有持久时刻用整数 `worldTick`（字段 `*Tick`），时长用 `durationTicks`；1 tick 为 100ms 模拟时间。
- `ticksPerDay` 是可调配置，首轮按现有 120 秒/日兼容；上述值随节奏测试一起调整。
- 世界时间显示、游戏日相位迁移、暂停与快进统一见 [05-RUNTIME-CONTRACTS.md](05-RUNTIME-CONTRACTS.md)。

判断“不能做”和“不愿做”必须分离：缺材料属于前者，不认可复仇属于后者。
界面示例：“想做炼丹差事，但丹炉有人使用，准备先整理药材。”
界面示例：“不愿同行：伤势尚重，也担心山院无人照料。”
能力、机会和意愿是独立检查结果；不能使用一个灰色按钮掩盖三类原因。
供给危机不能自动把全部 NPC 改成生产机器人；愿意救急的人响应，掌门保留亲自采集与交易出路。

## 5. 活动生命周期、占位与中断

统一生命周期：`proposed → reserving → navigating → preparing → executing → settling → completed`。
任意适用阶段可进入`waiting`，保存待恢复阶段和阻塞原因；可进入`interrupted / cancelled / failed`。中断保存可恢复进度，取消/失败为终态，均须释放或明确延期占位；恢复要重验前置。
`proposed`：形成本人意图、原因、目标和完成条件，不能先发生产奖励。
`reserving`：申请独立工位或床位，获得 `slotId + reservationId`；申请失败进入等待或替代选择。
`navigating`：沿可达路线前往目标；显示“前往药田”，不可显示“正在浇水”。
`preparing`：进入工位、摆放物件、取得材料，核验活动前置未被他人消费。
`executing`：动画、道具与声音由当前活动派生，进度只在实际工位满足条件时推进。
`settling`：产物、消耗、技能、记忆和关系变化由一个幂等结果事务结算。
`completed`：结果已结算的终态；释放工位和临时物件是清理动作，不是另一套活动阶段。下一有效周期创建新活动/批次。
任务目标至少保存 `sceneId, targetId, slotId`，不把建筑名字或屏幕坐标当身份。
建筑入口是通道，工位是执行位置；师生、病人、工匠不得全挤在门口执行。
多人协作使用分工位与参与者集合；一个丹炉不能被两个互不知情的活动同时消耗材料。
预约占位有宽限与超时，避免路上阻塞永远锁住工位；物理到达后改为使用占位。
建筑移动、拆除、关闭或几何版本变化后，活动验证目标并重规划；已完成进度按活动规则保留。
场景之间使用入口与出口转换，不能跨场景瞬移到工位；远行期间地方场景不绘制留影。

每人一个正在执行活动、最多三个短期意图（可调），长期志向不进入无限日常队列。
受伤、火灾、直接敌袭、明确撤退等危机可以打断活动，记录暂停原因与可恢复进度。
安全避让是 NPC 的生存判断；掌门号召不能直接覆盖 NPC 对风险与义务的判断。
中断时释放临时工位；特定闭关或施工可保留明确的设施占用，但必须有可见期限。
危机结束后先检查身体、材料、目标和承诺，再恢复；原目标失效则说明原因并改选。
读档重建活动占位并检测冲突；确定性解决重复申请，不能重复结算奖励。
活动真实状态同时驱动人物标签、动画、面板与日志，禁止渲染层自行编造“忙碌”。

## 6. 关系、记忆、知情与侠义

关系有方向：A 信任 B 不代表 B 信任 A；不同人可以对同一行为有不同评价。
关系轴首版沿用信任、敬重、亲近、冲突（0–100，可调）；师徒、亲属、恩人是关系类型。
忠诚是个人价值、信任、认同、待遇与经历的综合倾向，不是永久锁定成员的单一条。
门人超过掌门境界不自动背叛；共同经历与师恩也不保证永远认同掌门。
记忆保存事件 ID、时间、参与者、结果、本人解读、重要性与证据来源。
共同劳作、救治、授业、守约、危险中相助都能形成记忆；赠礼不覆盖严重背叛。
普通日常记忆允许摘要归档；救命、师承、离宗、背叛与关键承诺不能被固定长度队列挤掉。
关键记忆与关系结果已结算标记分开；整理摘要不能再次增加好感。
关系变化包含原因和上下文，避免一条全局“成功 +5、失败 -5”适用于所有人。

世界事实、人物观察、传闻、怀疑、确认事实分层保存。
秘密行为先有动机、机会和实际行动，再可能留下证据；不能固定计时随机生成作恶。
玩家知道的事实取决于掌门目击、证言、物证、调查或他人自愿披露。
未发现的私学、取物或隐瞒，不能在人物活动原因、学法列表、关系日志中泄漏。
隐私投影可以显示“独处研习，暂不愿详谈”，但不能用假行为替代真实位置。
证据支持具体指控；怀疑不得自动变成事实，处分后记忆保留争议与当事人解释。
护院执事提升调查机会，不能拥有跨场景读心能力。

独立保存三类评价：江湖侠义/行事名声、势力立场、个人关系。
侠义评价记录行为类别、手段、对象与已知传播范围，不能将复仇一律判恶。
敌对势力可以因利益仇视行侠者；受惠者可能信任他而江湖尚不知情。
救治、守约、背叛、劫掠、滥杀等名声由事实及传播产生；不靠送礼洗净事件记录。
规则与事件作者规范见 [04-WORLD-STORY.md](04-WORLD-STORY.md)。

## 7. 组织、师承与小而精路线

角色状态区分访客、暂居、追随者、正式门人、离宗者与外部修士，允许关系持续存在。
加入需要共同条件与本人同意；离宗不删除个人传承、经历和身份。
首版执事限庶务、传功、护院，专业人才可继续承担丹师、药师等具体职责。
任职检查能力、在场、可用时间、本人认同与已担职责；邀请反馈记录双方约定。
师徒成立需双方意愿和实际授受机会；建立师徒关系不自动分享全部知识。
弟子归峰根据适性、志向、导师、关系和条件选择；掌门只提供组织选择与主持邀请。
山院、立派、分峰是组织能力发展，人数仅为可调参考，不用人口单项阻断全部剧情。
小而精宗门可以凭专业人才、稳定产能、传承深度和可信人脉推进第一篇章。
少人路线承担出山后人手不足的取舍；多人路线承担住居、供给、教学和协调成本。
多人管理通过职责与空间容量减少重复邀请，不能用批量强制派工抵消规模成本。

## 8. 成长、失败与死亡边界

成长来源分修为、理解、技艺与阅历；做工增长对应技艺，救人不直接兑换所有武学经验。
学习机会、理解程度、练习熟练度和教学能力分别保存；详见 [02-EQUIPMENT-ARTS.md](02-EQUIPMENT-ARTS.md)。
突破、认主等重大风险应有可获取的预兆、调查与反制机会，明确风险类别而非直接剧透幕后身份；特定暗线可造成修为/资质损失或NPC死亡，不把每次普通失败都做成毁人。
一般战败可受伤、撤离、损失、俘虏；进入真正致死危险后按10推进濒危、自救/求救、干预与死亡，不能全员自动脱险。
建议首版：掌门败亡进入明确失败/读档流程，不自动换人继承操控权。
NPC永久死亡已纳入v1.1；日常不随机秒杀。可救危机须提供实际发现/到达预算，可能错过、失败或无人救援；远方未知人物可死亡而掌门尚不知情。健康→濒危→死亡的因果不能只在结算弹窗里补写。
已确认剧情中的父母死亡保留，不因一般失败建议改变主角前史。
婚恋、婚育、寿元终结、后代继承、大规模人口更替后置；保留扩展位置，不承诺本版玩法。
暂不建立全身器官模型、心理疾病诊断或复杂政治派系模拟。

身死后结束身体活动、释放/转移预约、清理队伍与职责占用，遗体/物品保留实际位置及归属，死亡记录与lifeStatus一次提交。亲友在获知后形成各自记忆和反应，未知者不能从全知关系面板直接悼念；课程、债务和师承留下持续后果。详见10，不能简单删成员来完成死亡。

## 9. 选择与人物可读性

人物栏使用真实肖像、姓名、当前短活动、紧急状态和定位入口。
场景单击或单次触摸优先选择人物；地面移动命令针对掌门，需要明确操作语义。
触控命中区至少 44 × 44 屏幕像素，不随世界缩放缩到不可点击。
多人重叠弹出附近人物选择；命中区重叠不能永远只选到同一数组首项。
建筑遮挡下可见人物仍可选中；屋顶淡出、轮廓与室内呈现使用统一遮挡规则。
悬停/选中显示“陆知微 · 浇灌药田”；普通状态只保留必要标识，避免全屏姓名条。
对当前可观察人物可定位并调整镜头；山外仅显示掌门已知最后位置/消息时刻/不确定范围。未知去向、失踪或死亡不能经人物栏泄漏实时场景，查找和卜算见09/10。
不同动作使用方向、姿态、随身工具和目标物反馈；静止时也能区分研读、睡眠和疗伤。
远景使用活动摘要与人物定位入口；近景保证可辨识人体与门窗尺度。
详情依次显示当前行为和原因、身体、志向、传承装备、关系经历；秘密内容按知情过滤。
具体镜头、绘制层及点击约定见 [03-SPATIAL-ART.md](03-SPATIAL-ART.md)。
