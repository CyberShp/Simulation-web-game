## 2. 空间、来源和勘察

GC03 锚点为 `(44,-46)`，一级入口 `(47,-39.4)`。由根代理负责的 `ea-north-meditation-geometry.mjs` 导出 `NORTH_MEDITATION_VERSION='north-meditation-1'`、道路、可走面、实体障碍及建位；北界 -52。`enableNorthMeditation` 要求已开藏经阁北台，登记 `s.spatial.northMeditation={version,openedAtTick}`，只开通道路。

四蒲团（世界米制）：`(45.15,-42.02489626556017)`、`(46.5875,-42.02489626556017)`、`(48.075,-42.02489626556017)`、`(49.525,-42.02489626556017)`。维护位：`(45.1875,-44.18257261410788)`、`(49.5,-44.18257261410788)`。最终脚圈、固体与通路以同源 geometry / survey 校验为准。

天然地点定名 **云岫北台浅脉眼**，稳定来源 ID `spirit-source:yunxiu:north-terrace`。作者事实是台地下方一处低阶通用灵气支脉，影响范围限定 GC03 这块台地；天然积蓄、脉势及流量独立于聚灵台。已建石钵是引流器，四蒲团共用这一源头。画面目前表现台地石纹与人工器座；勘察定位台地下方脉眼，不把器座解释为天然脉体，也不赋予地火、寒潭或稀有道痕属性。

公开 `surveyMeditationSource()` 安排掌门走到西维护脚点，以相同源点作为未建时的勘察站位。实际到位贡献满 80 世界步后，取得一次勘明事实，披露可用储量、脉势和引流条件。行路不计勘察进度；忙碌、源点未开放或不可达时原子拒绝。复测沿同一站位和工时更新测量事实，不重置自然值。暂停及存读保留行路、进度和人物身份。取消保留已经发生的源状态与观测历史。

自然来源在内容定义中稳定存在，未启用档不新增字段。首次正式勘察命令建立该地点的可选运行记录；其初始满蓄表示此前无人抽取的自然积蓄，不能转为库存、货物或通用货币。勘察成功才允许新 GC03 正式施工。拆台、重建、开关道路和重复勘察均保留同一来源记录。

## 3. T-24 有限供能与恢复参数

内部以整数“毫脉息”保存，1000 毫脉息为 1 脉息；此为地点计量，不扩公共资源表。脉势以 0–10000 基点保存。

| 参数 | 初值／规则 |
| --- | --- |
| 天然容量 | 1,200,000 毫脉息；初始满蓄，升级不改变上限 |
| 脉势 | 初始 10000，最低 2500；下降表示源头衰弱 |
| 自然恢复 | 每世界步 `floor(200×脉势/10000)` 毫脉息，即健康时每模拟秒 2 脉息；只登记实际入蓄增量 |
| 当期抽取上限 | 每世界秒 `floor(4000×脉势/10000)` 毫脉息；四席共享，另受现存储量和维护余量约束 |
| 一席完整需求 | 每实际修行世界秒 1000 毫脉息的有效供给；未到位、未预约、无主修、已满当前境界修为或活动被占用时不请求 |
| 三级引流效率 | 65% / 80% / 90%；原始抽取量乘效率得到可分配量，损耗确实离开源储量 |
| 三级完整供能收益 | 相对该人物普通基础修行速率乘 1.6 / 1.9 / 2.2；实际供给不足时，倍率为 `1 + 等级额外倍率×实得/1000` |
| 过用衰退 | 当期抽取后低于 25% 蓄量，按本秒抽取超过本秒自然实际恢复的净额，每 1 脉息下降 10 脉势基点；整数向上取整，最低 2500 |
| 脉势恢复 | 已连续 600 世界步没有抽取，且储量至少恢复至 50%，此后每世界步恢复 1 基点至 10000；现场检修不直接修复脉势 |

同一脉眼的自然容量、恢复基数和最大原始流量不会随建筑等级、人数或镜头变化。一级单人完整引流约需 1.539 原始脉息／秒，低于健康恢复 2；四席持续满负荷最多共取 4 原始脉息／秒，健康一级总有效供给只有 2.6，须分配给四人。升级提高引流效率与维护持续量，仍受同一源头的当前流量和储量限制。

断供或检修时保留有实际空蒲团的普通基础修行：掌门基础 2.2、NPC 基础 0.9，继续乘既有资质、主辅法门、口粮和个人效果，不得到新聚灵加成。已有主殿基础修行照常可用。关闭或损坏的建筑仍按原场所规则停止接待，不能把“断供可基础修行”当作忽略施工、障碍或身体预约。

### 同秒分配和一次结算

纯 `cultivationRate`、场所报价和 UI 不抽能。仅掌门/NPC 原执行分支在 `prepareFacilityActivity` 确认真正到席后，向本世界秒批次登记一次请求；原 XP 增量改为等待批次合并。共同批次在该次 `advanceWorldSecond` 内、所有人物执行之后结算，且在外层世界步结束前完成。

结算先复核人物、buildingInstanceId、slotId、预约与脚点，汇总有效请求。原始抽取量取“当前储量、当前流量、总有效需求折算原始量、维护余量”的最小值；总有效量均分，整数余数按稳定槽位顺序与世界秒轮转分配。人物数组遍历先后不决定谁获得全部供能。随后各人的普通 XP 与已分配额外 XP 一次加入，沿既有境界上限截断；原疲劳、知识增长和自主突破意图继续各结算一次。

持久记录最近脉冲世界步、每人实得、总抽取、损耗及累积账；同一人同一世界步再次提交不能重复抽取或增加 XP。批次是已有世界步内的汇总阶段，不成为第二模拟循环。读档、纯视图、缩放、关闭和暂停均不新建批次。逐步与批量推进须结果相同。

## 4. 维护、现场材料与升级

新 GC03 初建完成时引流设施处于完好校准状态，维护余量为 2,400,000 原始毫脉息；二、三级上限为 3,600,000 / 4,800,000。实际抽取同时扣同量维护余量。它表示引流槽、器座和护栏的可用工作量，与源头的天然储量分账；基础吐纳不耗引流维护量。

`startMeditationMaintenance(buildingId)` 建立现场检修工单。材料为每级 2 木、1 石；工时为一级 80、二级 100、三级 120 个实际贡献世界步。材料来自完工时创建的现场货位 `stockpile:<instanceId>`（容量 80，原七资源零值，入口绑定 GC03，必须通过现有运输实际送达）。工单沿既有投入预约与取消机制：到位开始检修才消耗预留材料；开始前取消退回预约，开始后取消保留已耗量与工时历史，维护余量仍为取消前的实际余量。重新开单另行预约材料并从零工时开始，取消本身不补足维护。

两维护位最多两人实际参与；掌门通过正式工单到位，门人只可按现行 `inviteWork` 意愿和承诺接工。每人每世界步最多贡献一次。检修期间引流暂停，已坐蒲团者可做基础吐纳；工单完成后一次恢复当级维护上限。材料、维修或升阶不会回填天然储量和脉势。

本次新 GC03 以专用版本标记接入现场维护；通用日结跳过其旧 `jade:2×level` 扣费与自动修复，仅保留公共口粮和已存在天气／结构规则。旧无标记 meditation 实例继续原规则。维护单与修行预约未妥善结束时，按现有身体/工位边界拒绝改建或拆除。

升级沿原材料价格和实际运料施工，同时新增以下来源门槛：已完成勘察；最近 1200 世界步内有一次现场复测；当前天然蓄量不少于 50%；升二级脉势至少 7000，升三级至少 8500；现设施维护余量不少于本级上限的 50%；本楼无活动修行或检修预约。确认时复验条件。施工不抽能，完成只改变引流效率、实际占地与维护上限，不刷新源状态。维护余量按原剩余比例继承到新上限，不能以升级获得完整检修。

本期各级仍保留四个稳定蒲团及两个维护位；更高引流效率体现等级改善。新增练位或第二支点必须另有实际来源、空间和阶段画面，此处没有提前登记额外容量。

## 6. 版本、存读和失败边界

可选源账版本建议 `spirit-sources:yunxiu:v1`；新建筑 `meditationSupplyVersion` 与建成事实共同绑定 `sourceId`。旧档缺源账不补字段、不重算旧修行与维护；只有正式勘察建立源账，只有本批新 GC03 完工时加建筑标记。旧 meditation 迁位保留旧行为；启用来源不把旧实例静默转为新设施。

勘察和维护工单保留人物、目标站位、真实路径、预约、材料投入、进度与终态事实。最新修行脉冲保存实际请求者与分配，拒绝重复人/槽、跨源引用、超流量、负储量、未来世界步与额外结算。未知版本、删标记留事实、删货位、错误入口绑定、篡改累计量或悬空身体均拒载并保留输入原文。拆除建筑保留天然源与终态维护/勘察历史。读取不追算离线恢复，也不把暂停误计入脉势休养。
