# 10 · 危机进程、救援与死亡

设计编号：DB-2026-10-05 v1.1。状态：目标规格，尚未实现。

本文件依据2026-10-05用户最新要求，取代v1.0“NPC永久死亡后置”的边界：**NPC外出可永久身死；死亡有可追踪过程，玩家只能操控掌门，通过获得消息、定位与实际行动干预。**主角永久死亡、世代继承与硬删档未获用户授权，仍按失败、读档与恢复处理。

依赖：[人物](01-CHARACTERS.md)、[世界与剧情](04-WORLD-STORY.md)、[运行时契约](05-RUNTIME-CONTRACTS.md)、[活世界](08-LIVING-WORLD.md)、[谋局与机缘](09-INTRIGUE-OPPORTUNITIES.md)、[内容创作](12-CONTENT-AUTHORING.md)。不能建立第二套死亡或战斗事实。

## 1. 设计承诺与权限

1. NPC是世界中的独立生命，有判断、资源、亲友与自救能力；不会一直等掌门来决定生死。
2. 风险从实际行为、空间、敌意、环境与已存在的谋局产生，不能按每天一个概率直接删除门人。
3. 生死可以被改变，但不能由“营救成功”或“让他死”两个远程按钮改写。
4. 玩家可以亲自探查、赶路、参战、疗伤、破阵、接应、谈判，也可以布设玄幻陷阱或误导行动。每种行动有前置、时间、代价、可失败结果与责任痕迹。
5. 玩家不能接管NPC身体；邀请援手、托人调查、购买定位服务是对独立行动者的请求，不保证被接受。
6. 世界不是围绕掌门等待的舞台。远方无关人物可以未被玩家发现便死亡；已知危险也可能因为判断错误、距离过远、资源不足或犹豫而救不回来。
7. 作者必须提供可解释因果与相称的信息渠道，不能把“尔虞我诈”用作无迹可寻、任意秒杀或自动倒读档的理由。

玩家了解规则不等于角色获得位置、事实或敌方计划。调试器能观察全部阶段，正式UI只能呈现角色已知部分。

## 2. 危险进程与身体状态分别记录

危险描述“发生了什么、接下来可能怎样”，身体描述“这个人现在能做什么”。两者不能共用一个血条或阶段字段。

| 对象 | 字段与取值 | 含义 |
| --- | --- | --- |
| 人物生命 | `lifeStatus: alive / dead` | 是否已经结算不可逆死亡；失踪、被俘、倒地均不等于dead |
| 身体能力投影 | `bodyState: fit / impaired / incapacitated / dying` | 存活者从伤势、意识与治疗状态派生；死者不再提供活人身体能力投影，不用作第二份可独立修改的身体事实 |
| 危机实例 | `stage: forming / exposed / engaged / escalating / critical / resolved` | 威胁演变；不等于每名参与者都处于同一身体状态 |
| 危机结局 | `outcome`及逐人结果 | 解危、逃离、受困、被俘、失踪、伤残或死亡等实际结果 |
| 战斗会话 | `phase: preparing / active / settling / ended` | 一场实际斗法的生命周期，与危机及人物引用关联 |
| 玩家知识 | 调查、消息与观察记录 | “可能遇险”“最后露面地点”“已证实身亡”；不写入真实危机阶段 |

生命事实与死亡记录在同一事务内提交；不能先发丧讯，再因血条未清空继续安排该人生产。死亡后不删除人物注册表，不复用ID。

`dying`表示正在经历致命伤势或持续消耗，保存来源、剩余演变条件与可用稳定措施。敌人完好地被困在即将崩塌的洞天也可能处于`critical`，但其身体仍为`fit`。已经重伤的人抵达安全医舍后可能危机已`resolved`，身体仍为`impaired`。

“没有消息”不能自动转成dead；“身体无法行动”不能自动转成不可救。失踪是位置/知情状态，被俘是容纳/行动限制，均与lifeStatus分开。

## 3. 从风险到结局

| 危机阶段 | 可能发生的实际变化 | NPC与玩家可能的干预 |
| --- | --- | --- |
| forming | 行路路线暴露、禁地条件变化、敌方设伏、阵势开始失衡 | 更改计划、备药、打探、拆除源头、提前布防 |
| exposed | 人已进入危险区域，出口或补给受影响，出现征兆 | 识破、撤离、求助、发信、留下路标、寻找替代通道 |
| engaged | 斗法、追逐、禁制消耗或事故实际开始 | 战斗、谈判、断后、救治、破阵、接应 |
| escalating | 资源减少、伤势加重、增援将至或退路恶化 | 取舍目标、放弃财物、分散逃离、稳住伤势、改选出口 |
| critical | 存在明确致命演变条件；不等于终局已经锁定 | 有时可稳伤、破局、救出或自救；也可能已来不及 |
| resolved | 威胁停止或本次事件结束，逐人后果结算 | 后续疗伤、追索、善后、问责或悼念 |

阶段可以跳过不适用环节、反复升降或分支，但必须保留原因。例如遭遇伏击可以从forming进入engaged，仍有形成过程、攻击前置与实际行动；不能凭“跳阶段”在一个读UI请求里判死。

一次危机可含多名参与者，各人的身体、脱困机会与结局独立。一人逃出，不代表全队危机自动解除；队伍不是共享生死的单个抽签对象。

每个阶段至少保存`stageStartedTick`、`durationTicks`、`stageProgressTicks`及演变条件。`durationTicks`表示本阶段规则时长，不是统一的“现实秒救援倒计时”。不同阶段可由耗尽灵力、完成敌方动作、禁制崩坏或抵达地点等条件结束。可逆条件解除后，按规则延缓、逆转或结束危机，不悄悄重抽命运。

生命归零、灵力耗尽、失去意识与死亡有不同语义。伤害先产生身体后果；是否致命由伤势种类、持续环境、救治与事件条件决定。敌方追击或处决必须由实际在场者执行有时间成本的动作，不能以离屏“最终伤害”瞬间补死。

前期教学事件优先采用可撤离、可稳定伤势的风险；危险探索中不保证每次都有完整的倒地缓冲。人物主动进入已明确告知不可逆后果的高危行为，可以失去最初的安全余地，但不能绕过已经设定的因果过程。

## 4. 世界战斗共用一只钟

斗法、赶路、疗伤、卜算、调查、生产、留守生活与其他地方的冲突，都消耗相同`worldTick`。tick单位及暂停规则由05规定。

- 玩家参战时，门派继续生活，远方战斗继续按规则演变；切到斗法画面不冻结整个修仙界。
- 暂停、后台、关闭和按05规定暂停的阅读操作使全世界暂停。不能让敌方继续倒数、我方治疗停止。
- 战术暂停允许排掌门计划和查看已知情况；移动、施法、换装、服药、破阵与救治必须恢复后消耗动作时间。
- 快进改变墙钟推进速度，不增加攻击次数或为离屏战斗额外判一次胜负。有关玩家已知危险的自动降速/暂停是推荐可配置辅助；未知危险不能通过辅助开关泄露秘密。
- 单个combatSession由唯一模拟写入者推进，参与者每个tick至多承担一个实际身体动作。不能同一人物既与山外敌人战斗，又在山院生产或另一处助战。
- 多场战斗并行存在于世界时钟上；玩家当前只直接操控掌门所在场次，其他战斗由各自参与者自主行动。

近景、地图图标、消息摘要是同一会话的表现。离屏时可批量推进到下一个动作/阶段边界，但行动成本、位置、资源、伤势、随机流与死亡规则保持相同；不能换成独立“胜率一抽”。进入近景时展开当前真实参与者、伤势、禁制与动作阶段，不重置敌人、回满血或重掷结果。

切镜头、查看世界地图或查阅不同战斗消息均不接管NPC、不改变模拟精度，不因摄像机本身额外推进或冻结远方。界面若按05要求暂停，须全世界一致暂停；读投影本身不驱动时钟。真实可操作近景需要掌门实际抵达该场景；远方页面只能展示已有消息/观察及其时刻，不渲染玩家未知的实时布阵或人物位置。将来若有远视法术，其施术、可见范围、持续时间与干扰另作规则，也不授予直接控制NPC的权限。

详细模拟不要求全世界所有NPC逐帧运行。仅持续存活的重大冲突/危机、已承诺行动与附近场景执行相应步骤；普通远方生活使用有限、可追踪活动。批量推进必须在消息发送、行动完成、有人到场、阶段切换与死亡等边界拆分，不能一次跨过玩家已到场的救援动作。

## 5. NPC自救、求援与反制

NPC依据已知情报、经验、价值观、责任、伤势、资源和环境决定是否冒险、撤退、求援或交换条件。判断可以失误，但不是全部人固定等救援。

| 行动 | 规则 |
| --- | --- |
| 备行与留路 | 选择补给、护具、同行、路线、返程约定；有经验者更可能留下可核对行踪 |
| 识破危险 | 检查禁制、比较来源、观察异常、试探路线；识破需能力/证据，不由“聪明”直接获得所有真相 |
| 自救撤离 | 舍弃机缘、使用有限保命物、交换利益、找掩体、改变出口或求临时同盟 |
| 稳定伤势 | 实际服药、止住灵力流失、躲避持续伤害、等待接应；延缓危险并付出真实消耗 |
| 求援 | 信物、传讯、同行托付、路人转报；通路可受距离、天气、禁制、截断与欺骗影响 |
| 保护他人 | 自愿断后、扶伤、分药；根据关系与承诺决定，不因“同门”必然赴死 |
| 识破陷阱 | 发现异象、追索材料/阵纹、绕行、拆除、诱使对方反受其害；不承诺永远识破 |

NPC求援需有实际媒介与发出时刻。消息到达前已死亡，仍可能留下迟到求救；UI说明“消息发于何时、收到于何时”，不把迟信包装成实时生命条。

保护符、替身、结契援护等保命方式只能按其明确内容使用：数量有限、效果有边界、代价有来源。不能给重要人物隐形无限免死，也不能让所有NPC拥有同样的求救道具。

## 6. 发现与定位

定位是救援链的一部分，需要掌门或受托人物的行动与世界时间。玩家不能通过人物面板直接看到未公开位置或所有危机的精确坐标。

| 渠道 | 可得到什么 | 限制与代价 |
| --- | --- | --- |
| 既有行程/返程约定 | 计划路线、约定地点、可能经过区域 | 计划可能变更；逾期提示失联，不断言已遇险 |
| 求援/同伴转报 | 发信时位置、遭遇描述、请求 | 传递延迟、封禁、截获、误认、伪造；核对来源 |
| 人情与线人 | 目击、传闻、可疑人物或买卖记录 | 关系、报酬、偏见、保密与利益；不是付钱必出真坐标 |
| 调查与踪迹 | 最后露面、行迹方向、战斗残留、入口变化 | 痕迹会过时；需要到场、能力、比较与搜寻 |
| 卜算 | 可检验的方位/区域、关联征兆、模糊状态或干扰提示 | 需关联媒介、修为/技艺、材料及施术时长；准确度受遮蔽与干扰影响 |
| 偶遇 | 亲眼见斗法、伤者、信物、洞口异象 | 由掌门实际路线、时间与可见范围触发，不为救援自动传送主角 |

卜算首版建议输出“区域或方向 + 指向依据 + 推算时刻 + 已知限制”，不用作者无法解释的万能百分比。结果可以粗略、过时、受干扰或被诱导；有对照调查与校验方式。风险与误差来源见09，不可让同一事实换措辞便重抽卜算。

重复卜算不是免费刷答案。新媒介、施术者能力、干扰解除、足够经过时间或新观察才改变输入；同输入使用已定结果并可重复核验，不奖励连点。

玩家地图上的标记属于知情投影：已证实位置、最后已知位置、疑似区域分别显示，并记录信息年龄。标记可以过时；不知道所在层/入口时不能以精确导航箭头绕过调查。真假、来源与传播均引用09的claim/evidence模型，不在本文件再复制一套消息。

## 7. 赶到、干预与救援窗口

完整链为：**察觉异常 → 获得线索 → 判断可信度 → 定位/搜寻 → 准备与出行 → 抵达当前现场 → 干预实际危险 → 脱离与善后**。流程不是固定剧情问答，每一步可以由已存在条件省略，也可能失败。

掌门采取行动后，旅程、其他危机阶段与留守世界一起推进。赶路时间取决于路线、交通、天气、负重、伤势和通行权；不能点地图支付费用便瞬间救出。

到场可进行的行动根据真实现场开放：参战、谈判赎人、打破阵眼、打开出口、拖离持续伤害区域、治疗稳定、提供保命物、组织撤退或承接追击。战斗、搬运伤者与操作阵眼是有占位/动作时间的行为，不能同时在互不相邻地点执行。

NPC若意识清醒，接受治疗、随行、服用不明丹药与交付随身物仍按意愿判断。对于无意识者，现场急救/搬离直接危险可按预设紧急救护规则实施；不把这一例外扩展为永久接管、任职或学法。

救援不承诺成功：人可能已经自行逃离、被转移、被俘、被骗至另一层，也可能伤势不允许远程转运。迟到时保留真实过程与可发现证据；掌门可以收敛遗物、追查、救其他人或终止追赶，不只剩“失败”弹窗。

救援窗口依据阶段配置、NPC自救、敌人行动和路线测算。对作者安排的早期、已建立情感联系的教学危机，至少验证一条正常资源条件下可行的发现与干预链；后期高风险事件可出现无法兼顾或已无法挽回的局面，并需相称前兆。

可救情景必须在作者工具中登记真实tick预算：`消息传递 + 核验/定位 + 准备 + 出行 + 寻找入口/到达伤者 + 执行有效干预`，与该分支实际致命演变时刻比较。并行步骤只在不同自愿行动者或真实并行条件下抵扣，不能让掌门一边赶路一边在远处破阵。同tick干预与死亡边界按05统一世界步排序裁定，不由回调先后决定。

预算应同时测最短合理路线、普通路线及至少一个延误分支，记录NPC自救延长窗口、天气/入口变化和消息误差的影响。“可救”至少存在一条正常能力/资源与已可获得信息下的行动链，而不是要求玩家预知秘密、暂停时免费移动、零成本卜算或预先蹲在未开放洞口。该工具数据不是正式UI的全知倒计时；玩家只看能够观察到的危险及估计。

**没有普遍的“每人都一定能救”下限。**远方陌生人可无人目击地死亡；但为玩家设计的持续生命危险，若既无可信征兆、无发现渠道、无NPC自救/求援可能，又以此惩罚玩家，属于内容设计失败。线索可能不可信或被忽略，不等于作者可以完全不给线索。

自动暂停/警示只能依据掌门实际收到的信息或直接观察。其文案是“陆知微已逾约定归期”“收到残缺求援”，不能把隐藏危机的剩余tick或敌人真名显示出来。已知现场可显示当前动作与可观察危险，不用隐藏阈值倒数承诺必救。

## 8. 暗中害人也必须发生在世界里

陷阱是玄幻游戏中的可部署实体或事件条件，不是改写生命属性的指令。本节只定义游戏系统，不提供现实伤害方法。

建议`hazardsById`记录：稳定ID、来源命令/事件、布置者、场景与几何位置、材料/法器实例、部署活动、触发条件、效果规则、识破/解除条件、持续时间、已有触发结果及证据痕迹。

| 环节 | 必须成立的条件 |
| --- | --- |
| 获得条件 | 掌门有能力、可接触材料、合理场所与通行机会；不能远程随意修改洞天 |
| 布置 | 实际到场或合法受托者自愿到场，消耗材料与动作时间；被看见、被打断均可能发生 |
| 诱导 | 通过消息、利益、路线或可见机会影响他人；对方依据已知信息决定，不保证照做 |
| 触发 | NPC确实进入相应空间/条件；按同一世界钟、动作和身体规则生效 |
| 演变 | 形成受困、暴露、争斗或持续消耗危机；不是触发即强制dead |
| 反制 | NPC可识破、绕行、拆阵、反用、求援、逃离或建立反证；对手会适应重复手法 |
| 责任 | 生成可被发现/隐藏的线索、材料来源、目击、阵法签名与利益关系；指控需经过09证据与组织处置 |

陷阱效果不能自动改成“敌人入洞后必死”；同门、无关人或施术者也可能承受规则允许的后果。是否限制目标，必须由法术实际能力和成本决定，不能由UI名单筛选赋予全知辨敌。

改写禁制、误导机关、封锁出口等内容都需作者定义具体场景交互与可逆/不可逆后果。首版只实现少量有完整因果链的玄幻预设，不提供无限自由脚本或跨地图任意杀人的权限。

恶意行动引发的社会后果按知情、立场与利益变化。被发现不保证全世界立即通缉，未被发现也不自动免除同谋把柄、债务、幸存者记忆与未来调查。死亡记录保存实际因果，公开版本可以有争议。

## 9. 死亡结算与余波

NPC永久死亡是世界事实，可由合法致命演变结算；不是读档时重抽、关页面后追加或UI回调触发。

死亡事务至少同时处理：

1. `lifeStatus=dead`，创建唯一`deathRecordsByPersonId[personId]`；记录时刻、地点、原因链、关联危机/战斗及真实参与者。
2. 结束该人身体行动，释放或转移工位、预约、临时道具、队伍席位与职责；其他参与者继续各自合法活动。
3. 身体和携带物留在实际位置或按当时事件规则转移。可搜寻、被他人取得、损毁、流失或被官方保管；不能把全身装备直接发到掌门背包。
4. 所有权、保管、借用、绑定与继承/领取许可分别处理。门派借物不是死亡便复制归库，私人财物不是掌门自动财产；债务、担保和托付按既有规则处理。
5. 师承、课程、职责与进行中的工程留下缺口；保留已学知识与已有劳动，不撤销全部共同成果。
6. 亲友、师生、仇敌与同僚依据知情产生悲恸、怀疑、宽慰、愧疚、追索或利益变化，不用全员统一“忠诚-10”。
7. 生成可传播的消息、遗言/遗物与调查入口；尚未知情者不立即显示悼念。事实、消息和公开指控仍有不同状态。

死亡记录不可因姓名改变或离宗而消失；同一personId不得生成第二具可搜刮遗体。各物品、债务、遗物领取与奖励使用唯一事务/结算键。遗体可以失踪，不代表记录被删；未找到尸身不保证死亡消息可靠。

关系不是全部归零。死者作为记忆、师承来源、债务主体与事件关联继续存在；幸存者可以改变志向、承担遗愿或拒绝继续探险。余波有持续期和行为差异，不只加一条日志。

## 10. 鬼道、魂魄与复活边界

鬼道不是“所有死人自动加入的职业”。死亡、残魂、鬼修、转生与复活属于不同条件和实体转换；不以派别名称抹去死亡代价。

首版推荐：NPC死亡按不可逆结局处理；有限内容可留下残念、传讯或可调查灵迹，但不因此自动恢复生前身体、境界、资质、物品或可操控席位。完整夺舍、转生、复活与世代继承后置，不能作为常规死者恢复按钮。

任何未来魂魄续存内容必须预先定义适用对象、形成条件、连续身份、能力损失、持续时间、资源与社会后果。是否还是同一人物、何时才算最终消亡由共同schema规定，不用生成同名NPC骗过死亡验收。

对于已知、自愿开启的不可逆动作，在行动前明确其不可逆性质和已知代价；不可逆节点提供相称提示，不在每次普攻重复确认。玩家未知的敌方秘密不会通过确认框泄露，其可识别前兆与调查渠道必须由09和作者验收保障。

主角被击倒、剧情败亡或绝境失败进入明确的恢复/失败/读档流程；不删正式档、不自动换NPC为主角、不擅自加入灵魂继承。复仇篇章中的父母死亡和已有结局仍保持既定事实。

## 11. 难度、开局保护与公平性

推荐初版采用“前期安全教学 + 明确可致死的探索世界”。这不是全世界的永久安全罩：教学安排先让玩家理解行程、求援、伤势、定位与救援，再开放高危洞天和谋局。

风险提示表达角色合理知道的级别、条件与准备建议：安稳路线、需谨慎、有重伤风险、存在身死风险。不能保证“谨慎”无人死亡，也不能把已知致死区域包装成普通采集。

推荐可配置较宽容的教学/救援节奏，调整NPC防险倾向、求援条件、稳定伤势的成本、阶段时长与可用撤路；标准探索仍允许永久死亡。不用“简单模式把未知消息全部变真”改变修仙世界的核心。

作者按事件类别验证：

- 安稳日常：无条件随机死亡禁用；设施事故与敌袭需实际源头、演变与可察觉异常。
- 已知风险探索：预先展示合理已知风险与准备机会；进入后允许损失与致命结果。
- 突发遇袭：危险来源、NPC防备、战斗演变与消息通路成立；不能用瞬时抹除跳过过程。
- 持续失联：有计划信息、逾约、调查或追踪路径；不把所有失联都标成救援倒数。
- 明确陷阱/谋局：至少有不依赖全知的前兆或检验路径，结果受行动改变，不因玩家识破临时再加必杀层。

每个危机的难度参数包括路线时长、线索到达时长、阶段时长、救治条件和NPC可用自救资源。不能单独拉长死亡倒数就宣布公平；要测从玩家实际知情时刻开始是否有合理选择，以及失败是否可解释。

## 12. 数据、迁移与保存

目标根实体为`crisesById`、`combatSessionsById`、`hazardsById`及`deathRecordsByPersonId`。人物、场景、装备与消息继续引用既有主表；`person.combatSessionId`是当前实际参与的有效会话引用，没有参与时为null。每人只能有一场占用身体的有效会话，不能在preparing/active/settling间用不同阶段绕过唯一占用，更不能创建第二个人物副本。

危机实例示例（局部形状，不是可直接导入存档）：

```json
{
  "id": "crisis:jade-cavern:001",
  "kind": "sealed-cavern",
  "causeEventIds": ["event:cavern-gate:001"],
  "sceneId": "scene:jade-cavern:outer",
  "participants": [{"personId": "person:npc:001", "role": "at-risk"}],
  "stage": "critical",
  "stageStartedTick": 2400,
  "durationTicks": 600,
  "stageProgressTicks": 120,
  "combatSessionId": null,
  "hazardIds": ["hazard:gate-seal:001"],
  "conditionIds": ["condition:exit-sealed", "condition:ward-draining"],
  "resolutionTransactionId": null,
  "outcome": null
}
```

真实条件与player-visible消息分开。以上600 ticks仅示例，不是所有洞天的统一死亡时限。计时只由模拟推进，存在条件变化时由对应规则调整；渲染倒计时不能修改durationTicks。

保存包含当前动作阶段、资源/伤势、危机进度、行程、部署物、随机状态、消息发送/收到时刻、发现记录与已定死亡结果。读档继续同一事件，不重新出“这个NPC到底生死”的随机题。

旧v1–v5存档升级必须备份、隔离转换、校验引用并可恢复。新结构版本号由实施决定；设计版本v1.1不代表存档已经升级。

旧档迁移不得立即补算“过去应该死了的人”，不得让正在安全执行旧日常的门人突然成为致死抽签对象。迁移保留旧人物、关系、伤势、已完成战斗、行程与剧情结局；无法建立新危机条件的旧在途行为采用可解释的兼容收束或待恢复状态，而非凭空制造敌袭。

推荐首次加载迁移档时提供一次简短规则说明：“未来危险探索可能造成永久身死；日常不补算死亡；可先导出备份”。未开始的新探索按新规则走。是否提供本档的过渡教学/旧行程保护是产品可调选项，不能把每个人的死亡逐个交给玩家弹窗批准，也不能悄然把用户已确认的死亡边界永久关掉。

若保存失败，按05暂停并允许导出，不能在死亡事务半提交时继续跑余波。原档与其他正式档不删除；死亡事实不会在加载失败时静默恢复为alive。

## 13. 验收

| ID | 必须验证的行为 |
| --- | --- |
| CRISIS-01 | 同一事件的危险阶段与逐人身体状态独立；健康者可陷绝境，受伤者可已脱险；失踪/被俘不等于死亡 |
| CRISIS-02 | 危机有来源、真实参与者、可追踪阶段和明确演变条件，无日常定时随机删人或UI秒杀 |
| CRISIS-03 | NPC能合理准备、识破、撤离、稳伤与求援；拒绝掌门邀请不会自动触发死亡惩罚 |
| CRISIS-04 | 玩家近景战斗、远方斗法、危机、旅程和宗门生产共用世界钟；暂停/后台/关闭全部停止 |
| CRISIS-05 | 近景与离屏在相同动作输入、随机种子和tick下保持资源、伤势、位置与终局一致；进入画面不重置、不重抽 |
| CRISIS-06 | 一个人不会同时占多个斗法会话或边外出战斗边在山院生产；批量推进在到场/干预/结算边界正确切分 |
| RESCUE-01 | 未知遇险不显示全知坐标或剩余生命倒数；最后已知位置、疑似区域、已证实位置可区分 |
| RESCUE-02 | 传讯延迟/过时、卜算误差、假消息与调查可实测；同输入连点不免费重掷答案，付费也不必得到精确真相 |
| RESCUE-03 | 一条早期教学危机可通过正常资源和真实路线完成发现、定位、到场、干预及返程，不依赖控制台或强控NPC |
| RESCUE-04 | 同一危机测试及时、绕路、误信、迟到、NPC自行脱困与被转移；每个结果有符合事实的可发现依据 |
| RESCUE-05 | 掌门救治、搬运、战斗、破阵使用实际动作、占位和时间；未知信息不因自动暂停或辅助提示泄露 |
| RESCUE-06 | 部署玄幻陷阱消耗真实材料/时间、符合空间/触发条件；NPC可识破或反制；不能远程点人改dead |
| RESCUE-07 | 持续危险至少有相称征兆/发现或自救渠道；远方未知NPC可未被玩家发现而身死，无“人人必救”承诺 |
| DEATH-01 | NPC死亡事务完整且只结算一次；注册/死因保留，身体行动停止，工位/队伍/职责无幽灵占用 |
| DEATH-02 | 遗物真实留存/转移；私产、公物、借物与绑定不混淆，债务和师承余波保留，不能无限搜刮 |
| DEATH-03 | 知情亲友出现各自悲恸/追索/志向变化；未收到消息者不全知；公开指控不自动等于真实死因 |
| DEATH-04 | 主角失败不硬删档、不擅自继承；NPC死亡无普遍鬼道复活按钮；不可逆已知动作有相称提示 |
| DEATH-05 | 关键人物身死有遗物/记录/其他证人等合理替代证据，可靠复仇主线可继续；不靠复活或新幕后黑手补洞 |
| DEATH-06 | 读档恢复动作、危险进度、消息时刻和死亡结果，旧v1–v5迁移无追算历史死亡、随机换人或丢旧结局 |

验收记录分别标明已知/未知危险、玩家视角/调试真相、新档/旧档和各阶段存档点。设计文件及模拟trace只能证明规则一致性，不能替代真人是否理解危险、定位和救援的体验验证。
