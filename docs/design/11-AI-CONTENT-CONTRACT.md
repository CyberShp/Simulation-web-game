# AI 与内容生成契约

设计编号：DB-2026-10-05；版本：1.2。本文是目标设计，**本轮不接入任何 AI API**，也不选定供应商、模型、价格或计费套餐。AI 是可选表达能力，世界成立的条件由本地规则和受验收内容保证。

共同事实、时钟和命令见 [05-RUNTIME-CONTRACTS.md](05-RUNTIME-CONTRACTS.md)；天气与生态见 [08-LIVING-WORLD.md](08-LIVING-WORLD.md)；情报、暗线与谋局见 [09-INTRIGUE-OPPORTUNITIES.md](09-INTRIGUE-OPPORTUNITIES.md)；危机、斗法与生死见 [10-CRISES-RESCUE-DEATH.md](10-CRISES-RESCUE-DEATH.md)。作者内容入库规则见 [12-CONTENT-AUTHORING.md](12-CONTENT-AUTHORING.md)。

## 1. 明确取舍

**推荐可选、默认关闭。** 玩家不购买 API、不联网、不提供密钥，也必须获得完整的世界生活、人物自主、天气变化、真假消息、谋局、战斗、救援、死亡、暗线和主线。

AI 开启后可以增加说话变化、日记措辞和已知事件的叙述。它不增加机械收益、不提供独占线索、不提高卜算准确率，不让付费玩家更容易救人或识破骗局。

规则决定“发生了什么、谁知道什么、谁意图说什么”；模型只在授权范围内决定“这句话怎样表达”。即使未来加入候选行动生成，权威选择仍属于有约束的规则层。

本版将原 R-15 细化为：规则与内容完整可玩；在线 AI 可选且默认关闭；获知过滤后的表达是唯一首轮运行用途；高层候选提案后置。用户提出了“是否引入”的问题，尚未逐项批准此建议，不能标为 `user-confirmed`。

## 2. 四级能力与首版范围

| 等级 | 用途 | 可以做什么 | 不可以做什么 | 本版范围 |
| --- | --- | --- | --- | --- |
| A0：无 AI | 完整本地游戏 | 规则人物、预设对白、组合式消息、完整暗线与结果 | 因无模型而关闭天气、情报、救援或主线 | 必须成立 |
| A1：作者辅助 | 开发期离线创作 | 提议事件草稿、对白、人物关系、线索与分支；经人工和规则验收后编入内容版本 | 未审草稿直接成为新档秘密；自动修改已发布存档 | 可以使用 |
| A2：运行表达 | 玩家主动开启的可选能力 | 改写已授权对白、按已知事实写日记、润色场景观察 | 创造事实、秘密、承诺、奖励、真假判断、致死结果或新的对话选项 | 后续接入时的唯一首轮运行能力 |
| A3：高层候选提案 | 未来研究 | 为有明确身份和权限的规则主体提供候选动机/动作表达，经规则筛选后采用 | 直接执行、操控掌门、全知策划、绕过 NPC 意愿、成为必需模拟器 | 明确后置 |

A0 并非删减内容模式。每个正式内容条目必须先能在 A0 下被触发、理解、完成和复盘，再决定是否提供 A2 表达。

A1 提案按正式内容流程落地：稳定 ID、参与人、前置事实、陈述来源、可观察线索、期限、成本、反制、失败与生存路径、结果事务、旧档影响及验收。文本好看不能替代这些字段。

## 3. 世界写入权的边界

| 能力 | 权威来源 | AI 读取或输出范围 |
| --- | --- | --- |
| NPC 工作、出行、善恶选择 | 人物目标、性格、关系、能力和规则评分 | 可表达已定意愿与公开理由 |
| 天气、生态、路况 | `weatherByRegionId / ecologiesBySceneId` 与时钟 | 可描写人物已感知的雨、雾、风等现象 |
| 传闻、谎话、证据 | `claimsById / factsById / investigationsById` | 可表达授权 claim，不能判真或补造来源 |
| 卜算 | `divinationsById` 的消耗、结果范围和干扰规则 | 可润色已确定卦辞，不能提高精度或开天眼 |
| 谋局、稀有机缘、母篇风险 | `schemesById / opportunitiesById` 与定义版本 | 只表达已经获知的迹象或已授权陈述 |
| 战斗、危机、伤势、死亡 | `combatSessionsById / crisesById / hazardsById / deathRecordsByPersonId` | 可叙述已发生且掌门获知的表现；不得裁定生死 |
| 资源、装备、法门、突破 | 权威命令、活动和一次性事务 | 不读写余额，不生成实例或奖励 |

不得因为模型认为“戏剧性不够”临时添母篇持有者、域外来敌、死者复生、暗藏血统、未知境界、新功法或隐藏奖励。作者想加入这些内容，走 A1 内容评审，不在 A2 对白里即兴添加。

NPC 说“我明日陪你去”必须已有承诺事务或明确的未决提议；模型不能用漂亮的措辞替 NPC 答应同行。模型说“这里安全”只能表达对应人物已获授权的判断/陈述，不能替换地图风险规则。

## 4. 叙述包：先过滤，再请求

模型网关不接收原始存档、全人物表、全谋局、敌我装备全量或全地图真相。规则层先生成有范围的 `NarrativePacket`；它是知情投影，不是新的事实主表。

| 字段 | 允许进入包的内容 | 禁止进入包的内容 |
| --- | --- | --- |
| `speakerId, recipientIds` | 稳定身份及当前获准对话的对象 | 全世界人物关系矩阵 |
| `visibleEntities` | 已见姓名、可见外观、已知称谓和位置粗略描述 | 隐藏阵营、真名、未露装备属性 |
| `observedFacts` | 当前角色确实可感知且允许向受众表达的事实 | 玩家/发言者未知的真实凶手、母篇、陷阱机制 |
| `authorizedClaims` | 已配置且允许说出的 claim 内容、口吻约束和 claimId | 未授权的新指控、新消息、秘密外泄 |
| `publicTone` | 已公开或可表达的性格、习惯、礼貌和心情 | 隐藏恶意数值、谋局目标和真实谎话标记 |
| `allowedEntities / allowedTerms` | 本次获准提到的地点、法门、境界、物品名称 | 让模型任意补充新实体或游戏数值 |
| `constraints` | 输出类型、字数、句子用途、允许的措辞范围 | 对世界状态的任意写入权限 |

双方已知交集可以直接形成谈话素材。交集以外的新线索须由规则引擎先批准披露，建立对应 claim/观察或知情记录；AI 只能表达这一授权内容，不能自行决定把秘密告诉掌门。

谎话同样来自授权 claim。内部许可可引用 `liePermissionId`，但发往模型的包只包含“该人物此刻允许说出的陈述”和表达约束，**不包含其真实真假、幕后者、谋局步骤或未暴露意图**。玩家界面也不能因后台存在谎话许可就显示“此人在说谎”。

人物引用了错误消息时，句子的类型始终是“人物声称/相信”，不得经模型改写成旁白认证。真假、误信、刻意隐瞒、伪证与调查等级仍由情报系统保存。

包必须同时完成发言者知情过滤、披露许可和接收者范围检查。不能把“掌门不知道”当作万能理由让所有 NPC 都知道；也不能让一个 NPC 获得另一个 NPC 的私密见闻。

## 5. 请求与响应形状

以下 JSON 是接口局部形状，不能直接作为真实请求或存档导入；实现时需要类型、范围与引用校验。

```json
{
  "requestId": "ai-request:session-a:0018",
  "mode": "expression-only",
  "packetId": "narrative-packet:0018",
  "packetVersion": 1,
  "worldRevision": 142,
  "observedAtTick": 3600,
  "rulesetVersion": "rules:sample:1",
  "contentVersion": "content:sample:1",
  "speakerId": "person:visitor:004",
  "recipientIds": ["person:master"],
  "capabilities": ["utterance.paraphrase"],
  "visibleEntities": [
    {"id": "person:visitor:004", "name": "山客", "description": "披着湿斗篷的来客"}
  ],
  "observedFacts": [
    {"factId": "fact:rain-observed:008", "text": "院外正在下雨", "scope": "current-observation"}
  ],
  "authorizedClaims": [
    {"claimId": "claim:visitor:rumor:018", "text": "听雨遗址近日有人寻得古卷", "presentation": "speaker-stated-rumor"}
  ],
  "publicTone": {"manner": "谨慎、话少"},
  "constraints": {
    "maxCharacters": 100,
    "allowedEntityIds": ["person:visitor:004", "person:master", "location:tingyu-ruins"],
    "allowedClaimIds": ["claim:visitor:rumor:018"],
    "forbidNewFacts": true,
    "forbidCommands": true
  }
}
```

```json
{
  "requestId": "ai-request:session-a:0018",
  "packetId": "narrative-packet:0018",
  "worldRevision": 142,
  "segments": [
    {
      "kind": "speaker-utterance",
      "speakerId": "person:visitor:004",
      "claimIds": ["claim:visitor:rumor:018"],
      "factIds": [],
      "text": "听说近日有人在听雨遗址寻得古卷；我也只是听来的。"
    }
  ]
}
```

示例没有利用天气事实扩展传闻；若需要加入环境描写，须引用相应 factId，并保持其授权含义。任何量化风雨、路况、境界、价格、时间及风险描述须来自授权字段，不能由改写自行提高或降低。

响应只允许输出表达段，不携带 `effects`、余额、人物位置、命令或新实体。`aiGatewayResultId` 可以作为表达来源的稳定引用，不作为事实、claim、证据、命令批准或奖励键。

正式实现可将响应定义为封闭 JSON Schema：未知字段拒绝；段落 `kind` 限于授权枚举；实体和事实引用须在包白名单内；长度与段数有界；禁止可执行 HTML、脚本、工具指令及 URL 动作。内容中的书信、日志、玩家自定义姓名和外部模型文字全部按数据处理，不可当作网关指令。

## 6. 验证与表现：不把语义猜测当保证

结构校验可以核对 ID 和格式，**不能证明自然语言没有偷偷添加事实**。因此采用两类表达，而不是宣传“JSON 校验后绝无幻觉”。

1. **关键表达用模板锁定。** 死亡状态、救援期限、卜算精度、风险、交易承诺、调查结论、功法后患、地点位置与关键证词使用确定模板。AI 可润色前后气氛，不改动核心句。
2. **低风险措辞允许改写。** 问候、已授权传闻的说法、场景气氛和日记连接句允许有限变化；仍做实体、数字、事实引用、披露和用途检查。无法确认时回退原模板。

来客的情绪、夸饰、口头称赞不能自动变成名声变化；日记中的猜测只能保留“我怀疑”等主观标记，不能升级成已确认记录。

后台验证通过前不向玩家展示流式文字，更不能让未验证文本先改变玩家对生死、机缘或功法风险的判断。模型流式响应可以内部缓冲；最终接受一次或丢弃全部。模板已在屏幕上时，晚到结果不得自动改写玩家正在读的关键句。

若文字与授权含义冲突，即使格式正确也拒绝。为降低语义风险，初次接入优先限定问候与复盘表达，不把危机即时提示交给模型。

## 7. 启用、关闭与切换

设置页提供“世界对白表达 AI：关闭/开启”，默认关闭；明确说明基础玩法完整、请求包含哪些已知对话数据、是否使用玩家提供的服务、可能产生的请求费用及预算上限。

启用需由玩家明确选择，不能在第一次遇到骗局、救人或突破时诱导“必须开 AI 才能继续”。没有合法网关配置时保持 A0，提供设置说明；不得循环弹窗或隐藏关键功能。

关闭后立即取消新请求，待处理请求标为废弃；继续显示 A0 内容。开启、关闭、更换模型、网络断开均不重新抽取天气、人物、暗线、战利品、卜算或危机结果。

切换模型仅影响之后的允许表达。已经展示且被玩家依赖的证词与关键消息保持原文及来源；不能通过刷新润色改变旧证词含义或洗掉谎话留下的矛盾。

模型和提示版本更新必须单独记录，先回归表达边界再上线。它们不等于 `contentVersion` 更新，不能改变旧档世界事实；内容变化仍走正式内容迁移。

## 8. 等待、失联与晚到响应

API 请求不是模拟驱动器，也不是 worldTick 推进条件。请求耗时、重试、限流、认证失败、额度不足或掉线都不能自动暂停或加速世界。

普通剧情阅读、管理界面或战术暂停仍按共同暂停契约执行，同一操作在 A0/A2 下具有相同效果。网络请求本身不能新增暂停原因、延长危机保护窗或在响应到达时自行恢复游戏。

危机界面先展示掌门已获知的状态、已知时效、可观察危险、可行行动与模板对白；未知真实坐标、幕后人和后台致死倒计时仍被过滤。玩家能马上移动、斗法、调查或救援，不因等措辞失去操作入口，也不以付费接口的等待换得额外冻结时间。主动战术暂停遵循统一规则，与有没有AI无关。

每个请求有墙钟网络超时、最多尝试次数、取消条件和模板回退；这些网络参数不计入世界时间。超时、验证失败或身份不匹配时只降级表达，不撤销已经提交的世界行为。

请求持有 `requestId / packetId / worldRevision` 与参与实体版本。响应回来时检查会话仍存在、发言者身份、获知与许可没有失效、未关闭 AI、没有越过内容范围。

全局 revision 改变不一定使一句问候失效，但必须重新做依赖检查。依赖人物死亡、地点变化、情报已证伪、承诺已撤回、危机阶段结束等发生改变时，不把旧包文字显示成当前事实。

过期响应可在开发诊断中保留为“过期文本”，产品界面默认丢弃；任何情况下都不能执行其动作、补发奖励或修改世界。若用于历史日记，必须有对应历史事件和时刻，明确是对过去的复述。

## 9. 缓存、预算与存档

表达缓存键包含授权包摘要、表达用途、语言、模型/提示版本和隐私策略版本。不同人物、受众或披露许可的内容不得共用同一缓存键。

已正式展示的关键话语保存原文、说话人、claim/fact 引用、发言时刻、包版本和表达来源。事实和结果先保存，表达来源可记为 `template / ai-reviewed`；读档不为了恢复一句话重新请求 API。

未显示的可选气氛文字可以丢弃并使用模板。API 取消、失败、空响应不能产生一条新的情报或谎话记录。AI 缓存损坏仅失去可选措辞，不能损坏存档或使正文无法展示。

存档不包含 API 密钥、访问令牌、服务器凭据、完整网关日志或未过滤真相提示。可保存个人“AI 已启用”偏好，但恢复时仍须核对当前网关能力，不能把旧凭据随档分享。

预算按请求数量、可配置文本量、并发、重试和玩家批准的上限控制；实际费用的展示以选定服务的实际计费能力为准。达到上限自动停止请求并回到 A0，不影响世界进度。

调速不增加按 tick 请求的频率；请求只发生于明确表达节点。相同节点去重，重复打开人物卡、地图、日记或读档不连续刷请求。第一轮建议单会话至多一个表达请求在途，预算数值待接入压测确定。

现实 API 费用不得变成游戏内灵石消耗、NPC 的付费意愿、卜算成功率或成长加成。表达模式在同样世界种子与玩家命令下，应产生相同世界事实。

表达缓存、请求计数与模型随机性使用独立表达存储和标识空间，不推进世界 `rngState`，不占用事件的命运抽取序列；AI 字数、请求顺序和输出差异不能改变下一次天气、遭遇或斗法随机结果。

## 10. 接口安全与密钥方式

公共网页代码、公共仓库、静态资源、公开 URL、分析日志和游戏存档不得包含运营方密钥。未来有运营方网关时，由服务端保管凭据、鉴权、限制能力与预算；静态游戏不能靠前端隐藏字符串保护密钥。

玩家自行配置服务（BYOK）可作为后置接入方式，不是基础游戏要求。首次使用说明密钥将发往哪里、哪些对话数据会发出、在哪里清除。密钥仅用于玩家选择的服务，不随存档导出，不默认长期持久保存；没有合适的服务端保护或明确的玩家配置时，保持关闭。

网关只具备表达能力，不与拥有游戏事实写入权的服务器工具共享凭据或通用工具执行器。AI 返回的“工具调用”“修改存档”“上传资料”“执行链接”全部作为无效输出拒绝。

错误提示区分未配置、认证失败、网络超时、预算到达、服务拒绝、输出不合规和表达已过期。产品提示简短，诊断日志去除密钥和无关隐私。

## 11. 后置 A3：候选提案而非第二个模拟器

高层候选生成如未来确有价值，只能针对明确主体与能力白名单提出规则已支持的候选，例如“此人可考虑继续调查、暂避、求援中的哪一种”。它不能自造新机缘、新法门、新利益相关人或命运结果。

候选最少具有 `proposalId / requestId / actorId / expectedRevision / allowedActionId / referencedEntityIds / reasonClaimIds`，并进入以下顺序：

1. 用该人物的知情、目标、性格和已有义务生成有限输入；不发送全知谋局。
2. 候选只引用预先合法的动作 ID，不接受任意 command payload 或原始效果。
3. 规则引擎校验身份、权限、意愿、条件、时间、成本、冲突、危险和内容许可，并依既有评分决定采纳或拒绝。
4. NPC 采纳后进入普通活动/命令事务；掌门候选只作界面建议，须玩家主动采纳，AI 不替玩家下令。
5. 重复 proposalId 幂等；过期、超时、无效或被拒绝时采用规则本身的决定。

批准是游戏内规则校验与玩家必要操作，不要求开发过程中对每条 NPC 提案弹出外部审批。人物拒绝、误判、撒谎仍按规则和其已知事实发生；不得借 AI 生成“合理借口”绕过门人自主边界。

A3 也不能直接批准死亡、制造陷阱或决定吸取境界。它最多选择已有合法行动，风险与因果由危机/谋局系统推进。同种子和已批准行动的结算规则不能因模型更换而改变。

NPC 世界基本决策在 A0 中必须完整，因此 A3 未上线、不可用或永久关闭都不减少自主生活与暗线能力。禁止为了接 API 将原有规则决策删除。

## 12. 作者内容验收与有限交付

高阶功法、装备、洞天与机缘由作者配置一条或多条暗线；模型可以协助构思，但正式内容必须有可验证的规则图。普通秘闻可组合生成，不能通过在线模型无限补写已存在物品的历史。

作者审查至少覆盖：动机能否成立、获知是否越权、诱饵有没有实际利益、线索与反制是否可达、 NPC 能否独立受骗和识破、是否存在其他利益方、未参与时世界怎样推进、生死是否有阶段、突破是否可中断、失败后可否继续、与主线及旧档是否冲突。

初次运行 AI 交付前只接有限表达场景，先测 A0 与 A2 同事实、故障回退、秘密隔离及证词稳定。不能用“AI 已接入”替代活世界、实体场景或人物可理解性的验收。

## 13. 验收规则

| ID | 必须通过的验收 |
| --- | --- |
| AI-01 | 全程关闭 AI、断网或无密钥的新档可完成开局、经营、调查、斗法、救援、暗线和主线；基本 NPC 自主照常 |
| AI-02 | 相同种子、模拟 tick 和玩家命令下，A0/A2 的天气、人物选择、情报许可、资源、伤势、死亡和奖励事实相同 |
| AI-03 | 模型输入看不到隐藏谋局、母篇、幕后身份、未获知伤势或真伪；有意谎话只来自授权 claim |
| AI-04 | 人物传闻不会被旁白认证；模型输出新实体、数字、承诺、风险结论或不在白名单的 claim 时拒绝并回退 |
| AI-05 | 玩家输入与故事书信中的“忽略规则/调用工具/披露秘密”无法越权；输出 HTML、命令与工具调用不执行 |
| AI-06 | 长时延、失败、限流、额度不足及超时均不阻止操作、不改变 worldTick 速率、不延迟确定的危机提示或免费冻结世界 |
| AI-07 | 请求后说话人死亡、消息证伪、地点变化、许可撤销或关闭 AI，晚到响应被丢弃；没有迟到命令执行 |
| AI-08 | 未验证的流式正文不进入产品；关键结论固定模板；语义无法确认时回退，不谎报结构校验等于事实正确 |
| AI-09 | 切换模型、刷新、调速、重复打开 UI 与读档不重抽事件、不重复请求奖励、不改旧证词或制造新的已知消息 |
| AI-10 | 预算到达后 A0 无缝继续；费用不转化成灵石、成长、卜算精度或救人优势 |
| AI-11 | 公共构建、仓库、URL、日志和分享存档无密钥；缓存只在相同主体、受众与披露许可下复用 |
| AI-12 | 已展示关键消息的说话人、时刻、claim/fact 引用和原文可恢复；缓存/API 不可用不损坏世界存档 |
| AI-13 | A1 未验收草稿不能进入正式内容；正式暗线具有线索、期限、反制、结果、存档和无 AI 完整路径 |
| AI-14 | 后置 A3 无事实写权限；候选经身份、知情、意愿、版本和成本校验，掌门行动需玩家采纳，重复或过期候选不执行 |

本版没有 API 实现或以上验收结果。状态应记为 `designed`；不得写成“AI 已可用”“费用受控已验证”或“绝无幻觉”。
