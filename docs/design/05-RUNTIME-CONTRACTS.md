# 运行时、数据与存档契约

设计编号：DB-2026-10-05；版本：1.2。本文为目标接口，不宣称现有EA已经采用这些字段。它负责跨模块的唯一事实与序列化边界；领域规则分别见 [人物](01-CHARACTERS.md)、[装备武学](02-EQUIPMENT-ARTS.md)、[空间](03-SPATIAL-ART.md)、[世界](04-WORLD-STORY.md)、[经济](07-ECONOMY-ORGANIZATION.md)。

本地实施状态：EA 1.6.0-dev / schema 6，规则修订opening-runtime-3。实际覆盖范围、现有存档接口与本地增量按[STATUS](STATUS.md)最新段、[接手指南](../CODEX-HANDOFF.md)及代码核对；[15–18的历史实施入口](README.md)只说明对应旧批次。下文包含目标接口与局部示例，不能据示例直接重写已持久化字段或宣布完整schema已验收；接续实现须明确现有字段与目标语义的对应、兼容和测试。

## 1. 事实、定义和画面分开

| 层 | 内容 | 可否改变游戏事实 |
| --- | --- | --- |
| 内容定义 | 建筑预制件、物品、法门、动作、事件模板、规则配置 | 只作为版本化规则输入 |
| 世界状态 | 实体、位置、活动、物品归属、库存、关系、已定结果 | 由命令或模拟步修改 |
| 命令与事务 | 经过权限/前置校验的玩家请求和AI请求 | 可以原子提交、扣费、登记结果 |
| 模拟 | 移动、活动进度、生产、事件、成长、恢复 | 由唯一模拟时钟驱动 |
| 玩家知情投影 | 姓名、动作、原因、可用操作、已公开证据 | 只读；隐藏事实经过权限过滤 |
| 渲染与输入 | 镜头、贴图、动画、命中候选、拖动预览 | 不产出、不重抽人物、不直接改资源 |

同一事实只有一个写入者。管理页、宗门总览、近景、世界地图与战斗读取同一实体，不复制拥有不同生命值/外观/关系的人物。

## 2. 目标状态根与引用

根状态建议包含：

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 存档结构版本；本地开发版首轮schema 6迁移已实现；其余目标主表按15逐步接入，历史旧档为version=5 |
| `revision` | 权威状态修订号，用于命令前置及过期请求判断；不等于schemaVersion |
| `rulesetVersion, contentVersion` | 平衡规则、内容定义版本，与运行时版本分离 |
| `worldTick, ticksPerDay, rngState` | 唯一时钟、日长配置、已持久化随机状态 |
| `personsById, scenesById, buildingsById` | 人物、场景、建筑实例主表 |
| `itemsById, editionsById` | 实物实例与典籍版本/内容记录，定义另存 |
| `organizationsById, factionsById, locationsById, routesById` | 组织与地理身份 |
| `activitiesById, workOrdersById, reservationsById, travelsById` | 个人行为、共享工作单、独占槽位/物资预约、旅队实例 |
| `eventsById, factsById, story` | 事件、事实、篇章锚点与结果 |
| `ecologiesBySceneId, weatherByRegionId` | 地表/资源/灵气条件与区域天气过程，详见08；updatedThroughTick为游标非独立时钟 |
| `schemesById, claimsById, opportunitiesById` | 安排/谋局、陈述、重要机缘/事件根链；引用原人物/事件/事实，不复制装备归属 |
| `investigationsById, divinationsById` | 调查/卜算的活动、来源、观测、结果与成本引用 |
| `crisesById, combatSessionsById, hazardsById, deathRecordsByPersonId` | 持续危险、实际斗法、部署危险及逐人唯一死亡记录，详见10 |
| `stockpilesById, economy, policies` | 可定位资源、流水、公开制度 |
| `transactions, migration` | 幂等与迁移映射、必要结算结果 |

人物示例中的 `activity` 是读取投影；持久根保存 `activityId` 并引用活动主表，不再保存第二个可独立修改的活动副本。关系可以内嵌于人物，但仍以目标人物ID为键。装备清单为实例位置的派生索引，不能和实例location各自持有一套归属。

典籍版本描述章节、可靠性、来源和复制关系；实体书/玉简由`itemsById`记录位置与所有权，并以`editionId`引用内容。口传版本引用来源人物和授受事实，不伪造实体书的位置。多个合法复制品可引用相同内容，但各有实物实例和许可。

各文档示例为局部形状，不能直接当成完整可导入存档。实现前应由共同schema给出必填、空值、枚举、范围及引用校验。

NPC目标/阶段生活计划、信念`beliefs`内嵌人物。`person.combatSessionId`为空或唯一有效会话引用，`activityId`仍负责唯一身体活动；备战/结算不绕过唯一占用。

`person.lifeStatus`为`alive / dead`，死亡必须与唯一死亡记录原子提交。存活者`bodyState`由health/injuries/意识/救治事实派生为`fit / impaired / incapacitated / dying`，死者不提供活人bodyState。失踪、被俘和外出均不意味着死亡；未知死亡也不自动变成玩家已知。

危机`stage`为`forming / exposed / engaged / escalating / critical / resolved`；战斗会话`phase`为`preparing / active / settling / ended`；谋局`schemeStage`为`planned / preparing / active / compromised / settling / resolved`。这些是领域阶段，不能替代统一人物活动phase。气候`phase`是版本化天气类型，不能当成活动阶段。

法门已内化联系保存在`person.cultivation.practiceLinks`，以`internalizedSignatureId`为稳定主键，引用`artId / sourceEditionId / signatureDefinitionId / mechanismId / schemeId`及当前联系状态`latent / active / severed / purified`。它保存功体实际联系，不另复制理解、修为或整条谋局。正在突破的`breakthroughAttemptId`引用对应活动ID；未知联系不进入人物学习面板的可知投影。

`opportunitiesById`统一注册重要独立根链，`rootKind`为`opportunity / event-chain`；普通子事件用`rootChainId`引用根链，不另建统计副本。根链保存首次对掌门可参与/调查的激活记录`playerActivationTick`（未发生时为null），一链计一次；重新传闻、进入子战斗或重载不重复计入分母。纯NPC隐秘进程仍可运行，但未成为掌门可参与/调查的链不进入体验密度统计。

重要根链使用明确`manipulationTag`及`manipulationReasonIds`计入40%统计；理由枚举为`deliberate-manipulation / consequential-deception / covert-hostile-plan`。公开竞争、继承职责与可信合作不自动计入；有schemeId不意味着恶意。真相卡可写同字段作为编译输入，运行中不再保留另一套可独立统计标签。

## 3. 稳定身份

- 主角固定逻辑ID示例为 `person:master`；NPC示例 `person:npc:001`。
- 建筑使用 `buildingId`，物品使用 `instanceId`，人物和事件使用 `id`；各表中的主键与其身份字段必须一致。
- 定义ID与实例ID分开，如 `item:def:seal` 与 `item:instance:001`。不能凭名字或数组下标判断身份。
- `sceneId` 是运行中的局部场景身份；地点字段 `localSceneId` 引用这个ID，不是另一套场景身份。
- 槽位是建筑实例与预制件局部槽位的组合，如 `building:1042/slot:desk:1`。迁建改变位置，不改变槽位身份。
- 姓名、服饰、镜头、语言和地图缩放改变时，身份不变。
- 同一人物只有一个实体位置：本地scene、worldTravel或特殊容纳状态。大地图旅队点与战斗角色为投影。
- 离宗人物保留身份、关系和重要记忆，不重新生成同名陌生人。
- 旧数值ID通过持久映射转换，并重写所有引用；不得只转换主表后丢失师承、战斗和剧情关联。

## 4. 数值、空间与时间单位

| 数据 | 目标约定 |
| --- | --- |
| 地面 | 一世界单位=一逻辑米；U-99/R-28营造单位格为2米，0.5米仅为导航精度；投影由镜头负责 |
| 位置 | 局部场景平面 `x,y`，可选 `z` 表示高度；世界大地图坐标不得混入局部平面 |
| 朝向 | 世界方向或合法离散朝向；不能用屏幕朝向替代 |
| 状况 | 新建筑/物品 `condition` 为0–1比例；旧建筑0–100转换；UI显示百分比 |
| 境界 | `realmId + layer`；旧1–12数值由适配器明确转换 |
| 人物能力 | 可调0–100量表，如comprehension/技能；资质结构不等于境界 |
| 法门掌握 | `learning[artId].understanding/mastery`各0–100；修为`progress`为0–1；UI比例由投影换算 |
| 资源 | 有限、非负，推荐存最小计量整数；迁移不能因四舍五入静默抹去旧数量 |
| 时刻 | 非负整数 `worldTick`，字段名 `*Tick` |
| 持续量 | 非负整数 `durationTicks`；禁止混用秒、毫秒和现实分钟 |

本版tick单位固定100ms模拟时间；模拟更新可批量推进整数tick。`ticksPerDay=1200`沿用现有120秒/日作为兼容基点，日长不是不可调整的世界观设定。改变tick单位需新契约与迁移；UI的辰时、日期由配置推导。

1x/2x/4x改变单位墙钟内推进的模拟步数，不改变一个tick的意义。调速不允许额外结算生产、绕过冷却或重复抽事件。

暂停、后台、关闭、没有写锁的只读会话、剧情阅读以及明确要求暂停的管理操作不推进模拟。恢复后重新锚定墙钟，不补跑隐藏或关闭的时间。纯读取/投影函数自身既不推进，也不单独冻结某处世界；正常运行时仍由持写锁的模拟器推进。界面是否暂停明确由pause policy规定，全世界一致，不能一个地图页停远方而让山院继续。渲染插值只改善画面，不改变真实位置或结果。

战术暂停可选择目标、取消/调整掌门计划；动作成本和命中在恢复后合法执行阶段结算。剧情选择、交易和建造确认是明确命令，可在暂停时提交，但施工和行走不推进。

战斗中的服药、换装、治疗、施法和部署同样是有阶段/时间的动作；暂停时只排计划，恢复后执行并扣其消耗，冷却不刷新。不能把“允许暂停交易/确认营造”推广为暂停连续服药或瞬间完成教学。

### 世界步的确定顺序

一个tick是全世界共用边界。跨地点斗法、危机、移动、调查、抽取、天气与生产不能各读一次墙钟。推荐世界步顺序：

1. 收取按序号登记的掌门命令和NPC已定意图；校验旧版本/权限。命令只开始或修改计划，不能把新收到的急救当成已完成治疗。
2. 处理本tick到期的天气/路线/设施条件，重验活动前置、通路、占位与已发生的中断。已知可见信息按其来源在之后投影，不把环境真相全知推送。
3. 推进真实移动与活动，确定本tick实际到达、动作开始/完成、维持停止的边界。到达后新开始的治疗/破阵仍需正整数durationTicks，不能与到达一起零时长完成。
4. 汇集在本tick真正完成的效果：攻击、护持、急救、断链、抽取、环境暴露及工序贡献。来源必须为可追踪动作/持续机制；按规则优先层计算，不能由回调先后决定。早于攻击完成的护持/已在维持的护盾可影响攻击；同tick已完成的防护/稳定效果先形成合法状态，再计算接触伤害与持续损耗，之后合并恢复/损伤。稳定措施只有对匹配伤势有效时才改变致命演变，不能无条件抵消处决或任意伤害。
5. 更新身体、危机、共享工序/转移账本与完成结果；只在全部合法效果合并后检查仍满足的不可逆死亡条件，原子提交生命/遗物位置/释放/死亡记录。禁止边遍历人物边删注册。已在更早tick死亡者不接受晚到治疗。
6. 处理观察、消息实际发送/送达、人物信念和知情社会反应；登记下一阶段事件/意图。消息可以描述早先观察，不把收到时刻当作实时现场。
7. 增加权威revision，生成知情投影并保存。表现/网络回调不得补结算；失败按保存契约处理。

效果优先层和叠加组属于版本化动作规则。相同tick同层效果从阶段开始快照计算，聚合时按稳定效果ID排序只用于确定重放，不能以数组遍历顺序决定谁先活谁先死。互相致命的攻击可产生双方倒地等独立身体后果；群体不是共享生死判定。

批量/加速推进在天气、消息、到达、动作完成、危机及死亡等边界拆分，和逐tick参考演算比较。可救情景按动作实际完成tick与致命边界验收；刚下救治命令不能抢先，已合法完成的救治不能因为渲染或网络延迟被排到死亡之后。

## 5. 命令结构与返回

命令只表达请求。NPC相关请求不能直接把“邀请”写成“强制执行”。

```json
{
  "commandId": "command:session-a:17",
  "type": "construction.confirm",
  "actorId": "person:master",
  "expectedRevision": 42,
  "payload": {
    "sceneId": "scene:yunxiu-courtyard",
    "placementId": "placement:Z-01:herb-01",
    "layoutVersion": "sect-growth-v1",
    "prefabId": "prefab:farm:basic:v1",
    "projectKind": "build"
  }
}
```

U-105/R-32 的新建项目引用预设建造点与布局版本；命令侧从受信布局定义解析占地、朝向、入口及通路，不能把客户端任意坐标当作已批准位置。上例是目标语义，尚未实现该版本。既有坐标命令及旧档按兼容分支保留，实施时再登记实际字段与版本迁移。

返回至少包含 `status`、`commandId`、`revision`、`reasonCodes`、`transactionId`、`changedIds` 和保存状态。成功前置检查不代表任务已经完成。

| status | 含义 | UI应当表达 |
| --- | --- | --- |
| `rejected` | 无权限、过期、缺少条件或无效目标，未提交 | 明确原因及可采取措施 |
| `committed` | 事务已写入内存事实，含任务创建/邀请登记 | “工地已建立/邀请已发出”，不谎称建筑落成 |
| `already-applied` | 相同命令已处理 | 返回已有结果，不重复扣费或领奖 |

意愿接受/拒绝是人物后续的可见结果，不与命令校验拒绝混为一谈。道路阻塞、资源不足和工位等待分别使用原因码。

保存失败与游戏事务失败分开。内存事务已成功而磁盘写入失败时，显示“本次变化尚未保存”、暂停，允许导出或明确内存试玩；不得显示资源没有变化并再次提交同一操作。

## 6. 事务和幂等

每个结算必须可追踪其来源：命令、活动、事件、生产批次或迁移。

1. 校验身份、权限、版本、条件和当前引用。
2. 计算全部变更与资源预约。
3. 整体校验新状态，任何一项不成立则不提交。
4. 一次提交资源、身份、任务、事实与唯一结果键。
5. 更新只读投影并尝试保存，分别报告两种结果。

重要奖励键如 `reward:<eventId>:<choiceId>` 长期保留。交易/任务完成不能因界面重新挂载或动画结束回调再次发生。普通命令收据可按会话序号与检查点压缩，但已经应用的命令仍须可拒绝重放，不能靠短日志存在与否判断。

双击、触屏重送、旧页面重新发送、读档恢复任务、完成回调重复触发，都不能重复扣费、生成装备或发奖。

## 7. 活动与独占槽位

权威活动阶段与 [人物规格](01-CHARACTERS.md) 一致：

`proposed → reserving → navigating → preparing → executing → settling → completed`。

适用阶段可进入`waiting`并记录待恢复阶段和原因；等待不是终态。释放是清理动作，不另设released阶段。

任意非完成阶段可进入 `interrupted/cancelled/failed`，需要释放或转移预约；具体恢复原因和保留进度记录在活动中。

最低字段：

```json
{
  "id": "activity:npc001:0008", "personId": "person:npc:001",
  "kind": "tend-herbs", "phase": "navigating",
  "sceneId": "scene:yunxiu-courtyard", "targetId": "building:herb-plot:001",
  "slotId": "building:herb-plot:001/slot:work:2",
  "reservationId": "reservation:0008", "durationTicks": 200,
  "progressTicks": 0, "committedUntilTick": 2400,
  "reasonCodes": ["supply-shortage", "matches-aspiration"],
  "resultTransactionId": null
}
```

一个人物只能有一个占用身体执行的主活动；监听号召、规划下一步等不能假装同时执行两个工位。等候目标可以没有slotId，得到预约后补全；没有有效slotId和到场事实不能开始需要工位的任务。

预约含持有人、对象、创建/到期、所属活动和状态。取消、离场、受伤、迁建、拆除、停用和读档均检查预约。租约到期可释放未开始的预约，实际执行不能被其他人无提示抢占。

生产由活动到场、材料、能力、工位和设施共同驱动；不能用动画或worker计数替代真实执行。

### 多人共享工作单

施工、共同炼制等共享工程使用`workOrdersById[workOrderId]`，保存目标、配方/几何版本、阶段、投入预留、共享进度、参与活动ID及结果事务。建筑引用`constructionWorkOrderId`，人物活动引用`workOrderId`。个人活动只记录其到场、贡献与占位，共享阶段进度和材料结算只由工作单写入。

工作单阶段为`planned / active / waiting / settling / completed / cancelled / failed`；人物离场仅结束自己的贡献，不复制或取消他人的结果。活动完成可以结算本人经验，工程完成只生成一次建筑/批次；两类结算键分开。单人独立活动无需工作单，多人活动不能每名参与者各发一份共享产物。

### 山域建设与功能迁移（U-105 / R-32）

[成长章程](../SECT-GROWTH-PLAN.md)新增的地域解锁、项目与迁移依然引用上述主表。地域 Z-01–07 使用稳定ID；资格、已开工、通路可达、容量可用、迁居完成和供给稳定分别由真实事实派生。人数只是需求输入，下降不撤销已解锁地域。

- 版本化布局定义预设建造点、所属地域、允许项目、占地、入口和连接；权威实例保留实际变换、布局版本与来源点引用。布局解析和引用校验一次产生几何结果，画面与寻路共同读取，不另存一份可独立变更的摆放事实。
- 行为按服务类型寻找有效设施／槽位，再交给布局与导航获得路线；主峰、东侧或具体坐标不直接写入休养、生产和研习规则。
- 升级及整座迁建保留原建筑ID；新建接替设施使用新ID，持久记录源／目标、接替用途、前置与对应工作单。每个实体仍只有一个有效位置。
- 迁居引用原人物、目的床位、行程、携带物与接受事实。安全目的地与路线成立后才开始迁移；正在治疗、生产或搬运的身体活动按既有规则安全完成／中断或等待，不能随阶段标记跳转位置。
- 工程不以阶段人数整体结算。材料预留、实际施工、容量启用、人员到达、实物交付、旧批次结束和旧址改造都有独立的一次结算凭据；新产能与配送经登记窗口核对后才退出旧产能。
- 保存布局版本、地域解锁与工程阶段、接替关系、活动／工作单、预约、库存位置和完成凭据。断路、满仓、伤停、取消和读档按同一持久状态恢复，暂停／后台／关闭不推进。

具体状态字段与命令名在实施批次对照现有 schema 冻结；本设计不直接新增存档版本，也不授权用阶段原型覆盖当前世界。正常、失败和存读验收使用 GROWTH-02–11。

## 8. 资源、施工与物品归属

- 总量、可用量、预约量和运输中数量分开，物资只有一个实际位置。
- 建造预览只读；确认建立工地并预约材料；搬运转移位置，施工阶段才消耗对应投入。
- 取消释放未投入的材料，已投入部分按明确回收规则处理；重复取消不再次退款。
- 物品实例只在一个位置：装备、保管、地面、运输或工序中。定义模板不是可交易实体。
- 公器借用需要意愿与权限，不能因保管人改变便自动成为私有物。
- 生产批次、打造完成、维修、套装激活和法门学习均有来源与去重键。
- 日维护、供给和组织预算使用日结算游标；改ticksPerDay或读档不重复消耗一天。

母子篇激活键为`schemeId + targetPersonId + internalizedSignatureId + breakthroughAttemptId`，同次突破只创建/恢复一个持续抽取危机。阶段往返、易主、重复回调、读档不刷新上限；每段以`activationKey + transferSequence`结算并累计损失/吸收/逸散/反噬。真正新突破是新活动，但必须重验联系仍有效；净化/断链的既定事实不能被重载抹去。

## 9. 内容与资产契约

每个可运行内容定义必须包含稳定ID、版本、前置、可执行动作、成本/产出或效果、空间要求、显示说明、失败原因和验收场景。

预制件同时提供占地、入口、通行、槽位、遮挡、命中和绘制锚点。人物外观配方同时服务肖像、生活与战斗。资源文件缺失不等于实体不存在：保留事实，提供一致的临时表现与重试，不静默删除。

素材接入前验证透明边缘、视角、门高、人物脚点、阴影方向、遮挡与点击范围。不能把完整概念画面的截图直接作为可经营空间权威。

## 10. 随机与知情

- 随机只由世界rngState或已登记的局部事件种子推进。
- 普通人物第一次生成、事件参与人和已决定结果保存；刷新不重掷。
- 事件保留种子并不意味着玩家不能选择；选择与随机结果是不同记录。
- 同一邀请的意愿基于已知状态与承诺，不因重复点击临时多抽一次。
- 世界真相、人物观察、玩家获知和公开传播分别记录；全知调试字段不能直接进入产品UI。
- 通行、筑基和关键证据需要可靠获取路径，不能只靠随机有利结果。

`claim`记录“谁在何时向谁声称什么”，包括观察时刻、发送/接收时刻、转述来源与可知证据；`fact`记录实际发生，包括“某人看见假象”的观察事实，不能因此写成假象内容在世界里为真。人物beliefs保存其相信/怀疑及来源，不成为另一份世界真值。

共同禁忌行为使用版本化世界定义，地区规制可增加取证/执法差异但不取消共同底线。公开邪修指控引用证据/陈述；实际是否犯禁引用真实行为，不能从道途标签、舆论或单声望生成。

秘密参与者和机制在激活时固定，后续真实行动可以更换持有者/执行者，但不得改写先前因果。未知危险只通过真实观察/消息/卜算产生知情；地图、特效、自动暂停、NPC原因、API包和数据导出产品投影不得提前揭示。

正常存档包含权威秘密以恢复模拟；产品UI/公开共享诊断只给权限内投影。纯客户端存档不承诺能阻止玩家自行读取源码/JSON；正常玩法不依赖反调试或加密遮挡，隐秘公平验收针对产品入口与API披露。

## 11. 旧存档迁移

历史实际档包括 `version=5` 及v1–v4路径；当前运行使用schema 6。首轮迁移记录见[15](15-OPENING-IMPLEMENTATION.md)，后续空间、内容与完成档保护的实际证据见[STATUS](STATUS.md)最新段。旧篇章的`legacy-ea-1.4.2`兼容分支与固定责任人映射须按加载器和对应案例核对；已完成结局不能被新内容重新打开。完整目标矩阵仍见[14](14-EARLY-GAME-DETAILED-DESIGN.md)，结构迁移与各内容分支验收分别登记。

| 原数据 | 迁移原则 |
| --- | --- |
| 人物、离宗人物、主角 | 稳定映射，保留名称、性格、记忆、师承、志向与原随机结果 |
| 数值境界1–12 | 明确转换炼气层与筑基阶段，不随新显示名重新计算人物 |
| knowledge单值 | 保留legacyMastery和映射来源；拆理解/熟练采用公开兼容映射，不随机重学 |
| 建筑x/y固定槽位 | 使用版本化映射放入新地形；不可安置的进入可恢复待安置状态，保留等级/价值/进度 |
| 自由布局及96米山院进入成长山域 | 保留原始空间、建筑／槽位／活动引用和投入；隔离生成预设点兼容映射，无法完整接纳时保留原服务并进入明确兼容状态或拒载保原档；不按人口批量重摆 |
| 主屋绘景 | 生成对应实体并保留身份与状态，不额外发建筑奖励 |
| 活动与重叠位置 | 重建槽位预约与合法路径；必要时暂停并说明恢复，不在同一入口继续假生产 |
| 旧time与日结算 | 保留已过游戏日、日内相位、任务剩余比例和维护游标 |
| 单一声望 | 作为legacyRenown来源，不凭空推断个人恩仇或恶名 |
| 旧装备缺失 | 不发虚构套装；仅迁移旧事实存在的物品或明确一次兼容补偿 |
| 章节、证据、既定事件、已领奖 | 原样保留语义与唯一结果，不重新抽取或领奖 |
| 天气/生态/隐秘目标 | 确定性初始化并保留当前已知天气/日相位；不补算过去灾害、资源透支或暗中交易 |
| 新NPC生死规则 | 从明确migrationTick生效；不追算旧死亡、不把旧安全活动转成致死抽签；旧在途缺条件时兼容收束/待恢复 |
| 新典籍同源联系 | 仅按已有来源/内容事实映射；不能把旧家传或已学普通法突然改为恶意母子篇 |

迁移先备份原文，在隔离副本转换，进行结构、引用和规则校验，再交付可恢复新档。失败保留原档与错误说明。未来更高版本档案不得静默降级或删除未知字段。

## 12. 模块接缝与现有代码复用

| 领域 | 可复用基础 | 需要替换或新增 |
| --- | --- | --- |
| 人物 | ea-life、ea-society的意愿/关系/记忆 | 主表身份、活动阶段、多槽位与知情投影 |
| 修行 | ea-data/ea-sim功法前置与授业 | 理解/熟练拆分、实际动作、实例装备与组合 |
| 空间 | ea-scene-state只读接口、实际设施投影、既有坐标兼容 | U-105版本化预设建造点与地域连接、独立实体预制件、布局到导航的共同解析 |

| 持久化 | 多档、备份、锁、失败反馈和隔离QA | 新结构迁移、引用完整性、活动/归属恢复 |

接口先以适配器接入，避免同时重写所有规则而无法比较行为。阶段适配只允许一个权威写入侧；不得让新旧模拟都结算同一生产。
