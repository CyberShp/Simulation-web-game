# 运行时、数据与存档契约

设计编号：DB-2026-10-05；版本：1.0。本文为目标接口，不宣称现有EA已经采用这些字段。它负责跨模块的唯一事实与序列化边界；领域规则分别见 [人物](01-CHARACTERS.md)、[装备武学](02-EQUIPMENT-ARTS.md)、[空间](03-SPATIAL-ART.md)、[世界](04-WORLD-STORY.md)、[经济](07-ECONOMY-ORGANIZATION.md)。

## 1. 事实、定义和画面分开

| 层 | 内容 | 可否改变游戏事实 |
| --- | --- | --- |
| 内容定义 | 建筑预制件、物品、法门、动作、事件模板、规则配置 | 只作为版本化规则输入 |
| 世界状态 | 实体、位置、活动、物品归属、库存、关系、已定结果 | 由命令或模拟步修改 |
| 命令与事务 | 经过权限/前置校验的玩家请求和AI请求 | 可以原子提交、扣费、登记结果 |
| 模拟 | 移动、活动进度、生产、事件、成长、恢复 | 由唯一模拟时钟驱动 |
| 玩家知情投影 | 姓名、动作、原因、可用操作、已公开证据 | 只读；隐藏事实经过权限过滤 |
| 渲染与输入 | 镜头、贴图、动画、命中候选、拖动预览 | 不产出、不重抽人物、不直接改资源 |

同一事实只有一个写入者。管理页、宗门总览、近景、世界地图与战斗读取同一实体，不复制拥有不同生命值/外观/关系的人物。

## 2. 目标状态根与引用

根状态建议包含：

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 存档结构版本；本轮尚未决定新版本号，当前实际存档为v5 |
| `revision` | 权威状态修订号，用于命令前置及过期请求判断；不等于schemaVersion |
| `rulesetVersion, contentVersion` | 平衡规则、内容定义版本，与运行时版本分离 |
| `worldTick, ticksPerDay, rngState` | 唯一时钟、日长配置、已持久化随机状态 |
| `personsById, scenesById, buildingsById` | 人物、场景、建筑实例主表 |
| `itemsById, editionsById` | 实物实例与典籍版本/内容记录，定义另存 |
| `organizationsById, factionsById, locationsById, routesById` | 组织与地理身份 |
| `activitiesById, workOrdersById, reservationsById, travelsById` | 个人行为、共享工作单、独占槽位/物资预约、旅队实例 |
| `eventsById, factsById, story` | 事件、事实、篇章锚点与结果 |
| `stockpilesById, economy, policies` | 可定位资源、流水、公开制度 |
| `transactions, migration` | 幂等与迁移映射、必要结算结果 |

人物示例中的 `activity` 是读取投影；持久根保存 `activityId` 并引用活动主表，不再保存第二个可独立修改的活动副本。关系可以内嵌于人物，但仍以目标人物ID为键。装备清单为实例位置的派生索引，不能和实例location各自持有一套归属。

典籍版本描述章节、可靠性、来源和复制关系；实体书/玉简由`itemsById`记录位置与所有权，并以`editionId`引用内容。口传版本引用来源人物和授受事实，不伪造实体书的位置。多个合法复制品可引用相同内容，但各有实物实例和许可。

各文档示例为局部形状，不能直接当成完整可导入存档。实现前应由共同schema给出必填、空值、枚举、范围及引用校验。

## 3. 稳定身份

- 主角固定逻辑ID示例为 `person:master`；NPC示例 `person:npc:001`。
- 建筑使用 `buildingId`，物品使用 `instanceId`，人物和事件使用 `id`；各表中的主键与其身份字段必须一致。
- 定义ID与实例ID分开，如 `item:def:seal` 与 `item:instance:001`。不能凭名字或数组下标判断身份。
- `sceneId` 是运行中的局部场景身份；地点字段 `localSceneId` 引用这个ID，不是另一套场景身份。
- 槽位是建筑实例与预制件局部槽位的组合，如 `building:1042/slot:desk:1`。迁建改变位置，不改变槽位身份。
- 姓名、服饰、镜头、语言和地图缩放改变时，身份不变。
- 同一人物只有一个实体位置：本地scene、worldTravel或特殊容纳状态。大地图旅队点与战斗角色为投影。
- 离宗人物保留身份、关系和重要记忆，不重新生成同名陌生人。
- 旧数值ID通过持久映射转换，并重写所有引用；不得只转换主表后丢失师承、战斗和剧情关联。

## 4. 数值、空间与时间单位

| 数据 | 目标约定 |
| --- | --- |
| 地面 | 一世界单位=一逻辑米；可营造网格0.5单位；投影由镜头负责 |
| 位置 | 局部场景平面 `x,y`，可选 `z` 表示高度；世界大地图坐标不得混入局部平面 |
| 朝向 | 世界方向或合法离散朝向；不能用屏幕朝向替代 |
| 状况 | 新建筑/物品 `condition` 为0–1比例；旧建筑0–100转换；UI显示百分比 |
| 境界 | `realmId + layer`；旧1–12数值由适配器明确转换 |
| 人物能力 | 可调0–100量表，如comprehension/技能；资质结构不等于境界 |
| 法门掌握 | `learning[artId].understanding/mastery`各0–100；修为`progress`为0–1；UI比例由投影换算 |
| 资源 | 有限、非负，推荐存最小计量整数；迁移不能因四舍五入静默抹去旧数量 |
| 时刻 | 非负整数 `worldTick`，字段名 `*Tick` |
| 持续量 | 非负整数 `durationTicks`；禁止混用秒、毫秒和现实分钟 |

本版tick单位固定100ms模拟时间；模拟更新可批量推进整数tick。`ticksPerDay=1200`沿用现有120秒/日作为兼容基点，日长不是不可调整的世界观设定。改变tick单位需新契约与迁移；UI的辰时、日期由配置推导。

1x/2x/4x改变单位墙钟内推进的模拟步数，不改变一个tick的意义。调速不允许额外结算生产、绕过冷却或重复抽事件。

暂停、后台、关闭、只读、剧情阅读以及当前规格要求暂停的管理操作不推进模拟。恢复后重新锚定墙钟，不补跑隐藏或关闭的时间。渲染插值只改善画面，不改变真实位置或结果。

战术暂停可选择目标、取消/调整掌门计划；动作成本和命中在恢复后合法执行阶段结算。剧情选择、交易和建造确认是明确命令，可在暂停时提交，但施工和行走不推进。

战斗中的服药、换装、治疗、施法和部署同样是有阶段/时间的动作；暂停时只排计划，恢复后执行并扣其消耗，冷却不刷新。不能把“允许暂停交易/确认营造”推广为暂停连续服药或瞬间完成教学。

## 5. 命令结构与返回

命令只表达请求。NPC相关请求不能直接把“邀请”写成“强制执行”。

```json
{
  "commandId": "command:session-a:17",
  "type": "construction.confirm",
  "actorId": "person:master",
  "expectedRevision": 42,
  "payload": {
    "sceneId": "scene:yunxiu-courtyard",
    "prefabId": "prefab:farm:basic:v1",
    "transform": {"x": 18, "y": 12, "orientation": "south"}
  }
}
```

返回至少包含 `status`、`commandId`、`revision`、`reasonCodes`、`transactionId`、`changedIds` 和保存状态。成功前置检查不代表任务已经完成。

| status | 含义 | UI应当表达 |
| --- | --- | --- |
| `rejected` | 无权限、过期、缺少条件或无效目标，未提交 | 明确原因及可采取措施 |
| `committed` | 事务已写入内存事实，含任务创建/邀请登记 | “工地已建立/邀请已发出”，不谎称建筑落成 |
| `already-applied` | 相同命令已处理 | 返回已有结果，不重复扣费或领奖 |

意愿接受/拒绝是人物后续的可见结果，不与命令校验拒绝混为一谈。道路阻塞、资源不足和工位等待分别使用原因码。

保存失败与游戏事务失败分开。内存事务已成功而磁盘写入失败时，显示“本次变化尚未保存”、暂停，允许导出或明确内存试玩；不得显示资源没有变化并再次提交同一操作。

## 6. 事务和幂等

每个结算必须可追踪其来源：命令、活动、事件、生产批次或迁移。

1. 校验身份、权限、版本、条件和当前引用。
2. 计算全部变更与资源预约。
3. 整体校验新状态，任何一项不成立则不提交。
4. 一次提交资源、身份、任务、事实与唯一结果键。
5. 更新只读投影并尝试保存，分别报告两种结果。

重要奖励键如 `reward:<eventId>:<choiceId>` 长期保留。交易/任务完成不能因界面重新挂载或动画结束回调再次发生。普通命令收据可按会话序号与检查点压缩，但已经应用的命令仍须可拒绝重放，不能靠短日志存在与否判断。

双击、触屏重送、旧页面重新发送、读档恢复任务、完成回调重复触发，都不能重复扣费、生成装备或发奖。

## 7. 活动与独占槽位

权威活动阶段与 [人物规格](01-CHARACTERS.md) 一致：

`proposed → reserving → navigating → preparing → executing → settling → completed`。

适用阶段可进入`waiting`并记录待恢复阶段和原因；等待不是终态。释放是清理动作，不另设released阶段。

任意非完成阶段可进入 `interrupted/cancelled/failed`，需要释放或转移预约；具体恢复原因和保留进度记录在活动中。

最低字段：

```json
{
  "id": "activity:npc001:0008", "personId": "person:npc:001",
  "kind": "tend-herbs", "phase": "navigating",
  "sceneId": "scene:yunxiu-courtyard", "targetId": "building:herb-plot:001",
  "slotId": "building:herb-plot:001/slot:work:2",
  "reservationId": "reservation:0008", "durationTicks": 200,
  "progressTicks": 0, "committedUntilTick": 2400,
  "reasonCodes": ["supply-shortage", "matches-aspiration"],
  "resultTransactionId": null
}
```

一个人物只能有一个占用身体执行的主活动；监听号召、规划下一步等不能假装同时执行两个工位。等候目标可以没有slotId，得到预约后补全；没有有效slotId和到场事实不能开始需要工位的任务。

预约含持有人、对象、创建/到期、所属活动和状态。取消、离场、受伤、迁建、拆除、停用和读档均检查预约。租约到期可释放未开始的预约，实际执行不能被其他人无提示抢占。

生产由活动到场、材料、能力、工位和设施共同驱动；不能用动画或worker计数替代真实执行。

### 多人共享工作单

施工、共同炼制等共享工程使用`workOrdersById[workOrderId]`，保存目标、配方/几何版本、阶段、投入预留、共享进度、参与活动ID及结果事务。建筑引用`constructionWorkOrderId`，人物活动引用`workOrderId`。个人活动只记录其到场、贡献与占位，共享阶段进度和材料结算只由工作单写入。

工作单阶段为`planned / active / waiting / settling / completed / cancelled / failed`；人物离场仅结束自己的贡献，不复制或取消他人的结果。活动完成可以结算本人经验，工程完成只生成一次建筑/批次；两类结算键分开。单人独立活动无需工作单，多人活动不能每名参与者各发一份共享产物。

## 8. 资源、施工与物品归属

- 总量、可用量、预约量和运输中数量分开，物资只有一个实际位置。
- 建造预览只读；确认建立工地并预约材料；搬运转移位置，施工阶段才消耗对应投入。
- 取消释放未投入的材料，已投入部分按明确回收规则处理；重复取消不再次退款。
- 物品实例只在一个位置：装备、保管、地面、运输或工序中。定义模板不是可交易实体。
- 公器借用需要意愿与权限，不能因保管人改变便自动成为私有物。
- 生产批次、打造完成、维修、套装激活和法门学习均有来源与去重键。
- 日维护、供给和组织预算使用日结算游标；改ticksPerDay或读档不重复消耗一天。

## 9. 内容与资产契约

每个可运行内容定义必须包含稳定ID、版本、前置、可执行动作、成本/产出或效果、空间要求、显示说明、失败原因和验收场景。

预制件同时提供占地、入口、通行、槽位、遮挡、命中和绘制锚点。人物外观配方同时服务肖像、生活与战斗。资源文件缺失不等于实体不存在：保留事实，提供一致的临时表现与重试，不静默删除。

素材接入前验证透明边缘、视角、门高、人物脚点、阴影方向、遮挡与点击范围。不能把完整概念画面的截图直接作为可经营空间权威。

## 10. 随机与知情

- 随机只由世界rngState或已登记的局部事件种子推进。
- 普通人物第一次生成、事件参与人和已决定结果保存；刷新不重掷。
- 事件保留种子并不意味着玩家不能选择；选择与随机结果是不同记录。
- 同一邀请的意愿基于已知状态与承诺，不因重复点击临时多抽一次。
- 世界真相、人物观察、玩家获知和公开传播分别记录；全知调试字段不能直接进入产品UI。
- 通行、筑基和关键证据需要可靠获取路径，不能只靠随机有利结果。

## 11. 旧存档迁移

当前实际 `version=5`，保留已有v1–v4路径。目标结构采用新的schema版本时，必须增加明确迁移，不就地覆盖v5后谎称仍兼容。

| 原数据 | 迁移原则 |
| --- | --- |
| 人物、离宗人物、主角 | 稳定映射，保留名称、性格、记忆、师承、志向与原随机结果 |
| 数值境界1–12 | 明确转换炼气层与筑基阶段，不随新显示名重新计算人物 |
| knowledge单值 | 保留legacyMastery和映射来源；拆理解/熟练采用公开兼容映射，不随机重学 |
| 建筑x/y固定槽位 | 使用版本化映射放入新地形；不可安置的进入可恢复待安置状态，保留等级/价值/进度 |
| 主屋绘景 | 生成对应实体并保留身份与状态，不额外发建筑奖励 |
| 活动与重叠位置 | 重建槽位预约与合法路径；必要时暂停并说明恢复，不在同一入口继续假生产 |
| 旧time与日结算 | 保留已过游戏日、日内相位、任务剩余比例和维护游标 |
| 单一声望 | 作为legacyRenown来源，不凭空推断个人恩仇或恶名 |
| 旧装备缺失 | 不发虚构套装；仅迁移旧事实存在的物品或明确一次兼容补偿 |
| 章节、证据、既定事件、已领奖 | 原样保留语义与唯一结果，不重新抽取或领奖 |

迁移先备份原文，在隔离副本转换，进行结构、引用和规则校验，再交付可恢复新档。失败保留原档与错误说明。未来更高版本档案不得静默降级或删除未知字段。

## 12. 模块接缝与现有代码复用

| 领域 | 可复用基础 | 需要替换或新增 |
| --- | --- | --- |
| 人物 | ea-life、ea-society的意愿/关系/记忆 | 主表身份、活动阶段、多槽位与知情投影 |
| 修行 | ea-data/ea-sim功法前置与授业 | 理解/熟练拆分、实际动作、实例装备与组合 |
| 空间 | ea-scene-state只读接口、实际设施投影 | 固定地块映射、预设道路、大背景主屋、统一预制件 |
| 世界 | ea-campaign/ea-narrative的篇章与可靠线索 | 持久外NPC、社会评价、地点状态、事件实例 |
| 持久化 | 多档、备份、锁、失败反馈和隔离QA | 新结构迁移、引用完整性、活动/归属恢复 |
| UI | 当前纸卷青玉风格与基本导航 | 人物栏、行动原因、工位/物流/装备/预览投影 |

接口先以适配器接入，避免同时重写所有规则而无法比较行为。阶段适配只允许一个权威写入侧；不得让新旧模拟都结算同一生产。

## 13. 契约验收

| ID | 验收 |
| --- | --- |
| DATA-01 | 所有实体与引用有效，换名字、换镜头、进出战斗身份不变 |
| CLOCK-01 | 1x/2x/4x在相同模拟tick产生同样事实；暂停/后台/关闭不推进 |
| TX-01 | 重复命令、回调和读档不重复扣费、退款、产物或奖励 |
| SLOT-02 | 预约获得/释放/中断/读档恢复一致，超容量不能执行 |
| VIEW-01 | 打开UI和重绘不改变资源、随机、位置、学习或私密事实 |
| SAVE-02 | 已提交但未保存的变化有准确提示，导出与恢复能保留其状态 |
| MIG-01 | v1–v5迁移保留人物、建筑、知识、事件结果与日相位，有失败恢复 |
| MIG-03 | 未知版本、丢失定义、无法安置设施不会静默抹档或冒充成功 |
| RUNTIME-01 | 每个目标系统仅有一个写入者；新旧适配器不双重运行 |
