# 模拟仙府

国风青绿山水风格的实时 2.5D 仙府经营游戏原型。直接提供静态 dist/。

核心循环：建造、分配弟子、资源生产、建筑升级、弟子修炼与突破。

控制：选择建筑后点击地块建造；拖动平移地图，滚轮缩放；空格暂停；Esc 取消。

首版使用本次会话内状态，并提供显式导出/导入存档文件，不依赖浏览器自动保存。图片为项目原创生成素材。

## v0.1 范围
- 独立 2.5D 地图，拖动、缩放、建筑点选与地块占用校验。
- 6 类建筑，建筑最高 3 级；生产建筑每 20 秒产出，实际产量受建筑等级、弟子资质和境界影响。
- 灵石、灵木、青石、灵草四类资源；主殿被动产灵石，避免货币卡死。
- 弟子招募、分工、修炼与炼气 1–9 层突破。
- 暂停与 1×/2×/4× 时间倍率；弹窗期间自动暂歇。
- 三项引导目标、奖励领取、府中见闻。
- JSON 文件导出/导入，带结构与数值验证；暂不支持自动云存档与离线结算。
- WebMCP 在支持的浏览器中暴露状态读取、建造、弟子分配、时间控制。

## 本地预览与校验

无需构建或安装依赖。用支持 `.mjs` JavaScript MIME 的静态服务器提供 `dist/`；例如 `python3 -m http.server 8080 --directory dist`，随后打开 `http://localhost:8080`。不要直接双击 HTML（浏览器模块有同源限制）。

运行 `node --test tests/*.test.mjs` 检查鼠标捕获释放回归，运行 `node --check dist/game.mjs` 检查语法。

## 自有服务器部署

1. 先识别现有站点的服务与数据范围，备份站点目录、数据库和 Web 服务配置。
2. 将完整 `dist/` 放入 `/var/www/simulation-web-game/releases/<版本号>/`。
3. 将 `/var/www/simulation-web-game/current` 指向该版本目录。
4. 根据当前 Web 服务选择 `deploy/Caddyfile.example` 或 `deploy/nginx.conf`，整合到现有配置；不要覆盖无关站点。校验配置后重载服务。
5. 验证首页、`.mjs` MIME、素材可访问，再下线确认属于旧个人平台的应用服务。

本仓库不包含服务器登录凭据、生产配置或用户存档。游戏当前不依赖后端服务。
